Claude Code 개발 환경 #1 — Windows에서 hook을 만들며 겪은 함정

hook은 Claude Code가 정해진 시점에 실행하는 스크립트다. 입력은 JSON으로 표준 입력(stdin)에 들어오고, 출력은 JSON으로 돌려준다. 원리는 간단하지만 Windows와 데스크톱 앱 조합에서는 문서만 보고 짐작한 대로 움직이지 않는 곳이 많았다.

한 일

처음 만든 hook은 두 개다.

hook시점하는 일
인수인계 복원세션 시작같은 작업 폴더의 최근 인수인계 노트를 세션에 붙인다
압축 전 백업자동·수동 압축 직전그때까지의 요청과 답변을 위키에 남긴다

둘 다 PowerShell 5.1로 썼다. 시험은 두 단계로 했다. 먼저 JSON 입력 파일을 만들어 스크립트에 직접 넣어 보는 파이프 시험, 그다음 실제로 새 세션을 열어 보는 실사용 시험이다.

막힌 점과 해결

/clear는 clear로 오지 않는다

세션 시작 hook은 시작 이유(matcher)를 골라 걸 수 있다. 인수인계 복원이 필요한 때는 “/clear로 비운 직후”이므로 clear가 맞아 보인다. 데스크톱 앱에서 각 동작이 어떤 이벤트로 오는지 직접 기록해 봤다.

동작실제로 온 이벤트
새 세션SessionStart · startup
/compactPreCompact · manual → 같은 세션의 SessionStart · compact
/clear새 세션 ID의 SessionStart · startup

/clear가 새 세션 시작과 똑같이 왔고, hook 입력에는 둘을 가를 정보가 없었다. clear에만 걸었다면 데스크톱 앱에서는 복원이 한 번도 실행되지 않는다. 그래서 startup과 clear 모두에 걸고, 대신 붙일 노트의 조건을 좁혔다.

  • 노트에 적힌 작업 폴더가 지금 세션의 작업 폴더와 같다 (대소문자, 끝 슬래시 무시)
  • 노트 상태가 “진행 중”이다
  • 48시간 이내에 쓴 노트다
  • 그중 가장 최근 1건만

같은 폴더에서 48시간 안에 여는 새 세션에는 모두 노트가 붙는다. 인수인계가 목적이므로 이 정도는 허용했다.

데스크톱 앱은 상태 표시줄 스크립트를 실행하지 않는다

대시보드에 대화 창 크기(200K인지 1M인지)를 보여 주려고, CLI의 상태 표시줄(statusLine) 스크립트가 크기를 파일로 남기게 했다. 데스크톱 앱에서는 그 파일이 끝내 생기지 않았다. hook은 실행하지만 상태 표시줄 스크립트는 실행하지 않았다. 지금은 기본 200K로 가정하고, 사용량이 200K를 넘으면 1M으로 바꿔 표시한다.

한글이 든 PowerShell 스크립트

PowerShell 5.1은 BOM 없는 UTF-8 파일을 시스템 코드 페이지(CP949)로 읽는다. 스크립트 안의 한글 문자열이 깨졌다. 출력도 UTF-8로 지정해야 Claude Code가 JSON을 제대로 읽는다.

3

# 스크립트 파일은 UTF-8 BOM으로 저장한다
[Console]::OutputEncoding = New-Object Text.UTF8Encoding($false)
[Console]::InputEncoding  = [Text.Encoding]::UTF8   # 이 줄은 나중에 추가했다
$payload = [Console]::In.ReadToEnd() | ConvertFrom-Json

입력 줄은 한참 뒤에 추가했다. 입력 인코딩을 지정하지 않으면 stdin도 CP949로 읽는다. 짧은 시험 입력에서는 문제가 없었는데, 파일 수정 뒤 hook에는 고치기 전 파일 내용 전체가 입력으로 들어온다. 한글이 많은 파일을 고치면 따옴표가 깨진 글자에 먹혀 ConvertFrom-Json이 실패했고, hook은 오류를 삼키고 조용히 끝났다.

설정 저장소 동기화 hook이 이 때문에 일부 스킬 파일의 수정을 커밋하지 않았다. 내용에 따라 될 때도 있어서 늦게 발견했다. 손으로 만든 짧은 입력으로는 재현되지 않는다. 실제 편집 때 들어온 입력을 임시 로그로 그대로 남겨 봐야 원인이 보인다.

시험 입력의 역슬래시가 줄어든다

Claude의 Bash 도구에서 heredoc으로 JSON 시험 입력을 만들면 \\가 \로 줄었다. Windows 경로가 든 JSON이 깨져 ConvertFrom-Json이 “인식할 수 없는 이스케이프 시퀀스”로 실패했다. 스크립트가 아니라 시험 입력이 잘못된 것이다. 시험 입력은 파일 쓰기 도구로 파일을 만든 뒤 stdin으로 넣는다. 한글 치환 문자열이 든 Python 스크립트를 heredoc으로 넘길 때도 같은 계열의 문제로 매칭이 깨져, 이것도 파일로 만들어 실행한다.

경로가 길면 git과 Python이 멈춘다

시험용 임시 볼트를 세션 전용 작업 폴더 안에 만들었더니, git은 Filename too long, Python은 WinError 206으로 멈췄다. 그 폴더는 경로 자체가 길다. 시험용 저장소는 %TEMP% 아래 짧은 이름의 폴더에 만든다.

hook 오류가 세션을 막지 않게

hook 스크립트가 예외로 멈추면 세션 작업이 막힐 수 있다. 모든 스크립트를 try { … } catch { … exit 0 }로 감싸 실패해도 통과시키고, 원인을 볼 수 있게 오류 내용은 stderr에 남긴다.

증상원인해결
/clear 뒤 복원이 안 됨데스크톱 앱의 /clear는 startup으로 옴startup과 clear 모두, 조건을 좁혀 1건만
창 크기 파일이 안 생김데스크톱 앱은 상태 표시줄 스크립트를 실행하지 않음기본값 가정, 사용량으로 자동 전환
한글 깨짐, hook이 조용히 끝남PowerShell 5.1의 기본 인코딩 CP949파일 BOM, 출력·입력 인코딩 지정
시험 JSON이 깨짐heredoc에서 \\ → \시험 입력은 파일로
Filename too long너무 긴 작업 폴더 경로짧은 임시 경로
hook 오류로 작업이 막힐 위험예외실패해도 통과, stderr에 기록

배운 점: 짧은 시험 입력으로는 드러나지 않는 문제가 있었다. 시험 입력을 손으로 만들면 실제 입력의 크기와 글자를 따라가지 못한다. hook은 실제 세션에서 실제 입력으로 한 번 더 확인하고, 입력을 그대로 남기는 임시 로그를 붙일 수 있게 만들어 둔다.
