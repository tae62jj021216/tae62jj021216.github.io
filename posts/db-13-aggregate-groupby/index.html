[DB] 13. 집계 함수와 GROUP BY

여러 행을 하나의 값으로 요약하는 것이 집계 함수이고, 행을 기준 열의 값별로 묶어 묶음마다 요약하는 것이 GROUP BY다. 이 글에서는 COUNT의 세 가지 형태, 집계 함수가 NULL을 다루는 방식, GROUP BY와 HAVING, 소계를 붙이는 WITH ROLLUP, 값을 이어 붙이는 GROUP_CONCAT을 정리한다.

예제는 00편의 가상 카페 DB cafedb를 쓴다. NULL이 섞인 합계·평균을 보는 팁(tip) 예제만 연습 DB cafe_practice에 만든 staff 복사본으로 실행한다. MySQL 8.4에서 실행한 결과다.

실습 준비 SQL

cafedb.staff를 cafe_practice로 복사하고, 팁 열(tip)을 추가해 직원 8명 중 2·3·5·7번에게만 값을 넣는다. 나머지 4명은 NULL이다.

CREATE TABLE cafe_practice.staff AS
  SELECT staff_id, name, role, store, salary FROM cafedb.staff;
ALTER TABLE cafe_practice.staff ADD PRIMARY KEY (staff_id), ADD tip INT NULL;
UPDATE cafe_practice.staff SET tip = 300 WHERE staff_id = 2;

UPDATE cafe_practice.staff SET tip = 100 WHERE staff_id IN (5, 7);

행이 11개였는데 결과는 한 행이다. 집계 함수는 여러 행을 받아 값 하나를 돌려준다. MIN·MAX는 문자(사전 순)와 날짜(이른 순)에도 쓸 수 있다.

집계 함수는 SELECT, HAVING, ORDER BY에만 쓸 수 있다. WHERE에는 쓸 수 없는데, 이유는 뒤의 “WHERE와 HAVING”에서 본다.

COUNT의 세 가지 형태

member 테이블에는 전화번호(phone)가 없는 회원이 3명, 도시(city)가 없는 회원이 1명 있다.

1
2

SELECT COUNT(*), COUNT(phone), COUNT(city), COUNT(DISTINCT city)
FROM member;
형태세는 것결과
COUNT(*)행 전체. NULL이 있어도 센다8
COUNT(phone)phone이 NULL이 아닌 행5
COUNT(city)city가 NULL이 아닌 행7
COUNT(DISTINCT city)NULL을 뺀 서로 다른 값의 개수 (서울, 부산, 대전)3

주의할 점: COUNT(DISTINCT city)는 NULL을 세지 않는다. 12편에서 본 SELECT DISTINCT city는 NULL을 한 행으로 보여 주지만(4행), COUNT(DISTINCT city)는 3이다.

SUM·AVG·MIN·MAX는 NULL을 무시한다

COUNT(*)를 뺀 모든 집계 함수는 NULL을 계산에서 뺀다. NULL을 0으로 보지 않고, 아예 없는 행처럼 다룬다는 뜻이다.

cafedb에서 합계를 낼 만한 금액 열 중에는 NULL이 없어서, 첫머리의 “실습 준비 SQL”로 만든 cafe_practice.staff의 팁(tip) 열을 쓴다. 직원 8명 중 4명만 팁 값이 있고, 나머지 4명은 NULL이다.

1
2
3
4
5

SELECT COUNT(*) AS 직원수, COUNT(tip) AS 팁받음,
       SUM(tip) AS 합계, AVG(tip) AS 평균,
       AVG(COALESCE(tip, 0)) AS 전체평균,
       SUM(tip) / COUNT(*) AS 직접계산
FROM cafe_practice.staff;
직원수팁받음합계평균전체평균직접계산
84700175.000087.500087.5000
  • AVG(tip)은 700 / 4 = 175다. 분모가 전체 직원 수(8)가 아니라 NULL이 아닌 행 수(4)다.
  • “직원 한 명당 평균 팁”을 구하려면 NULL을 0으로 바꾼 뒤 평균을 내야 한다. COALESCE(tip, 0)은 tip이 NULL이면 0을 돌려준다(18편에서 자세히 다룬다). 결과는 700 / 8 = 87.5다.

주의할 점: AVG(열)과 SUM(열) / COUNT(*)는 NULL이 있으면 값이 다르다. AVG(열)은 SUM(열) / COUNT(열)과 같다. 문제에서 NULL을 0으로 볼지, 없는 값으로 볼지 먼저 확인한다.

조건에 맞는 행이 하나도 없으면 COUNT는 0이고, 나머지 집계 함수는 0이 아니라 NULL이다(예: WHERE price > 10000이면 SUM(price)는 NULL). 값이 전부 NULL인 그룹도 마찬가지다.

GROUP BY 열은 그 열의 값이 같은 행끼리 묶고, 묶음마다 결과 행을 하나씩 만든다.

SELECT에 쓸 수 있는 열: ONLY_FULL_GROUP_BY

그룹마다 결과가 한 행이므로, SELECT에는 그룹마다 값이 하나로 정해지는 것만 올 수 있다. GROUP BY에 쓴 열, 집계 함수, 상수가 그렇다. 그룹 안에 값이 여러 개인 열을 쓰면 오류가 난다.

1
2
3
4
5
6

SELECT category_id, name, AVG(price)
FROM menu
GROUP BY category_id;
-- ERROR 1055 (42000): Expression #2 of SELECT list is not in GROUP BY clause and contains
-- nonaggregated column 'cafedb.menu.name' which is not functionally dependent on columns
-- in GROUP BY clause; this is incompatible with sql_mode=only_full_group_by

category_id = 4 그룹에는 메뉴가 3개라서 name을 하나로 정할 수 없다. MySQL 5.7부터 기본으로 켜진 ONLY_FULL_GROUP_BY 모드가 이런 쿼리를 막는다(옛 버전은 그룹 안의 아무 값이나 보여 줬다). Oracle은 항상 오류(ORA-00979)다. 예외로, 기본키로 묶으면 다른 열의 값이 하나로 정해지므로(함수 종속, 6편) GROUP BY menu_id에서는 name을 써도 된다.

WHERE와 HAVING

HAVING은 그룹에 거는 조건이다. 12편에서 본 실행 순서를 다시 보면 차이가 분명하다.

FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT

 WHEREHAVING
걸러내는 대상행 (묶기 전)그룹 (묶은 후)
집계 함수쓸 수 없다쓸 수 있다
위치GROUP BY 앞GROUP BY 뒤

WHERE가 실행될 때는 아직 그룹이 없어서 COUNT(*)를 계산할 수 없다.

1
2
3
4
5

SELECT category_id, COUNT(*) AS 메뉴수
FROM menu
WHERE COUNT(*) >= 2
GROUP BY category_id;
-- ERROR 1111 (HY000): Invalid use of group function

두 조건을 함께 써 보자. “5,500원 이상인 메뉴가 2개 이상인 카테고리”는 가격 조건이 행 조건, 개수 조건이 그룹 조건이다.

1
2
3
4
5
6

SELECT category_id, COUNT(*) AS 메뉴수
FROM menu
WHERE price >= 5500               -- ① 행을 먼저 거른다
GROUP BY category_id              -- ② 남은 행을 묶는다
HAVING COUNT(*) >= 2              -- ③ 그룹을 거른다
ORDER BY category_id;
category_id메뉴수
32
72

HAVING 없이 실행하면 카테고리 4와 5가 1개씩으로 더 나온다. WHERE에서 5,500원 미만 메뉴가 먼저 빠졌기 때문에, 원래 메뉴가 3개인 카테고리 4도 1개로 세어진다.

주의할 점: HAVING category_id >= 5처럼 집계 함수가 없는 조건도 HAVING에 쓸 수는 있다. 하지만 행 조건은 WHERE에 두는 것이 원칙이다. 묶기 전에 행을 줄이므로 결과는 같고 처리할 양은 적다.

ORDER BY는 SELECT 다음에 실행되므로 별칭을 쓸 수 있다. HAVING은 SELECT보다 먼저 실행되니 원래는 쓸 수 없지만 MySQL은 HAVING avg_price >= 5000처럼 별칭을 허용한다. 표준 SQL과 Oracle에서는 HAVING AVG(price) >= 5000처럼 집계식을 다시 써야 하므로, 시험 답안은 표준 방식으로 쓰는 것이 안전하다.

WITH ROLLUP: 소계와 총계

GROUP BY ... WITH ROLLUP은 그룹별 결과 뒤에 소계와 총계 행을 덧붙인다. 합계 행에서 묶지 않은 열은 NULL로 나온다. 이 NULL은 실제 NULL 그룹과 구분되지 않으므로, GROUPING(열)(MySQL 8.0부터)로 가린다. 그 행이 ROLLUP이 만든 합계 행이면 1, 아니면 0이다.

1
2
3
4

SELECT IF(GROUPING(store) = 1, '전체', store) AS 지점, COUNT(*) AS 주문수
FROM orders
GROUP BY store WITH ROLLUP
ORDER BY GROUPING(store), store;
지점주문수
강변점4
공원점3
본점5
전체12

IF(조건, 참일 때 값, 거짓일 때 값)은 조건에 따라 두 값 중 하나를 고르는 MySQL 함수다(18편에서 CASE와 함께 다룬다). 여기서는 합계 행이면 '전체', 아니면 지점 이름을 보여 준다.

ORDER BY GROUPING(store)를 빼고 ORDER BY store만 쓰면 NULL이 가장 작은 값이라 총계 행이 맨 위로 올라간다. 기준 열이 두 개면(GROUP BY store, 구분 WITH ROLLUP) 앞 열의 값마다 소계가 붙고, 마지막에 총계가 붙는다. 표준 SQL과 Oracle은 GROUP BY ROLLUP(store, 구분)으로 쓰고, MySQL 8.4도 이 형태를 받아들인다. 표준 SQL과 Oracle에는 원하는 묶음을 골라 소계를 내는 GROUPING SETS, 모든 조합의 소계를 내는 CUBE도 있지만 MySQL은 ROLLUP만 지원한다.

GROUP_CONCAT: 그룹의 값을 이어 붙이기

집계 함수는 숫자 하나를 돌려주지만, GROUP_CONCAT은 그룹 안의 값을 이어 붙인 문자열 하나를 돌려준다. 괄호 안에서 DISTINCT, ORDER BY, SEPARATOR(구분자, 기본은 쉼표)를 지정할 수 있다. 안쪽 ORDER BY가 없으면 이어 붙이는 순서가 보장되지 않는다.

1
2
3
4
5

SELECT category_id,
       GROUP_CONCAT(name ORDER BY price DESC, menu_id SEPARATOR ' / ') AS 메뉴
FROM menu
GROUP BY category_id
ORDER BY category_id;
category_id메뉴
3딸기 에이드 / 말차라떼
4바닐라라떼 / 카페라떼 / 아메리카노
5콜드브루 라떼 / 콜드브루
7치즈케이크 / 초코케이크
8밤 마들렌 / 버터쿠키

GROUP_CONCAT도 NULL을 무시한다(복습 문제 4).

주의할 점: 결과 문자열의 최대 길이는 group_concat_max_len(기본 1024바이트)이고, 넘치는 부분은 경고만 남기고 잘린다. GROUP_CONCAT은 MySQL 함수이고, Oracle과 표준 SQL에서는 LISTAGG가 같은 역할을 한다.
