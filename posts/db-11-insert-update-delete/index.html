[DB] 11. INSERT, UPDATE, DELETE

테이블에 행을 넣는 INSERT, 값을 고치는 UPDATE, 행을 지우는 DELETE를 정리한다. 생략한 열에 들어가는 값, safe update 모드, 제약조건에 걸리는 경우를 다루고, 시험에 자주 나오는 “여러 문장을 실행한 뒤의 테이블 상태”를 따라가 본다.

예제는 00편의 cafedb를 연습 DB cafe_practice로 그대로 복사해 쓴다. 실습 준비 SQL 뒤에 본문 SQL을 위에서부터 차례로 실행하면 글과 같은 결과가 나온다(MySQL 8.4). 앞 예제에서 바뀐 데이터가 뒤 예제로 이어진다.

CREATE DATABASE cafe_practice DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
USE cafe_practice;

CREATE TABLE category   LIKE cafedb.category;
CREATE TABLE menu       LIKE cafedb.menu;
CREATE TABLE member     LIKE cafedb.member;
CREATE TABLE orders     LIKE cafedb.orders;
CREATE TABLE order_item LIKE cafedb.order_item;
INSERT INTO category   SELECT * FROM cafedb.category;
INSERT INTO menu       SELECT * FROM cafedb.menu;
INSERT INTO member     SELECT * FROM cafedb.member;
INSERT INTO orders     SELECT * FROM cafedb.orders;
INSERT INTO order_item SELECT * FROM cafedb.order_item;

ALTER TABLE category   ADD FOREIGN KEY (parent_id)   REFERENCES category(category_id);
ALTER TABLE menu       ADD FOREIGN KEY (category_id) REFERENCES category(category_id);
ALTER TABLE member     ADD FOREIGN KEY (referrer_id) REFERENCES member(member_id);
ALTER TABLE orders     ADD FOREIGN KEY (member_id)   REFERENCES member(member_id);
ALTER TABLE order_item ADD FOREIGN KEY (order_id) REFERENCES orders(order_id) ON DELETE CASCADE;
ALTER TABLE order_item ADD FOREIGN KEY (menu_id)  REFERENCES menu(menu_id);

기존 마지막 번호 12 다음부터 13, 14, 15가 매겨졌다.

주의할 점: 여러 행을 한 번에 넣으면 LAST_INSERT_ID()는 마지막 번호(15)가 아니라 첫 행의 번호(13)를 돌려준다. LAST_INSERT_ID()와 여러 행 VALUES는 MySQL에서 쓰는 방식이고, Oracle(21c까지)은 여러 행을 넣을 때 INSERT ALL을 쓴다.

INSERT INTO order_item (order_id, menu_id) VALUES (13, 12);   -- qty는 기본값 1

UPDATE: 값 고치기

1

UPDATE 테이블 SET 열1 = 값1 [, 열2 = 값2 ...] [WHERE 조건];

WHERE에 맞는 행만 고친다. SET에 여러 열을 쉼표로 적으면 한 문장으로 함께 고치고, 오른쪽에 원래 값을 쓴 계산식도 쓸 수 있다.

1
2

UPDATE menu SET price = price + 300, is_seasonal = FALSE WHERE menu_id = 11;
SELECT menu_id, name, price, is_seasonal FROM menu WHERE menu_id = 11;
menu_idnamepriceis_seasonal
11밤 마들렌38000

조건에 맞는 행이 여러 개면 모두 고친다. ROW_COUNT()는 바로 앞 문장이 바꾼 행 수다.

1
2

UPDATE menu SET price = price + 200 WHERE category_id = 4;
SELECT ROW_COUNT();
ROW_COUNT()
3

카테고리 4의 아메리카노·카페라떼·바닐라라떼가 4700·5200·5700원이 됐다. 고친 값도 제약조건을 지켜야 한다.

1
2

UPDATE menu SET price = 0 WHERE menu_id = 1;
-- ERROR 3819 (HY000): Check constraint 'menu_chk_1' is violated.

WHERE 없는 UPDATE

WHERE를 빠뜨리면 모든 행이 바뀐다. 오류도 경고도 없다.

1
2

UPDATE seasonal_menu SET price = 1000;
SELECT ROW_COUNT();
ROW_COUNT()
3

시즌 메뉴 세 개의 가격이 모두 1000원이 됐다.

safe update 모드

이런 사고를 막으려고 MySQL에는 safe update 모드가 있다. 켜 두면 키 열(기본키 등)을 쓰는 WHERE나 LIMIT이 없는 UPDATE·DELETE를 거부한다.

1
2
3
4
5
6
7
8
9

SET SESSION sql_safe_updates = 1;

UPDATE menu SET price = price + 100;
-- ERROR 1175 (HY000): You are using safe update mode and you tried to update a table without a WHERE that uses a KEY column.
UPDATE menu SET price = price + 100 WHERE price < 4000;      -- price는 키가 아니다
-- ERROR 1175 (HY000): You are using safe update mode and you tried to update a table without a WHERE that uses a KEY column.

UPDATE menu SET price = price + 100 WHERE menu_id = 10;      -- 기본키 조건은 된다 (1행)
SET SESSION sql_safe_updates = 0;

WHERE 없는 DELETE도 같은 오류로 거부된다. MySQL Workbench는 이 모드가 기본으로 켜져 있어서, 기본키가 아닌 조건으로 여러 행을 고치려 하면 이 오류를 자주 만난다(Workbench에서는 메시지 뒤에 모드를 끄는 방법 안내가 더 붙는다). 명령줄 클라이언트는 mysql --safe-updates로 접속하면 켜진다.

DELETE: 행 지우기

1

DELETE FROM 테이블 [WHERE 조건];

1

DELETE FROM menu WHERE menu_id = 14;      -- 1행 삭제

WHERE를 빼면 모든 행이 지워진다(테이블 구조는 남는다). TRUNCATE·DROP과의 차이는 9편에서 정리했다.

외래키와 DELETE

다른 테이블이 참조하는 행은 외래키의 ON DELETE 동작에 따라 결과가 달라진다(8편). 아메리카노(1번)는 주문 상세가 참조하고 있고, 그 외래키는 동작을 지정하지 않았으므로 삭제가 거부된다.

1
2

DELETE FROM menu WHERE menu_id = 1;
-- ERROR 1451 (23000): Cannot delete or update a parent row: a foreign key constraint fails (`cafe_practice`.`order_item`, CONSTRAINT `order_item_ibfk_2` FOREIGN KEY (`menu_id`) REFERENCES `menu` (`menu_id`))

반면 order_item.order_id는 ON DELETE CASCADE라서, 주문을 지우면 상세 행도 함께 지워진다.

1

DELETE FROM orders WHERE order_id = 1;    -- 주문 1번의 상세 2행도 함께 지워진다

단계별 상태 추적

시험에서는 INSERT·UPDATE·DELETE를 차례로 실행한 뒤 남은 행이나 값을 묻는 문제가 자주 나온다. 재고 테이블로 직접 따라가 본다. 단계마다 결과를 보기 전에 먼저 예측해 보자.

1
2
3
4

CREATE TABLE stock (
    item VARCHAR(10) PRIMARY KEY,
    qty  INT,
    unit VARCHAR(5) NOT NULL DEFAULT '개'
);
INSERT INTO stock VALUES ('원두', 12, 'kg'), ('우유', 4, 'L'), ('컵', 30, '개');  -- ①
INSERT INTO stock (item, unit) VALUES ('시럽', '병');                             -- ②
SELECT * FROM stock ORDER BY item;
itemqtyunit
시럽NULL병
우유4L
원두12kg
컵30개

①, ② 뒤: qty를 생략한 시럽은 기본값이 없어 NULL이다.

1
2

UPDATE stock SET qty = qty + 10 WHERE qty < 10;                                   -- ③
SELECT * FROM stock ORDER BY item;
itemqtyunit
시럽NULL병
우유14L
원두12kg
컵30개

③ 뒤: qty < 10이 참인 우유만 14가 된다. 시럽은 NULL < 10이 UNKNOWN이라 고쳐지지 않는다.

1
2

DELETE FROM stock WHERE qty < 15;                                                 -- ④
SELECT * FROM stock ORDER BY item;
itemqtyunit
시럽NULL병
컵30개

④ 뒤: qty < 15가 참인 원두(12)와 우유(14)가 지워진다. 시럽은 이번에도 UNKNOWN이라 지워지지 않고 남는다.

주의할 점: WHERE는 조건이 참인 행만 고르고, NULL과의 비교는 참이 아니다(12편). 그래서 NULL이 든 행은 <, >, <> 어느 조건의 UPDATE·DELETE에서도 빠진다. 상태 추적 문제에서는 NULL 행을 “끝까지 남는 행”으로 먼저 표시해 둔다.

정답과 해설

1. 기본값이 있는 grade는 'BASIC', 나머지는 NULL이다.

1

INSERT INTO member (member_id, name, joined_on) VALUES (112, '옥단춘', '2026-10-02');

2. 16이다. 두 행은 16, 17번이 되지만, 여러 행을 한 문장으로 넣으면 LAST_INSERT_ID()는 첫 행의 번호를 돌려준다. 같은 시점에 SELECT MAX(order_id) FROM orders;는 17이다.

3. (2, 10)과 (3, NULL)이 남는다.

  • UPDATE 뒤: (1, 3), (2, 10), (3, NULL), (4, 16). NULL >= 5는 참이 아니라 3번은 그대로다.
  • DELETE 뒤: point <> 10이 참인 1번(3)과 4번(16)이 지워진다. 3번은 NULL <> 10이 UNKNOWN이라 남는다.

4. (가), (라). (가)는 기본키 조건이라 실행된다. (나)는 WHERE가 없고, (다)는 키가 아닌 열만 조건에 써서 ERROR 1175로 거부된다. (라)는 키 조건은 없지만 LIMIT이 있어 실행된다.
