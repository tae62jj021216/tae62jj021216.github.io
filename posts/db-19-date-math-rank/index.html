[DB] 19. 날짜·수학·윈도우 함수

“주문 후 30일”, “가입한 지 몇 개월”, “백 원 단위로 반올림”, “가격 순위 1~3위”, “지점별 누적 매출” 같은 계산에 쓰는 MySQL의 날짜 함수, 수학 함수, 윈도우 함수(순위, 집계 OVER, LAG·LEAD, NTILE)를 정리한다.

예제는 00편의 cafedb를 쓴다. 조회만 하므로 cafedb에서 바로 실행하면 된다. “오늘”이 필요한 계산은 실행 시각에 따라 결과가 바뀌므로 2026-10-01로 날짜를 고정해 계산한다.

현재 날짜와 시각

함수돌려주는 값타입
NOW() (= CURRENT_TIMESTAMP)현재 날짜와 시각DATETIME
CURDATE() (= CURRENT_DATE)현재 날짜DATE
CURTIME() (= CURRENT_TIME)현재 시각TIME
SYSDATE()함수가 실행되는 순간의 날짜와 시각DATETIME

NOW()는 SQL 문이 시작된 시각으로 고정되고, SYSDATE()는 호출될 때마다 실제 시각을 읽는다. SELECT NOW(), SYSDATE(), SLEEP(2), NOW(), SYSDATE();를 실행하면 두 NOW()는 같은 시각이고, 두 번째 SYSDATE()만 첫 번째보다 2초 뒤다. 보통은 NOW()를 쓴다. Oracle에서는 SYSDATE(괄호 없음)가 대표 함수다.

날짜 더하고 빼기: DATE_ADD, DATE_SUB, INTERVAL

DATE_ADD(날짜, INTERVAL n 단위), DATE_SUB(날짜, INTERVAL n 단위)로 계산한다. 단위는 MINUTE, HOUR, DAY, MONTH, YEAR 등이다. 날짜 + INTERVAL n 단위처럼 연산자로 써도 된다.

4
5

SELECT order_id, ordered_at,
       DATE_ADD(ordered_at, INTERVAL 30 DAY) AS coupon_until,
       ordered_at - INTERVAL 2 HOUR          AS minus2h
FROM orders
WHERE order_id = 1;
order_idordered_atcoupon_untilminus2h
12026-08-01 08:12:002026-08-31 08:12:002026-08-01 06:12:00

월·연 단위로 더해 없는 날짜가 되면 그달의 마지막 날로 맞춰진다. DATE_ADD('2026-01-31', INTERVAL 1 MONTH)는 2026-02-28이다.

주의할 점: MySQL에서 날짜에 그냥 + 1을 하면 하루 뒤가 아니라 숫자가 된다. DATE('2026-08-01') + 1은 20260802, DATE('2026-08-31') + 1은 존재하지 않는 20260832다. 반드시 + INTERVAL 1 DAY(결과 2026-09-01)나 DATE_ADD를 쓴다. Oracle은 날짜 + 1이 하루 뒤이고, 월 단위 계산은 ADD_MONTHS(날짜, n)을 쓴다.

날짜에서 부분 꺼내기

YEAR(), MONTH(), DAY(), HOUR() 등은 해당 부분의 숫자를, DAYNAME()은 요일 이름(영문)을 돌려준다. 요일 번호는 WEEKDAY()(월요일 0 ~ 일요일 6)와 DAYOFWEEK()(일요일 1 ~ 토요일 7) 두 가지다. 표준 SQL 형식인 EXTRACT(HOUR FROM '2026-08-15 16:25:00')(결과 16)도 쓸 수 있다. Oracle도 EXTRACT를 지원하지만, 시·분·초는 TIMESTAMP 값에서만 꺼낼 수 있다.

수학 함수

함수뜻
ROUND(x, n)소수점 아래 n자리로 반올림. n이 음수면 정수 부분에서 반올림
TRUNCATE(x, n)소수점 아래 n자리로 버림. n 생략 불가
FLOOR(x)x 이하의 가장 큰 정수
CEIL(x) (= CEILING)x 이상의 가장 작은 정수
ABS(x)절댓값
MOD(a, b) (= a % b)나머지

ROUND(1234.567, 1)은 1234.6, ROUND(1234.567, -2)는 1200, TRUNCATE(1234.567, 1)은 1234.5다. TRUNCATE(1234.5)처럼 자릿수를 빼면 문법 오류(ERROR 1064)다. Oracle은 TRUNC(x)로 자릿수를 생략할 수 있다.

음수에서 달라지는 함수들

양수에서는 FLOOR와 TRUNCATE가 같아 보이지만 음수에서 갈린다.

1
2

SELECT x, ROUND(x) AS r, FLOOR(x) AS f, CEIL(x) AS c, TRUNCATE(x, 0) AS t
FROM (SELECT 2.5 AS x UNION ALL SELECT -2.5) AS v;
xrfct
2.53232
-2.5-3-3-2-2

FLOOR는 수직선의 왼쪽, CEIL은 오른쪽, TRUNCATE는 0 쪽으로 가고, ROUND는 .5를 0에서 먼 쪽으로 올린다. 단, ROUND의 이 규칙은 2.5 같은 정확한 소수(DECIMAL)일 때이고, DOUBLE 값은 가까운 짝수로 반올림해 ROUND(2.5E0)이 2다.

MySQL의 MOD 결과는 나눠지는 수(왼쪽)의 부호를 따라 MOD(-7, 3)은 -1, MOD(7, -3)은 1이다. 7 DIV 2는 정수 몫 3이다. CEIL은 자릿수 인자가 없어서, 백 원 단위로 올리려면 CEIL(x / 100) * 100처럼 쓴다.

윈도우 함수와 순위: RANK, DENSE_RANK, ROW_NUMBER

윈도우 함수는 GROUP BY와 달리 행 수는 그대로 두고, 각 행과 관련된 행 묶음(윈도우)을 계산해 그 행 옆에 결과를 붙인다. 순위 함수가 대표적이다.

1

함수() OVER ([PARTITION BY 그룹 기준] [ORDER BY 정렬 기준 [ASC | DESC]])

세 함수는 동점을 다루는 방식이 다르다. 메뉴 가격 순위로 비교한다.

SELECT menu_id, name, price,
       RANK()       OVER (ORDER BY price DESC)          AS rnk,
       DENSE_RANK() OVER (ORDER BY price DESC)          AS dense,
       ROW_NUMBER() OVER (ORDER BY price DESC, menu_id) AS rn
FROM menu
ORDER BY price DESC, menu_id;

PARTITION BY와 그룹별 상위 N개

PARTITION BY를 넣으면 그룹마다 순위를 1부터 다시 매긴다. 그런데 “순위가 3 이하인 행”을 바로 WHERE로 거르면 오류가 난다.

1

3
4

SELECT name, price, RANK() OVER (ORDER BY price DESC) AS rnk
FROM menu
WHERE RANK() OVER (ORDER BY price DESC) <= 3;
-- ERROR 3593 (HY000): You cannot use the window function 'rank' in this context.'

윈도우 함수는 WHERE·GROUP BY·HAVING이 끝난 뒤 SELECT 단계에서 계산되기 때문이다. 순위를 계산한 결과를 인라인 뷰나 CTE로 감싸고 바깥에서 거른다. 지점별 주문 금액 상위 2건은 다음과 같다.

WITH ranked AS (
  SELECT o.store, o.order_id, SUM(oi.qty * m.price) AS amount,
         RANK() OVER (PARTITION BY o.store
                      ORDER BY SUM(oi.qty * m.price) DESC) AS rnk
  FROM orders o
  JOIN order_item oi ON oi.order_id = o.order_id
  JOIN menu m ON m.menu_id = oi.menu_id
  GROUP BY o.store, o.order_id
)
SELECT store, order_id, amount, rnk
FROM ranked
WHERE rnk <= 2
ORDER BY store, rnk, order_id;

동점이 있으면 함수에 따라 행 수가 달라진다. 카테고리별 최고가 메뉴를 뽑으면 RANK() ... = 1은 케이크 분류에서 6,500원인 치즈케이크와 초코케이크를 둘 다, ROW_NUMBER() ... = 1은 하나만 돌려준다.

Oracle의 ROWNUM은 ORDER BY보다 먼저 매겨져서, 정렬 전의 임의 행이 잘린다. 정렬한 인라인 뷰 바깥에서 쓰거나 RANK/ROW_NUMBER를 쓴다. MySQL의 LIMIT은 정렬 뒤에 적용된다.

집계 함수 + OVER: 누적합과 그룹 합계

SUM, AVG, COUNT 같은 집계 함수도 OVER를 붙이면 윈도우 함수가 된다. OVER (PARTITION BY store)는 지점 전체 합계, 여기에 ORDER BY ordered_at을 더하면 지점 안에서 처음부터 현재 행까지의 합계, 즉 누적합이다. 주문별 금액을 CTE(17편)로 구한 뒤 두 값을 붙인다.

WITH order_amount AS (
  SELECT o.order_id, o.store, o.ordered_at, SUM(oi.qty * m.price) AS amount
  FROM orders o
  JOIN order_item oi ON oi.order_id = o.order_id
  JOIN menu m        ON m.menu_id   = oi.menu_id
  GROUP BY o.order_id, o.store, o.ordered_at
)
SELECT store, order_id, DATE(ordered_at) AS day, amount,
       SUM(amount) OVER (PARTITION BY store ORDER BY ordered_at) AS running,
       SUM(amount) OVER (PARTITION BY store)                     AS store_total
FROM order_amount
ORDER BY store, ordered_at;

지점이 바뀌면 누적합이 다시 시작되고, 지점의 마지막 행에서 running이 store_total과 같아진다. amount / SUM(amount) OVER (PARTITION BY store)로 쓰면 지점 매출 중 비율이 된다.

범위는 ROWS BETWEEN으로 직접 정할 수도 있다. OVER (PARTITION BY store ORDER BY ordered_at ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)는 직전 2건과 현재 행, 즉 최근 3건의 이동 합계다.

주의할 점: ORDER BY만 쓴 기본 범위는 처음부터 현재 행과 정렬 값이 같은 행까지(RANGE)다. 정렬 기준에 동점이 있으면 동점 행들의 누적합이 같은 값으로 나온다. 한 행씩 누적하려면 겹치지 않는 열을 정렬 기준에 더하거나 ROWS로 범위를 정한다.

LAG, LEAD, NTILE

LAG(열)은 윈도우 안에서 바로 앞 행의 값을, LEAD(열)은 바로 뒤 행의 값을 가져온다. 앞뒤 행이 없으면 NULL이고, LAG(열, n, 기본값)으로 몇 행 앞인지와 NULL 대신 쓸 값을 줄 수 있다. 회원별로 직전 주문과의 간격(일)과 다음 주문 번호를 구한다.

SELECT member_id, order_id, ordered_at,
       LAG(ordered_at) OVER w                       AS prev_at,
       DATEDIFF(ordered_at, LAG(ordered_at) OVER w) AS gap_days,
       LEAD(order_id) OVER w                        AS next_order
FROM orders
WHERE member_id IN (101, 103)
WINDOW w AS (PARTITION BY member_id ORDER BY ordered_at)
ORDER BY member_id, ordered_at;

NTILE(n)은 정렬한 행을 n개 그룹으로 나눠 그룹 번호(1~n)를 붙인다. 나누어떨어지지 않으면 앞 그룹부터 한 행씩 더 가진다. 메뉴 11개에 NTILE(3) OVER (ORDER BY price DESC, menu_id)를 적용하면 4개, 4개, 3개로 나뉘어 비싼 메뉴 4개가 1그룹이 된다. 상위 25% 같은 구간을 나눌 때 쓴다.

정답과 해설

1. RANK는 1, 2, 2, 4, 5, 5, 7, 8이고 DENSE_RANK는 1, 2, 2, 3, 4, 4, 5, 6이다. 급여가 같은 cafedb의 staff에 실행해도 같다.

2. WEEKDAY는 월요일이 0이므로 토·일은 5, 6이다.

SELECT order_id, store, DATE(ordered_at) AS day, DAYNAME(ordered_at) AS dname
FROM orders
WHERE WEEKDAY(ordered_at) IN (5, 6)
ORDER BY order_id;

1, 2, 3(일요일), 7, 10, 12번 주문 6건이 나온다. DAYOFWEEK(ordered_at) IN (1, 7)로 써도 같은 결과다.

3. 순서대로 -4, -4, -3, -1, 15700, 30, -30이다.

ROUND(-3.5)는 0에서 먼 쪽, FLOOR는 왼쪽, TRUNCATE는 0 쪽으로 간다. MOD는 왼쪽 수의 부호를 따르고, ROUND(15749, -2)는 십의 자리에서 반올림한다. DATEDIFF는 (끝, 시작), TIMESTAMPDIFF는 (시작, 끝) 순서라 같은 순서로 넣으면 부호가 반대다.

4. PARTITION BY store로 지점마다 순위를 매기고, 동점을 모두 남기려면 RANK(또는 DENSE_RANK)를 쓴다.

SELECT store, name, salary
FROM (SELECT store, name, salary,
             RANK() OVER (PARTITION BY store ORDER BY salary DESC) AS rnk
      FROM staff
      WHERE store IS NOT NULL) AS t
WHERE rnk = 1
ORDER BY store;
