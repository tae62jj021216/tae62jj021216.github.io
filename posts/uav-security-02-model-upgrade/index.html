UAV 보안 이상 탐지 #1 — 1학기 모델을 스크립트로 고도화하기

2학기 첫 작업은 1학기에 만든 Simulink 모델을 이어받아 고치는 일이었다. 블록을 마우스로 옮기고 선을 다시 잇는 대신, 모든 수정을 MATLAB 스크립트로 했다.

한 일

출발점과 원칙

출발점은 1학기 모델 세 개(공격기 모델, UAV 모델, 둘을 묶은 전체 모델)다. 고칠 곳을 정리해 보니 탐지·대응 논리의 버그, 빠진 기능, 실험 기록에 필요한 신호가 섞여 있었다. 그래서 고치기 전에 원칙 네 가지를 정했다.

원칙내용이유
바깥 인터페이스는 그대로UDP 포트, 패킷 크기, 필드 순서를 1학기 모델과 같게 둔다기존 브리지·시험 도구를 고치지 않고 연결하려고
바깥 의미가 바뀌는 수정은 설정으로PX4로 보내는 패킷에 모드 칸 추가, 송신 주기, 경고 코드는 설정 값으로 켜고 끈다. 기본값은 1학기 동작이다바꾼 동작과 원래 동작을 같은 모델로 비교하려고
대응은 유지하고 올리기만한 번 켜진 대응은 비행 끝까지 유지하고, 더 강한 대응으로만 바뀐다탐지 신호가 깜빡일 때 모드가 오락가락하지 않게
모든 수정은 스크립트로스크립트가 블록을 찾아 값과 선을 고친다원본에 다시 돌리면 같은 결과가 나온다

마지막 원칙이 가장 쓸모 있었다. Simulink 모델 파일은 바이너리라 GUI로 고친 내용은 diff로 보이지 않는다. 스크립트로 고치면 “무엇을 왜 바꿨는지”가 스크립트에 남고, 수정이 꼬이면 원본에서 다시 적용하면 된다. v2.0 이후 수정이 30건 넘게 쌓였지만 언제든 1학기 원본에서 같은 모델을 다시 만들 수 있었다.

고친 것

v2.0에서 고친 것 중 일부다.

고친 곳바꾼 내용
탐지 켜는 조건안전 모드에 들어간 뒤에도 탐지와 기록을 계속한다
대응 유지대응 값을 래치(latch)해 비행 끝까지 유지하고 올리기만 한다
보안 기능 시작시작 뒤 3초(30 sample) 동안 기다리던 지연을 없앴다
HOLD 기준 위치안전 모드에 들어간 순간의 위치로 고정한다
기록내부 신호와 UTC 시각을 기록해 브리지 기록과 시각을 맞출 수 있게 했다
실행 주기세 모델을 0.1초 고정 주기로 맞추고, 전체 모델은 실시간에 맞춰 돌게 했다

PX4 없이 먼저 검증

PX4 가상 비행을 붙이기 전에, 모델 논리만 따로 검증했다.

단계방법결과
컴파일·배선세 모델을 컴파일하고 끊긴 선을 찾는다통과. 끊긴 입력은 모두 1학기부터 쓰지 않던 옛 블록 안에 있었다
인터페이스1학기 모델과 블록 트리를 비교한다UDP 블록 설정 변경 없음
UAV 단독Python UDP 피더가 텔레메트리와 공격 패킷을 흉내 내 UAV 모델에 보낸다 (공격 40초)정상 오탐 0. Replay 40.5초 확정 → HOLD, Flood 40.7초 → LAND, Range 40.9초 → RTH
회귀 비교같은 입력을 1학기 모델과 v2.0에 넣는다첫 탐지 시각이 같거나 0.1초 차이. 1학기 모델은 Replay를 Flood로도 분류했고, v2.0은 Replay로만 분류했다

막힌 점

3에 영원히 닿지 않는 카운터

1학기 모델의 비행 상태 이상 확정 신호는 켜질 수 없는 구조였다. 상태 이상은 “기준을 3회 연속 넘으면 확정”하는데, 카운터가 2를 넘지 못했다.

카운터는 이번 값 = 직전 값 + 1로 세야 한다. 그런데 직전 값을 담는 지연 블록에 카운트가 아니라 직전의 0/1 판정 신호가 들어가 있었다. 직전 값이 최대 1이니 카운트는 최대 2이고, 기준 3에는 영원히 닿지 않는다.

같은 구조를 쓰는 공격별 “2회 연속 확인”은 기준이 2라 우연히 동작하고 있었다. 그래서 공격 탐지는 정상처럼 보였고, 상태 이상만 죽어 있었다.

5초 중 4초가 아니라 0.2초

공격기 모델의 Flood 버스트 블록 설정은 주기 5, 펄스 폭 4였다. 주석은 “5 sample 중 4 sample 동안 보낸다”였다. 실제로 시간 기준 펄스 생성기의 펄스 폭은 sample 수가 아니라 주기에 대한 백분율이다. 5초 주기 중 4%, 0.2초만 켜져 있었다. Flood를 시험하려면 공격부터 제대로 나가야 해서, 이 부분은 v2.0에 함께 고쳤다.

이름으로 블록을 찾을 수 없다

스크립트로 블록을 찾을 때 처음에는 블록 이름을 썼다. 이 모델은 블록 이름에 줄바꿈이 섞인 것이 많아 이름 매칭이 자주 실패했다. 블록마다 붙은 고유 번호(SID)로 찾도록 바꿨다. 참조 모델 안의 블록을 고칠 때는 그 참조 모델을 먼저 불러와야 SID로 찾을 수 있다.

되돌렸더니 1학기 모델이 됐다

실험용으로 바꾼 설정을 되돌리려고 데이터 사전 파일에 git checkout -- <파일>을 썼다. v2 설정이 아니라 1학기 원본 설정이 돌아왔다. 스크립트를 적용할 때 원본 커밋에서 파일을 꺼내 오는 과정(git checkout <원본 커밋> -- <파일>)이 원본을 스테이징 영역에 올려 두었고, git checkout --은 스테이징 영역의 내용으로 되돌리기 때문이다.

같은 실수를 이틀 연속 했다.

해결

문제해결다음에 볼 것
카운터가 3에 못 닿음지연 블록에 카운터 출력을 되돌려 넣었다카운터의 피드백 선이 자기 출력으로 돌아오는지
펄스 폭이 백분율sample 기준 펄스로 바꿨다시간 기준인지 sample 기준인지
블록 이름 매칭 실패SID로 찾는다블록 이름을 키로 쓰지 않는다
되돌렸더니 원본스크립트 적용 직후 결과를 스테이징해 둔다. 설정 기본값은 설정 스크립트로 되돌린다git checkout --이 무엇으로 되돌리는지

배운 점: 카운터와 펄스 폭 버그 모두 주석과 블록 이름은 의도대로 적혀 있었다. 주석이 아니라 블록 설정 값과 선의 연결을 직접 따라가야 실제 동작이 보인다.
