[DB] 17. CROSS·SELF JOIN과 CTE

15편의 조인은 서로 다른 두 테이블을 공통 열로 이었고, 16편에서는 FROM 절에 서브쿼리를 넣는 인라인 뷰를 봤다. 이 글에서는 조건 없이 모든 조합을 만드는 CROSS JOIN, 한 테이블을 자기 자신과 잇는 SELF JOIN, 그리고 인라인 뷰에 이름을 붙여 단계별로 쓰는 CTE(WITH)와 계층 구조를 따라 내려가는 재귀 CTE를 정리한다.

예제는 00편의 cafedb를 쓴다. MySQL 8.4에서 실행한 결과다.

CROSS JOIN: 카티션 곱

CROSS JOIN은 조인 조건 없이 왼쪽의 모든 행과 오른쪽의 모든 행을 하나씩 짝짓는다. 이것을 카티션 곱(Cartesian product)이라 하고, 결과 행 수는 두 테이블 행 수의 곱이다.

1

SELECT COUNT(*) FROM member CROSS JOIN menu;
COUNT(*)
88

회원 8명 × 메뉴 11개 = 88행이다. 결과의 열 개수(차수)는 두 테이블 열 수의 합, 행 개수(카디널리티)는 두 테이블 행 수의 곱이다. 관계대수의 ×(카티션 곱)에 해당하며 22편에서 다시 다룬다.

다음 두 형태도 MySQL에서는 같은 88행을 만든다.

1
2

SELECT COUNT(*) FROM member, menu;       -- 쉼표 조인에서 WHERE 조건을 빠뜨린 경우
SELECT COUNT(*) FROM member JOIN menu;   -- ON 없는 JOIN

주의할 점: 쉼표 조인에서 조인 조건을 빠뜨리면 오류 없이 카티션 곱이 나온다. 행이 수천 개인 테이블끼리라면 결과가 수백만 행이 된다. 또 ON 없는 JOIN을 CROSS JOIN처럼 받아 주는 것은 MySQL의 확장이고, 표준 SQL과 Oracle에서는 INNER JOIN에 조인 조건이 반드시 있어야 한다.

카티션 곱은 “모든 조합”이 필요할 때 쓴다. 예를 들어 점장 3명에게 시즌 메뉴 2개를 하나씩 시식하게 하는 배정표는 staff CROSS JOIN menu에 두 조건을 걸어 3 × 2 = 6행으로 만든다.

SELF JOIN: 자기 자신과 조인

staff 테이블의 manager_id는 같은 테이블의 staff_id를 가리키는 외래키다. 직원 이름 옆에 상사 이름을 보려면 staff를 두 번 불러 서로 다른 별칭을 붙이고 조인한다. 한쪽은 “직원” 역할, 다른 쪽은 “상사” 역할이다.

FROM staff e
LEFT JOIN staff m ON e.manager_id = m.staff_id

대표 월매는 상사가 없어(manager_id가 NULL) 내부 조인으로 쓰면 결과에서 빠진다(7행). 모든 직원을 보려고 LEFT JOIN을 썼다.

별칭은 선택이 아니라 필수다. FROM staff JOIN staff처럼 같은 이름을 두 번 쓰면 ERROR 1066 (42000): Not unique table/alias: 'staff'가 난다. 회원의 추천인(referrer_id)도 같은 구조다(복습 문제 2).

셀프 조인은 계층 관계가 아니어도 쓴다. 같은 지점 직원 두 명씩의 짝은 staff a JOIN staff b ON a.store = b.store AND a.staff_id < b.staff_id로 구한다. a.staff_id < b.staff_id가 없으면 (방자, 방자) 같은 자기 자신과의 짝과, 순서만 바뀐 짝이 모두 나온다.

CTE: WITH로 쿼리에 이름 붙이기

CTE(Common Table Expression, 공통 테이블 식)는 WITH 이름 AS (쿼리)로 쿼리 결과에 이름을 붙여, 바로 뒤의 쿼리에서 테이블처럼 쓰게 한다. 16편의 인라인 뷰(FROM (SELECT ...) AS t)를 쿼리 앞으로 빼내 이름을 붙인 것이라고 보면 된다. MySQL 8.0부터 지원한다.

1
2
3
4

WITH 이름 AS (
    SELECT ...
)
SELECT ... FROM 이름 ...;

WITH spending AS (
    SELECT o.member_id, SUM(mn.price * oi.qty) AS total
    FROM orders o
    JOIN order_item oi ON o.order_id = oi.order_id
    JOIN menu mn       ON oi.menu_id = mn.menu_id
    WHERE o.member_id IS NOT NULL
    GROUP BY o.member_id
)
SELECT m.name, m.grade, s.total
FROM spending s
JOIN member m ON s.member_id = m.member_id
WHERE s.total >= 15000
ORDER BY s.total DESC, m.member_id;

1단계(spending)에서 회원별 합계를 만들고, 2단계에서 그 결과를 회원 테이블과 조인해 거른다. spending을 괄호째 FROM 절에 넣으면 16편의 인라인 뷰와 결과가 같다. 다만 인라인 뷰는 안쪽부터 읽어야 하고, CTE는 단계마다 이름이 있어 위에서 아래로 읽힌다.

CTE는 WITH a AS (...), b AS (...)처럼 쉼표로 여러 개 이어 쓸 수 있고, 뒤의 CTE가 앞의 CTE를 참조할 수 있다. 예를 들어 spending으로 평균을 구하는 한 행짜리 CTE stats를 만들고 CROSS JOIN으로 모든 행에 붙이면 “평균보다 많이 산 회원”을 고를 수 있다. 카티션 곱을 쓸모 있게 쓰는 전형적인 경우다(복습 문제 3).

주의할 점: CTE는 그 WITH가 붙은 한 문장 안에서만 쓸 수 있다. 다음 쿼리에서 다시 쓰려면 WITH를 다시 적어야 한다. 여러 쿼리에서 계속 쓸 이름이 필요하면 뷰(20편)를 만든다.

재귀 CTE

WITH RECURSIVE는 자기 자신을 참조하는 CTE다. 두 부분을 UNION ALL로 잇는다.

부분역할
앵커(anchor) 멤버시작 행을 만든다. 한 번만 실행된다
재귀(recursive) 멤버바로 전 단계에서 새로 만들어진 행을 받아 다음 행을 만든다. 새 행이 없으면 멈춘다

가장 단순한 예로 1부터 5까지의 수를 만들어 보자.

1
2
3
4
5
6

WITH RECURSIVE nums AS (
    SELECT 1 AS n                          -- 앵커: 1
    UNION ALL
    SELECT n + 1 FROM nums WHERE n < 5     -- 재귀: 앞 단계 값 + 1
)
SELECT n FROM nums;   -- 1, 2, 3, 4, 5 다섯 행

앵커가 1을 만들고, 재귀 멤버가 1 → 2 → 3 → 4 → 5를 차례로 만든다. n = 5인 행에서는 WHERE n < 5가 거짓이라 새 행이 없으므로 멈춘다.

조직도: 단계와 경로

대표에서 시작해 manager_id를 따라 아래로 내려가며, 몇 단계 아래인지(lvl)와 대표부터의 경로(path)를 만든다.

WITH RECURSIVE org AS (
    SELECT staff_id, name, role, 1 AS lvl, CAST(name AS CHAR(100)) AS path
    FROM staff
    WHERE manager_id IS NULL                          -- 앵커: 상사가 없는 대표
    UNION ALL
    SELECT s.staff_id, s.name, s.role, o.lvl + 1, CONCAT(o.path, ' > ', s.name)
    FROM staff s
    JOIN org o ON s.manager_id = o.staff_id           -- 재귀: 앞 단계 직원의 부하
)
SELECT lvl, name, role, path FROM org ORDER BY path;

3장화바리스타월매 > 방자 > 장화
4옹고집파트타임월매 > 방자 > 장화 > 옹고집
3홍련바리스타월매 > 방자 > 홍련

실행 과정은 이렇다.

  1. 앵커: 월매(lvl 1)
  2. 1회차: 상사가 월매인 방자·향단·변학도(lvl 2)
  3. 2회차: 상사가 lvl 2 직원인 장화·홍련·전우치(lvl 3)
  4. 3회차: 상사가 장화인 옹고집(lvl 4)
  5. 4회차: 상사가 옹고집인 직원이 없어 멈춘다

path로 정렬하면 한 사람의 부하가 그 사람 바로 아래에 모여 트리 모양으로 읽힌다.

CAST(name AS CHAR(100))에는 이유가 있다. 재귀 CTE의 열 타입은 앵커 멤버가 정한다. name을 그대로 쓰면 path 열이 VARCHAR(10)이 되어, 경로가 길어지는 순간 오류가 난다.

특정 직원 아래의 팀원만 보고 싶으면 앵커의 시작점만 바꾼다(WHERE staff_id = 2로 시작하면 방자와 그 아래 장화·홍련·옹고집). 셀프 조인 한 번으로는 “바로 위 상사”까지만 알 수 있지만, 재귀 CTE는 단계 수를 몰라도 끝까지 따라간다.

카테고리 계층

category도 parent_id로 대분류 → 중분류 → 소분류를 이룬다. 음료(1) 아래에 커피(2)·논커피(3)가, 커피 아래에 에스프레소(4)·콜드브루(5)가 있고, 디저트(6) 아래에 케이크(7)·구움과자(8)가 있다. 조직도와 같은 틀로 경로를 만들 수 있다.

메뉴는 가장 아래 단계 카테고리에만 붙어 있어서, “음료”에 속한 메뉴를 찾으려면 음료의 모든 하위 카테고리를 먼저 모아야 한다.

1

WITH RECURSIVE sub AS (
    SELECT category_id FROM category WHERE name = '음료'
    UNION ALL
    SELECT c.category_id FROM category c JOIN sub s ON c.parent_id = s.category_id
)
SELECT mn.menu_id, mn.name, mn.category_id
FROM menu mn
JOIN sub s ON mn.category_id = s.category_id
ORDER BY mn.menu_id;

sub에는 1(음료), 2(커피), 3(논커피), 4(에스프레소), 5(콜드브루)가 모이고, 메뉴와 조인하면 음료 메뉴 7개가 나온다.

끝나지 않는 재귀

재귀 멤버가 계속 새 행을 만들면 무한히 반복된다. 종료 조건을 빠뜨린 경우다.

1
2
3
4
5
6
7
8

WITH RECURSIVE forever AS (
    SELECT 1 AS n
    UNION ALL
    SELECT n + 1 FROM forever
)
SELECT COUNT(*) FROM forever;
-- ERROR 3636 (HY000): Recursive query aborted after 1001 iterations.
-- Try increasing @@cte_max_recursion_depth to a larger value.

MySQL은 cte_max_recursion_depth(기본 1000)번을 넘게 반복하면 쿼리를 멈춘다. 정말 깊은 계층이라면 SET SESSION cte_max_recursion_depth = ...로 늘릴 수 있지만, 먼저 종료 조건이 있는지 확인한다.

주의할 점: 데이터에 순환(A의 상사가 B, B의 상사가 A)이 있으면 종료 조건이 있어도 끝나지 않는다. 경로 문자열에 이미 들른 번호가 있는지 검사하거나, lvl < 10처럼 깊이 제한을 재귀 멤버의 WHERE에 넣어 막는다.

Oracle은 RECURSIVE 키워드 없이 WITH org (열 목록) AS (...)로 쓰고, 옛 방식으로 START WITH ... CONNECT BY PRIOR ...와 LEVEL을 쓰는 계층 쿼리도 있다.
