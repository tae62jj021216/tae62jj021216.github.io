모은 데이터를 CSV로만 두면, 여러 번 모은 결과를 합치거나 조건으로 골라 보기가 번거롭다. 데이터베이스에 넣어 두면 SQL로 바로 조회할 수 있다. 이 글에서는 pymysql로 파이썬에서 MySQL에 접속해, 9편에서 받은 매장 23곳을 테이블에 넣고 꺼낸다.

설치는 pip install pymysql. SQL 문법(CREATE TABLE, INSERT, SELECT)은 데이터베이스 시리즈에서 다룬다. 결과는 Python 3.12, PyMySQL 2.2, MySQL 8.4에서 확인했다. 예제 DB 이름은 cafe_crawl이다.

연결 → 커서 → 실행 → 커밋 → 닫기

pymysql로 하는 일은 늘 이 순서다.

import os
import pymysql

DB = dict(host="127.0.0.1", port=3306, user="root",
          password=os.environ["MYSQL_PWD"],     # 비밀번호는 코드에 쓰지 않는다 (9편)
          charset="utf8mb4")

conn = pymysql.connect(**DB)
cur = conn.cursor()
print(cur.execute("DROP DATABASE IF EXISTS cafe_crawl"))
print(cur.execute("CREATE DATABASE cafe_crawl DEFAULT CHARACTER SET utf8mb4"))
conn.select_db("cafe_crawl")                     # USE cafe_crawl 과 같다

cur.execute("""
CREATE TABLE store (
    store_id   CHAR(4)      PRIMARY KEY,
    name       VARCHAR(50)  NOT NULL,
    sido       VARCHAR(20)  NOT NULL,
    gugun      VARCHAR(20)  NOT NULL,
    addr       VARCHAR(100),
    seats      INT,
    drive_thru CHAR(1),
    open_date  DATE
)""")
cur.execute("SHOW TABLES")
print(cur.fetchall())

commit하지 않으면

pymysql은 기본으로 자동 커밋이 꺼져 있다. 다른 연결을 하나 더 열어 확인해 본다.

other = pymysql.connect(**DB, database="cafe_crawl")

with other.cursor() as c2:
    c2.execute("SELECT COUNT(*) FROM store")
    print("커밋 전 다른 연결:", c2.fetchone())

conn.commit()
other.commit()            # 다른 연결도 새 상태를 보도록 자기 트랜잭션을 끝낸다

with other.cursor() as c2:
    c2.execute("SELECT COUNT(*) FROM store")
    print("커밋 후 다른 연결:", c2.fetchone())

커밋 전 다른 연결: (0,)
커밋 후 다른 연결: (1,)

execute가 1을 돌려줬어도 커밋 전에는 다른 연결에서 0건이다. INSERT·UPDATE·DELETE 뒤에는 반드시 conn.commit()을 부른다. 커밋하지 않고 연결을 닫으면 넣은 내용이 사라진다. 트랜잭션은 데이터베이스 시리즈 21편에서 자세히 다룬다.

주의할 점: other.commit()을 빼면 “커밋 후”에도 0건이 나온다. MySQL의 기본 격리 수준(REPEATABLE READ)에서는 한 트랜잭션 안의 SELECT가 처음 본 상태를 계속 보기 때문이다. 오래 열어 둔 연결로 조회할 때 최신 데이터가 안 보이면 이것을 의심한다.

try:
    cur.execute(sql, ("S024", "가상카페 서구 3호점", "대전광역시", "서구", "대전광역시 서구 연습로 99", 30, "N", "2026-09-01"))
    cur.execute(sql, rows[0])          # S001은 이미 있다
    conn.commit()
except pymysql.err.IntegrityError as e:
    conn.rollback()
    print("IntegrityError:", e.args)

cur.execute("SELECT COUNT(*) FROM store WHERE store_id = 'S024'")
print(cur.fetchone())

첫 INSERT(S024)는 성공했지만 두 번째가 실패해 rollback()으로 함께 취소되었다. “둘 다 들어가거나 둘 다 안 들어가거나”를 지키려면, 묶을 작업을 한 try 안에 두고 끝에서 한 번 commit(), 실패하면 rollback()한다.

메서드돌려주는 것
fetchone()다음 한 행 (튜플). 없으면 None

부산 매장 7곳 중 1 + 2 + 4행을 차례로 꺼냈다. 커서는 읽은 위치를 기억하며 앞으로만 간다.

주의할 점: 마지막 fetchall()이 빈 튜플 ()이다. 이미 다 읽어서 남은 행이 없기 때문이다. 같은 결과가 다시 필요하면 처음 꺼낸 결과를 변수에 담아 두거나 execute를 다시 한다.

값을 SQL 문자열에 끼워 넣지 않는다

값 안의 작은따옴표 '가 SQL의 따옴표를 닫아 버려 문법 오류가 났다. 더 위험한 경우는 값이 SQL의 뜻을 바꿀 때다.

SELECT * FROM store WHERE name = 'x\' OR \'1\'=\'1'

f-string으로 넣으면 조건이 name = 'x' OR '1'='1'이 되어 23행이 모두 나왔다. 이것이 SQL 삽입(SQL injection)이다. %s로 넘기면 pymysql이 따옴표를 \'로 바꿔 값 전체를 글자 하나로 다룬다(mogrify는 실제로 보낼 SQL을 보여 준다). 크롤링한 글자에는 따옴표가 얼마든지 들어 있으므로, 값은 항상 %s로 넘긴다.

주의할 점: %s는 값 자리에만 쓸 수 있다. 테이블 이름·열 이름은 %s로 넘기면 따옴표가 붙어 오류가 난다. 이름을 바꿔 가며 써야 한다면 정해 둔 목록({"store", "product"})에 있는지 확인한 뒤 문자열로 넣는다.
