[크롤링] 06. 정적 크롤링 ② 목록에서 상세 페이지로

목록 페이지에는 이름과 가격뿐이고, 원산지·재고·리뷰는 상품을 눌러 들어간 상세 페이지에 있다. 이 글에서는 목록에서 상세 링크를 모으고, 링크마다 들어가 정보를 꺼낸다. 요청이 30번 넘게 일어나므로 실패해도 멈추지 않게 짠다.

5편의 get_soup()(요청 + BeautifulSoup)을 그대로 쓴다. 결과는 Python 3.12, beautifulsoup4 4.15, pandas 3.0에서 확인했다.

상대 주소와 urljoin

목록 페이지의 상품 링크는 href="item/p001.html"처럼 상대 주소다. 브라우저는 지금 보고 있는 페이지 주소를 기준으로 이것을 완전한 주소로 바꾼다. 코드에서는 urllib.parse.urljoin이 같은 일을 한다.

주의할 점: 문자열을 이어 붙여 주소를 만들면 ../가 해석되지 않는다. 상세 페이지(.../shop/item/p001.html)의 “목록으로” 링크 ../list-1.html을 BASE_URL + "item/" + href로 붙이면 .../shop/item/../list-1.html이 된다. urljoin(상세 주소, href)를 쓰면 .../shop/list-1.html로 정리된다. 링크는 항상 그 링크가 있던 페이지 주소를 기준으로 urljoin한다.

def parse_detail(soup):
    spec = {}
    for tr in soup.select("table.spec tr"):
        spec[tr.select_one("th").get_text(strip=True)] = tr.select_one("td").get_text(strip=True)

    reviews = [{"user": li.select_one(".user").text,
                "stars": li.select_one(".star").text.count("★"),
                "text": li.select_one("p").text}
               for li in soup.select("ul.reviews li.review")]

    info = {"title": soup.select_one("h1.title").text,
            "origin": spec.get("원산지"),
            "stock": spec.get("재고"),
            "review_samples": len(reviews),
            "first_review": reviews[0]["text"] if reviews else None}
    return info, spec, reviews

soup = get_soup(urljoin(BASE_URL + "list-1.html", "item/p001.html"))
info, spec, reviews = parse_detail(soup)
print(spec)
print(reviews)
print(info)

def list_links(list_url):
    soup = get_soup(list_url)
    return [urljoin(list_url, a["href"]) for a in soup.select("li.product .name a")]

links = list_links(BASE_URL + "list-1.html")
print(len(links), links[0], links[-1])

def crawl_details(list_urls, delay=1.0):
    rows, failed = [], []
    seen = set()                                   # 이미 방문한 상세 주소
    for list_url in list_urls:
        for link in list_links(list_url):
            if link in seen:
                continue
            seen.add(link)
            try:
                info, _, _ = parse_detail(get_soup(link))
                rows.append({"url": link.rsplit("/", 1)[1], **info})
            except (requests.RequestException, AttributeError) as e:
                failed.append((link.rsplit("/", 1)[1], type(e).__name__))
            time.sleep(delay)
    return pd.DataFrame(rows), failed

함수 하나가 한 가지 일만 하게 나눴다.

함수하는 일
get_soup(url)요청하고 BeautifulSoup으로 바꾼다 (5편)
list_links(list_url)목록 한 페이지에서 상세 주소를 모은다
parse_detail(soup)상세 페이지 하나에서 값을 꺼낸다
crawl_details(list_urls)위 셋을 이어 전체를 돌고, 중복·실패를 처리한다

꺼내는 규칙이 바뀌면 parse_detail만, 페이지 넘기는 방식이 바뀌면 crawl_details만 고치면 된다.

실패한 페이지

상세 주소 하나가 없어졌다고 해 보자(p999.html은 없는 페이지다). list_links가 앞의 두 링크와 이 주소를 돌려주도록 바꿔 돌리면 이렇게 나온다.

1

(2, 6) [('p999.html', 'HTTPError')]

get_soup의 raise_for_status()가 404에서 HTTPError를 냈고, try가 그것을 잡아 failed에 적은 뒤 다음 링크로 넘어갔다. 나머지 2개는 정상으로 모였다.

주의할 점: except Exception:으로 모든 예외를 잡으면 코드의 오타(NameError 등)까지 조용히 넘어가 원인을 찾기 어렵다. 예상한 실패(요청 실패 requests.RequestException, 태그가 없을 때의 AttributeError)만 잡고, 실패 목록을 남겨 나중에 다시 시도한다.

복습 문제

  1. 현재 페이지가 https://site.com/shop/item/p001.html일 때 다음 href를 urljoin한 결과를 쓰시오.
    • ① p002.html
    • ② ../list-2.html
    • ③ /notice.html
  2. spec["원산지"] 대신 spec.get("원산지")를 쓴 이유는 무엇인가?
  3. crawl_details에서 seen 집합을 없애고 같은 입력(1페이지 두 번)으로 돌리면 몇 행이 되는가?
  4. 상세 페이지의 별점 ★★★☆☆를 숫자 3으로 바꾸는 코드를 쓰시오.
정답과 해설
  1. ① https://site.com/shop/item/p002.html ② https://site.com/shop/list-2.html ③ https://site.com/notice.html
  2. 원두가 아닌 상품에는 원산지 항목이 없다. []는 KeyError로 멈추고, get은 None을 돌려준다.
  3. 38행. 1페이지의 상품 8개가 한 번 더 들어간다.
  4. "★★★☆☆".count("★") → 3
