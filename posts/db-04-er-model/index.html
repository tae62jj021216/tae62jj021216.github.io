[DB] 04. 설계 단계와 ER 모델

테이블을 만들기 전에 무엇을 저장하고 서로 어떻게 연결되는지부터 정리해야 한다. 이 글에서는 데이터베이스 설계 단계와, 개념적 설계에서 쓰는 ER 모델(개체-관계 모델)의 구성 요소를 예제 카페 DB cafedb(00편)로 정리한다.

데이터베이스 설계 단계

설계는 보통 아래 순서로 진행하고, 뒤 단계에서 문제가 보이면 앞 단계로 돌아가 고친다.

단계하는 일결과물
1. 요구사항 분석저장할 데이터와 자주 하는 작업을 조사한다 (“비회원도 주문할 수 있다”)요구사항 명세서
2. 개념적 설계개체·속성·관계와 제약을 DBMS와 상관없이 표현한다ER 다이어그램
3. 논리적 설계관계 모델 같은 데이터 모델의 스키마로 바꾼다테이블, 기본키·외래키
4. 스키마 정제중복과 이상 현상을 찾아 테이블을 나눈다 (정규화, 6·7편)정규화된 스키마
5. 물리적 설계저장 구조, 인덱스, 자료형을 정한다물리 스키마
6. 보안 설계역할별 접근 권한을 정한다 (10편)권한 계획

주의할 점: 시험에서는 흔히 요구 조건 분석 → 개념적 설계 → 논리적 설계 → 물리적 설계 → 구현의 5단계로 묻는다. 이때 정규화는 논리적 설계, 인덱스·저장 레코드 양식·접근 경로는 물리적 설계, ERD 작성은 DBMS와 무관한 개념적 설계다.

ER 모델의 세 요소

ER 모델(Entity-Relationship Model)은 현실 세계를 개체, 속성, 관계 세 가지로 표현하는 개념적 데이터 모델이고, 이것을 그림으로 그린 것이 ER 다이어그램(ERD)이다.

개체 (Entity)

개체는 저장할 가치가 있고 다른 것과 구별되는 현실의 대상이다. 사람(회원), 사물(메뉴), 사건(주문)처럼 명사로 나타난다. 같은 속성을 가진 개체들의 묶음(회원)을 개체 타입, 그 안의 하나(회원 101번 홍길동)를 개체 인스턴스라고 하며, 나중에 각각 테이블과 행이 된다.

속성 (Attribute)

속성은 개체나 관계가 가진 성질이다.

종류뜻카페 예Chen 기호
단순 / 단일값 속성더 나눌 수 없다 / 값이 하나다메뉴의 가격, 회원의 이름타원
복합 속성더 작은 속성으로 나뉜다회원 주소 → 시·구·상세 주소타원에 하위 타원
다중값 속성값이 여러 개일 수 있다회원의 연락처(휴대폰, 집 전화)이중 타원
유도 속성다른 값에서 계산된다주문 합계 금액점선 타원
키 속성개체 하나를 유일하게 식별한다회원 번호 member_id이름에 밑줄

유도 속성은 언제든 계산할 수 있으므로 보통 따로 저장하지 않는다. 속성의 종류는 요구사항이 정한다. cafedb는 phone을 하나만 저장하므로 단일값 속성이지만, 연락처를 여러 개 받기로 하면 다중값 속성이 된다.

관계 (Relationship)

관계는 개체 사이의 연관으로, 보통 동사로 나타낸다(“회원이 주문을 한다”). 관계도 속성을 가질 수 있다. 주문 수량 qty는 “이 주문에 이 메뉴를 몇 개 담았는가”라는 담기 관계의 속성이다. 아메리카노의 수량은 주문 1에서는 2, 주문 3에서는 1이라 메뉴만으로도, 주문만으로도 정할 수 없다.

관계에 참여하는 개체 타입의 수를 관계의 차수(degree)라고 한다. 두 개체 사이면 이항, 세 개체 사이면 삼항, 같은 개체끼리면 단항(순환) 관계다.

주의할 점: 1편의 릴레이션 차수(열의 개수)와 관계의 차수(참여 개체 수)는 이름만 같고 다른 개념이다.

관계의 카디널리티: 1:1, 1:N, M:N

한 개체가 상대 개체 몇 개와 연결될 수 있는지를 카디널리티 비율(대응 수)이라고 한다.

비율질문 결과카페 예
1:1양쪽 모두 최대 1개지점 하나에 점장 한 명, 점장 한 명은 한 지점만 (지점을 개체로 뽑는다면)
1:N한쪽은 여러 개, 반대쪽은 최대 1개회원 한 명은 주문 여러 건, 주문 한 건의 회원은 최대 한 명
M:N양쪽 모두 여러 개주문 한 건에 메뉴 여러 개, 메뉴 하나는 여러 주문에

cafedb는 지점을 store 문자열 속성으로만 저장하지만, 지점마다 주소·전화번호가 필요해지면 개체로 뽑는다.

참여 제약: 전체 참여와 부분 참여

카디널리티가 최대 몇 개인지를 말한다면, 참여 제약은 최소 하나는 있어야 하는지를 말한다. 모든 개체가 반드시 참여하면 전체 참여(필수, Chen에서 이중선), 참여하지 않는 개체가 있어도 되면 부분 참여(선택, 단일선)다.

  • 회원 - 주문함 - 주문: 양쪽 모두 부분 참여다. 주문이 없는 회원(팥쥐)이 있고, 회원 번호가 NULL인 비회원 주문(3번)도 있다.
  • 주문 - 담기 - 메뉴: 빈 주문은 없으므로 주문은 전체 참여, 새 메뉴는 아직 안 팔렸을 수 있으므로 메뉴는 부분 참여다.

둘을 한 번에 (최소, 최대)로 적기도 한다. 담기 관계에 주문은 (1, N), 메뉴는 (0, N)으로, 주문함 관계에 주문은 (0, 1)로 참여한다.

주의할 점: (최소, 최대)는 “그 개체 하나가 관계에 몇 번 참여하는가”를 그 개체 쪽에 적는다. 회원 쪽에 1, 주문 쪽에 N을 적는 1:N 표기와 위치가 반대로 보이므로 표기법을 먼저 확인한다.

약한 개체와 식별 관계

자기 속성만으로는 식별되지 않고 다른 개체의 키를 빌려야 식별되는 개체를 약한 개체(weak entity), 키를 빌려 주는 개체를 소유 개체, 둘을 잇는 관계를 식별 관계라고 한다.

메뉴마다 “샷 추가” 같은 옵션을 둔다고 하자. “샷 추가”는 아메리카노에도 카페라떼에도 있으므로 메뉴 번호 + 옵션 이름이 있어야 식별된다. 메뉴 옵션이 약한 개체, 메뉴가 소유 개체이고, 소유 개체 안에서만 구별되는 옵션 이름이 부분 키다.

  • 소유 개체와 1:N 관계이고, 약한 개체 쪽은 식별 관계에 전체 참여한다.
  • 소유 개체가 없으면 존재할 수 없다(존재 종속).
  • Chen 표기법에서 약한 개체는 이중 사각형, 식별 관계는 이중 마름모, 부분 키는 점선 밑줄이다.

순환 관계

같은 개체 타입끼리 맺는 관계가 순환 관계(recursive relationship)다. cafedb의 직원은 manager_id로 같은 테이블의 상사를 가리킨다. 직원은 “관리한다” 관계에 상사와 부하 두 역할로 참여하고, 상사 한 명에 부하 여럿이므로 1:N이다. 대표는 상사가 없으므로(manager_id가 NULL) 부하 쪽은 부분 참여다. 회원의 추천인(referrer_id), 상위 카테고리(parent_id)도 같은 구조다.

ISA: 상위 개체와 하위 개체

개체를 세부 종류로 나눌 때 ISA 관계(특수화·일반화)를 쓴다. 공통 속성은 상위 개체(직원: 직원 번호, 이름, 지점)에, 종류별 속성은 하위 개체(정규직: 월급 / 파트타임: 시급)에 두고, 하위 개체는 상위 개체의 속성과 키를 물려받는다.

위에서 아래로 나누면 특수화, 공통점을 모아 위로 올리면 일반화다. 겹침/분리, 전체/부분 제약도 정하며, ERD에서는 상위·하위 개체 사이에 삼각형을 두고 ISA라고 적는다.

cafedb를 ER 모델로 정리하기

이벤트 테이블을 빼면 cafedb의 개체는 카테고리(category_id), 회원(member_id), 메뉴(menu_id), 주문(order_id), 직원(staff_id) 다섯이고(괄호 안은 키), 관계는 이렇다.

관계참여 개체비율참여 제약
주문함회원 - 주문1:N회원 부분, 주문 부분
담기 (속성 qty)주문 - 메뉴M:N주문 전체, 메뉴 부분
분류카테고리 - 메뉴1:N카테고리 부분, 메뉴 전체
상위 분류 / 추천 / 관리카테고리끼리 / 회원끼리 / 직원끼리1:N (순환)양쪽 부분

메뉴는 반드시 카테고리 하나에 속하지만 ‘음료’ 같은 상위 카테고리에는 메뉴가 직접 달려 있지 않아서, 분류 관계는 메뉴 쪽만 전체 참여다.

5편에서 이 표를 규칙에 따라 테이블로 바꾼다.

표기법: Chen과 까마귀발

교과서와 시험은 Chen 표기법을, 실무 모델링 도구는 까마귀발(IE, Crow’s Foot) 표기법을 주로 쓴다.

의미Chen 표기법까마귀발 표기법
개체 / 속성사각형 / 타원사각형 / 사각형 안에 한 줄씩
관계마름모개체를 잇는 선
1 / N선 옆에 1, N, M선 끝에 막대(│) / 까마귀발(<)
참여이중선 = 전체 참여막대 = 최소 1(필수), 원(○) = 최소 0(선택)
약한 개체이중 사각형, 이중 마름모식별 관계는 실선, 비식별 관계는 점선

까마귀발에서는 M:N을 교차 개체(예: 주문 상세)를 끼운 1:N 두 개로 풀어 그리는 경우가 많다.

주의할 점: 정보처리기사는 Chen 기호를 짝지어 묻는다. 개체 사각형, 관계 마름모, 속성 타원, 다중값 속성 이중 타원, 기본키 속성 밑줄, 약한 개체 이중 사각형.

복습 문제

  1. 다음 작업은 설계 5단계(요구 조건 분석, 개념적, 논리적, 물리적 설계, 구현) 중 어느 단계에서 하는지 쓰시오.
    ① ER 다이어그램 작성 ② 정규화 ③ 인덱스와 접근 경로 결정 ④ 사용자 인터뷰로 업무 파악
  2. 회원 개체에 다음 속성을 추가하려 한다. 각 속성의 종류(복합, 다중값, 유도)를 쓰시오.
    ① 생년월일에서 계산한 나이 ② 관심 메뉴 목록 ③ 우편번호·도로명·상세 주소로 나눈 주소
  3. 지점마다 좌석에 1번부터 번호를 붙여서 본점에도 강변점에도 3번 좌석이 있다. ‘좌석’을 ER 모델로 나타낼 때 약한 개체, 소유 개체, 부분 키, 식별자를 쓰시오.
  4. “모든 메뉴는 반드시 카테고리 하나에 속하고, 카테고리에는 메뉴가 하나도 없을 수 있다.” 이 문장에서 분류 관계의 카디널리티 비율과 양쪽의 참여 제약을 쓰고, 메뉴와 카테고리의 (최소, 최대)를 쓰시오.
정답과 해설
  1. ① 개념적 설계 ② 논리적 설계 ③ 물리적 설계 ④ 요구 조건 분석. 정규화는 테이블 구조(논리 스키마)를 다듬는 일이라 물리적 설계가 아니다.
  2. ① 유도 속성 ② 다중값 속성 ③ 복합 속성.
  3. 약한 개체는 좌석, 소유 개체는 지점, 부분 키는 좌석 번호, 식별자는 (지점, 좌석 번호). 좌석 번호만으로는 어느 지점의 3번인지 알 수 없어서 지점의 키를 빌린다.
  4. 카테고리:메뉴 = 1:N. 메뉴는 전체 참여, 카테고리는 부분 참여. (최소, 최대)로는 메뉴가 (1, 1), 카테고리가 (0, N)이다.
