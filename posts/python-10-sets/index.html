[Python] 10. 세트(set), 중복 없는 자료형, 합집합/교집합/차집합

기초 자료형 시리즈의 마지막인 세트(set)를 정리했다. 딕셔너리 바로 다음에 배우니까 왜 이 순서로 배우지 싶었는데, 정리하다 보니 세트가 딕셔너리와 뿌리가 같은 자료형이라는 걸 알게 됐다.

세트란

중복 값을 허용하지 않고(유일한 값으로만 구성), 순서가 없어서 인덱스로 접근할 수 없다. 딕셔너리의 키는 중복되면 안 된다고 배웠는데, 세트는 딕셔너리의 키만 모아놓은 구조라고 설명돼 있어서 딕셔너리 파트가 왜 먼저 나왔는지 이해가 됐다.

s1 = {1, 2, 3, 4, 2, 1, 5}
print(s1)   # {1, 2, 3, 4, 5}  <- 중복된 1, 2는 자동으로 하나만 남는다

{}가 빈 딕셔너리로 해석된다는 걸 모르고 있었으면 나중에 분명 헷갈렸을 것 같다. 세트를 {}로 만들려면 안에 값이 최소 하나는 있어야 한다.

세트에 넣을 수 없는 것들

세트는 내부적으로 모든 요소를 해싱(hashing)을 이용해서 저장하고 관리한다. 그래서 값이 바뀔 수 있는(mutable) 자료형은 요소로 넣을 수 없다.

# 세트 안에 세트를 요소로 가질 수 없음 (unhashable)
# s4 = {1, 2, s2}
# TypeError: unhashable type: 'set'

# 리스트도 넣을 수 없음
# s4 = {1, 2, [1, 2]}
# TypeError: unhashable type: 'list'

# 하지만 튜플은 넣을 수 있음 (immutable이니까)
s4 = {1, 2, (1, 2)}
print(s4)

# 인덱스 접근도 불가
# s2[0]  -> TypeError: 'set' object is not subscriptable

해시코드가 변경되면 안 된다는 설명을 보고, 딕셔너리 키 규칙(immutable만 가능)과 세트가 담을 수 있는 요소 규칙이 결국 같은 이유(해싱)에서 나온다는 걸 알게 됐다.

s1 = {1, 2, 3}

# 추가
s1.add(13)          # 요소 하나 추가
s1.update(s2)        # 다른 집합의 요소들을 병합

# 삭제
s1.clear()                 # 전체 삭제
s1 = {1, 2, 3, 6, 13}
s1.discard(3)               # 값으로 삭제 (없어도 에러 안 남)
s1.discard(30)               # 없는 값이어도 안전하게 무시됨
s1.remove(6)                 # 값으로 삭제 (없으면 KeyError!)
# s1.remove(16)               # KeyError 발생

print(s1.pop())              # 임의의 요소 하나를 반환하며 삭제 (순서가 없어서 뭐가 나올지 모름)

discard()와 remove()는 둘 다 값으로 지우는데, 차이는 없는 값을 만났을 때다. remove(x)는 x가 없으면 KeyError를 내고, discard(x)는 아무 일 없이 조용히 넘어간다. 그래서 없는 값을 지우려 할 때 안전하게 넘어가고 싶으면 discard(), 반드시 있어야 하는 값이라 없으면 에러로 알고 싶으면 remove()를 쓰면 되겠다고 정리했다.

집합 연산, 합집합/교집합/차집합

세트를 배우는 진짜 이유가 이 부분이 아닐까 싶을 정도로 유용했다.

s1 = {1, 2, 3}
s2 = {3, 6, 1}

# + 연산은 지원하지 않는다 (리스트와 다른 점!)
# s1 + s2  -> TypeError

# 합집합 : | 또는 union()
print(s1 | s2)             # {1, 2, 3, 6}
print(s1.union(s2))

# 교집합 : & 또는 intersection()
print(s1 & s2)              # {1, 3}
print(s1.intersection(s2))

# 차집합 : - 또는 difference()
print(s1 - s2)               # {2}  (s1에는 있지만 s2엔 없는 것)
print(s1.difference(s2))
print(s2 - s1)                # {6}  (반대 방향은 결과가 다름)

리스트에서 되던 + 연산이 세트에서는 안 된다는 게 처음엔 의아했는데, 세트는 합치는 개념 자체가 수학의 집합 연산(합집합/교집합/차집합)으로 정의돼 있어서 +라는 개념이 애초에 안 맞는다는 걸 이해했다. 그리고 차집합은 방향에 따라 결과가 다르다는 것도 실습하면서 직접 확인했다.

빈 세트는 {}가 아니라 set()으로 만들어야 한다는 것({}는 딕셔너리), 세트에는 리스트를 못 넣지만 튜플은 넣을 수 있다는 것(mutable vs immutable), discard()는 없는 값이어도 안전하고 remove()는 없으면 KeyError라는 것, s1 - s2와 s2 - s1은 방향에 따라 결과가 다르다는 것까지가 오늘 정리한 내용이다.

복습 문제.

  1. 두 강의의 수강생 학번이 python_class = {101, 102, 105, 108}, data_class = {102, 103, 108, 110}일 때, 다음을 각각 세트 연산으로 구해보시오.
    • 둘 중 하나라도 듣는 학생은 모두 몇 명인지 (len() 활용)
    • 두 강의를 다 듣는 학생의 학번
    • 데이터 강의는 안 듣고 파이썬 강의만 듣는 학생의 학번
    • 두 강의 중 딱 한 강의만 듣는 학생의 학번 (지금까지 나온 연산 두 개를 조합해볼 것)

  2. 리스트 nums = [1, 2, 2, 3, 4, 4, 4, 5]에서 세트를 이용해 중복을 제거한 뒤, 다시 정렬된 리스트로 만드는 코드를 작성해보시오.

  3. s = {1, 2, 3}에 대해 s.discard(10)과 s.remove(10)을 각각 실행했을 때 어떤 차이가 생기는지 예측하고, 실제로 실행해서 확인해보시오.

  4. 두 문자열 "hello world"와 "world of python"에 공통으로 등장하는 문자를 세트로 구해보시오. (set(문자열)을 활용) 결과에 공백 ' '도 들어가는지 확인해보고, 공백을 뺀 알파벳만 남기려면 어떻게 하면 되는지도 작성해볼 것.
