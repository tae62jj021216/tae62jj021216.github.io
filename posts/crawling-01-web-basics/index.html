[크롤링] 01. 웹 데이터 수집의 원리

웹 페이지에서 데이터를 모으려면 먼저 브라우저가 페이지를 어떻게 받아 오는지 알아야 한다. 이 글은 코드 없이 그 흐름을 정리하고, 어떤 도구로 수집할지 고르는 기준을 세운다.

이 시리즈의 예제는 이 블로그에 만들어 둔 연습 페이지(https://tae62jj021216.github.io/assets/crawl/)로 실행한다. 상품·매장·사람 이름은 모두 가상이다. 실제 사이트로 연습할 때는 아래 “수집 예절”을 먼저 본다.

크롤링과 스크래핑

용어뜻
크롤링(crawling)프로그램이 링크를 따라 여러 페이지를 돌아다니며 모으는 것
스크래핑(scraping)한 페이지에서 필요한 정보만 골라 꺼내는 것
크롤러(crawler)크롤링하는 프로그램

실제로는 둘을 섞어 쓴다. 쇼핑몰 목록 4페이지를 돌며(크롤링) 각 상품의 이름과 가격을 꺼내는(스크래핑) 식이다. 이 시리즈에서는 둘을 묶어 “크롤링”이라고 부른다.

클라이언트와 서버

브라우저 주소창에 주소를 넣으면 다음 일이 일어난다.

  1. 브라우저(클라이언트)가 서버에 “이 페이지를 달라”는 요청(request)을 보낸다.
  2. 서버가 응답(response)으로 HTML 문서를 돌려준다.
  3. 브라우저가 HTML을 읽고, 그 안에 적힌 CSS·이미지·자바스크립트를 다시 요청한다.
  4. 자바스크립트가 실행되며 화면을 더 그리기도 한다.

크롤링 프로그램은 이 중 클라이언트 역할을 대신한다. 어디까지 대신하느냐가 도구를 고르는 기준이 된다.

HTML과 DOM

응답 본문인 HTML은 태그가 겹겹이 들어간 문서다. 브라우저는 이것을 나무 모양의 DOM(Document Object Model)으로 바꿔 화면을 그린다.

    <h2 class="name"><a href="item/p001.html">에티오피아 예가체프 200g</a></h2>
    <p class="price"><strong class="sale">15,300원</strong></p>

ul 안에 li가, li 안에 h2와 p가 있다. 원하는 값(상품명, 가격)을 꺼내려면 “어느 태그 안의, 어떤 class를 가진 태그”인지를 찾아야 한다. 이 길을 찾는 도구가 3·4편의 BeautifulSoup이다.

연습 페이지의 dynamic/reviews.html에서 Ctrl+U를 누르면 <ul id="review-list"></ul>처럼 빈 목록만 있다. 화면의 리뷰는 페이지가 열린 뒤 자바스크립트가 reviews.json을 받아 그린 것이다. 서버가 보낸 HTML만 받는 도구로는 이 리뷰를 얻을 수 없다.

개발자 도구로 데이터 찾기

브라우저에서 F12를 누르면 개발자 도구가 열린다. 크롤링 전에 세 탭을 본다.

탭보는 것
Elements지금 화면의 DOM. 원하는 값이 어떤 태그·class 안에 있는지 확인한다
Network페이지가 주고받은 요청 목록. Fetch/XHR만 골라 보면 자바스크립트가 받아 온 JSON이 보인다
Console자바스크립트를 직접 실행해 본다

동적 페이지라도 Network 탭에서 데이터가 담긴 JSON 주소를 찾으면, 브라우저를 띄우지 않고 그 주소를 직접 요청해 받을 수 있다. 리뷰 페이지라면 reviews.json이다. 브라우저를 움직이는 방법보다 빠르고 단순하다.

수집 예절

robots.txt

사이트 운영자는 사이트 맨 위의 robots.txt에 크롤러가 지켜 주길 바라는 규칙을 적는다.

1
2
3

User-agent: *          ← 모든 크롤러에게
Allow: /admin/help/    ← 이 경로는 괜찮음
Disallow: /admin/      ← 그 밖의 /admin/ 아래는 가져가지 말 것

파이썬의 urllib.robotparser로 주소마다 허용 여부를 물어볼 수 있다.

1

from urllib.robotparser import RobotFileParser

rules = """User-agent: *
Allow: /admin/help/
Disallow: /admin/
"""
rp = RobotFileParser()
rp.parse(rules.splitlines())
for path in ["/shop/list-1.html", "/admin/users.html", "/admin/help/faq.html"]:
    print(path, rp.can_fetch("*", path))

1
2
3

/shop/list-1.html True
/admin/users.html False
/admin/help/faq.html True

robots.txt는 법이 아니라 약속이다. 그렇다고 무시해도 된다는 뜻은 아니다. 함께 지킬 것은 이렇다.

  • 요청 사이에 간격을 둔다. 반복문으로 페이지를 돌 때 time.sleep(1) 정도를 넣는다. 몰아 보내면 서버에 부담을 주고 429나 차단을 받는다.
  • 이용약관과 저작권을 확인한다. 수집을 금지한 사이트가 있고, 모은 글·이미지를 다시 공개하면 저작권 문제가 된다.
  • 개인정보는 모으지 않는다.
  • 로그인이나 자동입력 방지(캡차)를 우회하지 않는다. 사람인 척 막아 둔 장치를 피해 가는 코드는 쓰지 않는다.
  • 필요한 만큼만 가져간다. 같은 페이지를 계속 다시 받지 말고 한 번 받은 결과를 저장해 쓴다.

주의할 점: 파이썬 robotparser는 규칙을 위에서부터 보고 처음 맞는 것을 쓴다. 위 예에서 Disallow: /admin/을 Allow보다 먼저 쓰면 /admin/help/faq.html도 False가 된다. 표준(RFC 9309)은 경로가 더 구체적인 규칙을 따르라고 하므로, 판정이 다르게 나올 수 있다.

주의할 점: 파이썬 robotparser는 빈 줄을 규칙 묶음의 끝으로 읽는다. 이 블로그의 robots.txt는 User-agent: * 다음에 빈 줄이 있어서, 그대로 읽으면 Disallow: /norobots/가 어느 크롤러에도 걸리지 않고 can_fetch가 True로 나온다. 파서마다 해석이 다를 수 있으니, 결과만 믿지 말고 robots.txt 원문을 직접 열어 본다.

복습 문제

  1. 다음 URL에서 서버로 보내지 않는 부분은 무엇인가?
    https://example.com/board/list?page=3&size=20#comment-5
  2. 응답 상태 코드가 429일 때 크롤러에서 먼저 고칠 것은 무엇인가?
  3. 페이지를 열면 목록이 보이는데 Ctrl+U(페이지 소스 보기)에는 목록이 없다. 이 페이지에서 데이터를 얻는 방법 두 가지를 쓰시오.
  4. robots.txt가 User-agent: *, Disallow: /data/, Allow: /data/open/ 순서로 적혀 있다. 파이썬 robotparser로 /data/open/a.csv를 물으면 결과는 무엇이고, 그 이유는 무엇인가?
  5. 상황에 맞는 도구를 고르시오.
    • ① 공공기관이 인증키를 받고 쓰는 API를 제공한다
    • ② 버튼을 눌러야 표가 바뀌고, Network 탭에서 데이터 주소를 찾지 못했다
    • ③ 상품 목록이 페이지 소스에 그대로 있다
정답과 해설
  1. #comment-5(프래그먼트). 브라우저가 페이지 안 위치를 찾는 데만 쓴다. ?page=3&size=20(쿼리)는 서버로 간다.
  2. 요청 간격. 429는 짧은 시간에 요청이 너무 많다는 뜻이므로 time.sleep으로 간격을 늘린다.
  3. ① 개발자 도구 Network 탭(Fetch/XHR)에서 목록을 담은 JSON 주소를 찾아 직접 요청한다. ② Selenium으로 브라우저를 띄워 자바스크립트가 그린 뒤의 화면에서 꺼낸다.
  4. False. robotparser는 위에서부터 처음 맞는 규칙을 쓰는데, /data/open/a.csv는 첫 줄 Disallow: /data/에 먼저 걸린다. 경로가 더 구체적인 규칙을 따르는 표준 해석으로는 허용이다.
  5. ① API 요청(9편) ② Selenium(7·8편) ③ requests + BeautifulSoup(2~6편)
