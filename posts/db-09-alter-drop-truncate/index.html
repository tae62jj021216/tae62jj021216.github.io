[DB] 09. ALTER, DROP, TRUNCATE와 인덱스

테이블 구조를 바꾸는 ALTER, 테이블을 없애는 DROP, 테이블을 비우는 TRUNCATE를 정리한다. 열과 제약조건의 추가·변경·삭제, DROP·TRUNCATE·DELETE의 차이, 조회를 빠르게 하는 인덱스를 다룬다.

예제는 00편의 cafedb를 연습 DB cafe_practice로 복사해 쓴다. 실습 준비 SQL 뒤에 본문 SQL을 차례로 실행하면 글과 같은 결과가 나온다(MySQL 8.4).

실습 준비 SQL
1
2
3

DROP DATABASE IF EXISTS cafe_practice;
CREATE DATABASE cafe_practice DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
USE cafe_practice;

테이블은 본문에서 cafedb를 복사해 만든다.

제약조건 없이 복사하기

CREATE TABLE ... AS SELECT는 조회 결과로 새 테이블을 만든다. 열 타입, NOT NULL, 기본값과 데이터는 복사되지만 기본키·외래키·유니크·CHECK는 복사되지 않는다. 제약조건을 ALTER로 하나씩 붙여 보기에 알맞다.

1
2

CREATE TABLE member AS
SELECT member_id, name, grade, city, phone FROM cafedb.member;

DESCRIBE member;로 보면 grade의 기본값 BASIC과 NOT NULL은 복사됐지만, 원본에서 기본키였던 member_id의 Key 칸은 비어 있다.

ADD: 열 추가

1
2
3

ALTER TABLE member ADD PRIMARY KEY (member_id);                 -- 기본키부터 붙인다
ALTER TABLE member ADD point INT NOT NULL DEFAULT 0 AFTER grade; -- grade 바로 뒤에
ALTER TABLE member ADD (birth DATE, memo VARCHAR(50));           -- 맨 뒤에 두 열

이미 있던 행에는 새 열의 기본값이 들어간다(point는 0). 기본값이 없는 birth, memo는 NULL이 된다.

MODIFY: 타입과 제약조건 바꾸기

기존 데이터와 맞지 않는 변경은 거부된다.

1
2
3

ALTER TABLE member MODIFY name VARCHAR(20) NOT NULL;   -- 10자 → 20자로 늘림
ALTER TABLE member MODIFY city VARCHAR(10) NOT NULL;   -- 도시가 NULL인 회원이 있다
-- ERROR 1138 (22004): Invalid use of NULL value

MODIFY는 열 정의를 통째로 바꾼다. 제약조건을 빼고 쓰면 원래 있던 NOT NULL과 DEFAULT가 사라진다.

1
2

ALTER TABLE member MODIFY grade VARCHAR(20);
SHOW COLUMNS FROM member LIKE 'grade';
FieldTypeNullKeyDefaultExtra
gradevarchar(20)YES NULL 

유지하려면 다시 모두 적는다.

1

ALTER TABLE member MODIFY grade VARCHAR(20) NOT NULL DEFAULT 'BASIC';

주의할 점: MODIFY와 CHANGE는 “바꿀 부분만” 쓰는 명령이 아니다. 남겨 둘 NOT NULL, DEFAULT까지 전부 다시 적어야 한다.

CHANGE, RENAME COLUMN, DROP

1
2
3

ALTER TABLE member CHANGE phone mobile VARCHAR(20);        -- 이름 + 타입을 함께
ALTER TABLE member RENAME COLUMN city TO region;           -- 이름만
ALTER TABLE member DROP COLUMN birth, DROP COLUMN memo;    -- 한 문장에 여러 개

CHANGE는 이름을 바꾸지 않을 때도 옛 이름과 새 이름을 둘 다 적는다(CHANGE grade grade VARCHAR(20)). 이름만 바꿀 때는 정의를 다시 쓰지 않는 RENAME COLUMN이 안전하다. MODIFY·CHANGE는 MySQL 문법이다. Oracle은 MODIFY (열 타입)과 RENAME COLUMN을 쓰고, 표준 SQL은 ALTER COLUMN을 쓴다.

제약조건을 추가할 때도 이미 있는 데이터를 검사한다. 등급에 'VIP' 회원이 있으므로, VIP를 빠뜨린 CHECK는 거부된다.

1

ALTER TABLE member ADD CONSTRAINT ck_member_point CHECK (point >= 0);
ALTER TABLE member ADD CONSTRAINT ck_member_grade CHECK (grade IN ('BASIC', 'GOLD'));
-- ERROR 3819 (HY000): Check constraint 'ck_member_grade' is violated.
ALTER TABLE member ADD CONSTRAINT ck_member_grade CHECK (grade IN ('BASIC', 'GOLD', 'VIP'));
ALTER TABLE member ADD CONSTRAINT uq_member_mobile UNIQUE (mobile);

기본값을 없애면 그 열을 생략한 INSERT가 실패한다(point는 NOT NULL이다). 다시 기본값을 주면 들어간다.

1

ALTER TABLE member ALTER point DROP DEFAULT;
INSERT INTO member (member_id, name) VALUES (109, '숙향');
-- ERROR 1364 (HY000): Field 'point' doesn't have a default value

ALTER TABLE member ALTER point SET DEFAULT 100;
INSERT INTO member (member_id, name) VALUES (109, '숙향');   -- 성공, point = 100

외래키 추가와 제약조건 조회

주문 테이블도 복사해 기본키와 외래키를 붙이고, 걸린 제약조건을 information_schema.table_constraints에서 조회한다.

1
2
3
4

CREATE TABLE orders AS SELECT order_id, member_id, store FROM cafedb.orders;
ALTER TABLE orders ADD PRIMARY KEY (order_id);
ALTER TABLE orders ADD CONSTRAINT fk_orders_member
    FOREIGN KEY (member_id) REFERENCES member(member_id);

information_schema는 DB 구조 정보를 담은 읽기 전용 DB다. 자동으로 붙은 이름(member_chk_1 등)도 여기서 찾는다. NOT NULL과 DEFAULT는 열 정의의 일부라 나오지 않는다.

이름을 알면 DROP CONSTRAINT로 지운다. 하지만 다른 테이블이 참조하는 기본키는 바로 지울 수 없다.

1
2
3

ALTER TABLE member DROP CONSTRAINT ck_member_grade;
ALTER TABLE member DROP PRIMARY KEY;
-- ERROR 1553 (HY000): Cannot drop index 'PRIMARY': needed in a foreign key constraint

orders.member_id가 member.member_id를 참조하고 있어서다. 자식의 외래키를 먼저 지워야 부모의 기본키를 지울 수 있다(아래 DROP에서 해 본다).

테이블 이름 바꾸기

1
2

RENAME TABLE orders TO orders_2026;
ALTER TABLE member RENAME TO customer;    -- 같은 결과

외래키는 바뀐 테이블 이름을 그대로 따라간다.

DROP: 테이블과 DB 없애기

DROP TABLE은 데이터와 구조를 모두 없앤다. DROP DATABASE는 DB 안의 테이블까지 전부 없앤다. 외래키로 참조되는 부모 테이블은 지울 수 없다.

1
2

DROP TABLE customer;
-- ERROR 3730 (HY000): Cannot drop table 'customer' referenced by a foreign key constraint 'fk_orders_member' on table 'orders_2026'.

없는 테이블을 지우면 ERROR 1051이지만, DROP TABLE IF EXISTS로 쓰면 경고만 남기고 넘어간다.

표준 SQL의 DROP TABLE 테이블 CASCADE는 참조하는 제약조건·뷰까지 함께 지우고, RESTRICT는 참조가 있으면 거부한다. MySQL은 두 키워드를 받아들이기만 하고 아무 일도 하지 않아서 DROP TABLE customer CASCADE;도 같은 ERROR 3730이 난다. 자식의 외래키를 먼저 지우거나, 자식과 부모를 한 문장에 함께 적는다.

1
2
3

ALTER TABLE orders_2026 DROP FOREIGN KEY fk_orders_member;
ALTER TABLE customer DROP PRIMARY KEY;       -- 이제 된다
DROP TABLE orders_2026, customer;            -- 자식과 부모를 함께 지운다

주의할 점: 시험에서 “참조하는 테이블이 있어도 함께 삭제되게” 하라고 하면 표준 문법인 DROP TABLE 테이블명 CASCADE;를 쓴다(Oracle은 CASCADE CONSTRAINTS). 외래키의 ON DELETE CASCADE(행 단위 연쇄 삭제)와는 다른 개념이다.

DROP, TRUNCATE, DELETE 비교

TRUNCATE TABLE은 테이블 구조는 남기고 모든 행을 한 번에 비운다. 로그 테이블로 DELETE와 비교한다.

1
2
3
4
5
6
7
8

10
11
12
13

CREATE TABLE visit_log (
    log_id INT AUTO_INCREMENT PRIMARY KEY,
    store  VARCHAR(10) NOT NULL
);
INSERT INTO visit_log (store) VALUES ('본점'), ('강변점'), ('공원점');

DELETE FROM visit_log;                   -- 모든 행 삭제
INSERT INTO visit_log (store) VALUES ('본점');
SELECT log_id FROM visit_log;            -- 4

TRUNCATE TABLE visit_log;                -- 테이블 비우기
INSERT INTO visit_log (store) VALUES ('본점');
SELECT log_id FROM visit_log;            -- 1

DELETE는 행만 지우므로 AUTO_INCREMENT 번호가 이어지고, TRUNCATE는 테이블을 새로 만든 것처럼 1부터 다시 시작한다.

되돌릴 수 있는지도 다르다. 3행으로 만든 뒤 트랜잭션(21편) 안에서 지우고 ROLLBACK해 본다.

1

INSERT INTO visit_log (store) VALUES ('강변점'), ('공원점');

START TRANSACTION;
DELETE FROM visit_log;
ROLLBACK;
SELECT COUNT(*) AS 남은_행 FROM visit_log;      -- 3

START TRANSACTION;
TRUNCATE TABLE visit_log;
ROLLBACK;
SELECT COUNT(*) AS 남은_행 FROM visit_log;      -- 0

DELETE는 되돌아왔지만 TRUNCATE는 되돌아오지 않았다. MySQL에서 DDL은 실행 전후에 자동으로 커밋(암묵적 커밋)되기 때문이다.

인덱스

인덱스(index)는 책 뒤의 찾아보기처럼, 열 값을 정렬해 두고 그 값이 있는 행의 위치를 적어 둔 별도 구조다. 인덱스가 없으면 WHERE city = '부산'을 처리할 때 모든 행을 읽어야 하지만(전체 스캔), 있으면 정렬된 인덱스에서 해당 값만 바로 찾아간다.

인덱스는 CREATE [UNIQUE] INDEX 이름 ON 테이블 (열, ...)로 만든다. 회원 테이블을 인덱스 없이 다시 복사하고, 실행 계획(EXPLAIN)으로 인덱스를 쓰는지 본다.

1
2

CREATE TABLE member AS SELECT * FROM cafedb.member;   -- 인덱스 없이 복사
EXPLAIN SELECT * FROM member WHERE city = '부산';
typekeyrows
ALLNULL8

(일부 열)

type이 ALL이면 전체 스캔, rows는 읽을 것으로 예상한 행 수다. 단일 열, 복합(여러 열), 유니크 인덱스를 만들고 다시 본다.

1
2
3
4

CREATE INDEX idx_member_city ON member (city);
CREATE INDEX idx_member_grade_joined ON member (grade, joined_on);
CREATE UNIQUE INDEX uq_member_phone ON member (phone);
EXPLAIN SELECT * FROM member WHERE city = '부산';

이제 부산 회원 2행만 읽는다. 복합 인덱스 (grade, joined_on)은 앞 열부터 쓰인다. grade 조건에는 쓰이지만 joined_on만 조건으로 쓰면 쓰이지 않아 전체 스캔이 된다. 유니크 인덱스는 UNIQUE 제약조건과 같아서 중복 값을 막는다.

기본키를 추가하자 PRIMARY 인덱스가 생겼다. MySQL은 기본키와 UNIQUE 제약조건에 인덱스를 자동으로 만들고, 외래키 열에도 인덱스가 없으면 만든다. Seq_in_index는 복합 인덱스 안의 열 순서다. 인덱스는 DROP INDEX로 지운다(Oracle은 ON 테이블 없이 쓴다).

1

인덱스를 만들거나 지워도 SQL과 조회 결과는 그대로이고 속도만 달라진다. 2편에서 본 물리적 데이터 독립성의 예다.

복습 문제

  1. CREATE TABLE menu AS SELECT menu_id, name, price FROM cafedb.menu;로 만든 menu가 있다. 다음을 차례로 하는 ALTER TABLE 문을 쓰시오.
    • menu_id를 기본키로 지정한다.
    • name 바로 뒤에 category VARCHAR(10) 열을 추가한다. 비어 있을 수 없고 기본값은 '음료'다.
    • price 열의 이름을 unit_price로 바꾸되, INT NOT NULL은 유지한다.
    • unit_price가 1000 이상이어야 한다는 CHECK 제약조건을 ck_menu_price라는 이름으로 추가한다.
  2. 다음 요구에 알맞은 명령을 DELETE, TRUNCATE, DROP 중에서 고르고, 각 명령이 DDL인지 DML인지 쓰시오.
    • (가) 2025년 방문 기록만 지운다.
    • (나) 방문 기록 테이블은 남기고 전부 비운 뒤 번호를 1부터 다시 매긴다.
    • (다) 더 쓰지 않는 임시 테이블을 구조까지 없앤다.
  3. cafedb.orders를 복사하고 order_id를 기본키로 지정한 orders에서 SELECT * FROM orders WHERE store = '본점' ORDER BY ordered_at;을 자주 실행한다.
    • 이 조회에 알맞은 인덱스 idx_orders_store_time을 만드는 SQL을 쓰시오.
    • 이 인덱스가 WHERE ordered_at >= '2026-08-10'만 쓰는 조회에도 쓰이는지 쓰시오.
    • order_id에 인덱스를 따로 만들어야 하는지 쓰시오.
정답과 해설

1. CHANGE는 정의를 통째로 다시 적어야 하므로 INT NOT NULL을 빠뜨리면 안 된다.

1
2
3
4

ALTER TABLE menu ADD PRIMARY KEY (menu_id);
ALTER TABLE menu ADD category VARCHAR(10) NOT NULL DEFAULT '음료' AFTER name;
ALTER TABLE menu CHANGE price unit_price INT NOT NULL;
ALTER TABLE menu ADD CONSTRAINT ck_menu_price CHECK (unit_price >= 1000);

CHANGE 대신 RENAME COLUMN price TO unit_price를 써도 된다. 이 경우 정의는 그대로 유지된다.

2. (가) DELETE(DML) — 조건(WHERE)이 필요하므로 DELETE만 가능하다. (나) TRUNCATE(DDL) — 구조는 남기고 비우며 AUTO_INCREMENT를 되돌린다. (다) DROP(DDL).

3. 조건 열 store를 앞에, 정렬 열 ordered_at을 뒤에 둔 복합 인덱스를 만든다.

1

CREATE INDEX idx_orders_store_time ON orders (store, ordered_at);

이 조회는 인덱스로 본점 5행만 읽고, 인덱스 안에서 이미 ordered_at 순이라 따로 정렬하지 않는다. ordered_at만 쓰는 조회에는 쓰이지 않는다(앞 열부터 쓰인다). order_id는 기본키라 인덱스가 자동으로 있다.
