[Python] 14. 모듈과 패키지, 코드를 파일 단위로 나누어 재사용하기

지금까지는 코드를 한 파일에 다 몰아넣고 실습했는데, 오늘은 그걸 여러 파일로 나누는 방법인 모듈과 패키지를 정리했다.

모듈이란

모듈은 함수, 변수, 클래스들을 모아놓은 하나의 .py 파일이고, 패키지는 여러 모듈을 모아놓은 디렉터리다. 모듈 종류로는 표준 모듈(파이썬에 기본 포함된 random, os, datetime 등), 사용자 정의 모듈(내가 직접 만든 것), 써드파티 모듈(다른 사람이 만든 것)이 있다.

모듈을 쓰는 이유가 인상 깊었다. 코드 재사용뿐 아니라, 모듈마다 독립된 네임스페이스(이름공간)를 갖기 때문에 서로 다른 파일에서 같은 이름의 함수나 변수를 써도 충돌하지 않는다는 점이었다.

# money.py
def discount(price, percent):
    return price * (100 - percent) // 100

def split_bill(total, people):
    if people > 0:
        return total // people
    else:
        return "인원은 1명 이상이어야 합니다"

def won(amount):
    return f'{amount:,}원'

if __name__ == '__main__':
    print(won(split_bill(30000, 4)))   # 직접 실행할 때만 도는 테스트 코드

# 다른 파일에서 사용
import money

print(money.discount(20000, 15))              # 모듈명.함수명() 형태로 호출 -> 17000
print(money.won(money.split_bill(30000, 4)))   # 7,500원

여기서 if __name__ == '__main__':이 왜 필요한지가 오늘 제일 중요한 개념이었다. __name__은 현재 실행되는 파일이면 '__main__', 다른 파일에서 import된 상태면 그 모듈의 이름을 값으로 갖는 내장 변수다.

1
2

print('__name__ =>', __name__)                    # 직접 실행하면 '__main__'
print('money.__name__ =>', money.__name__)   # import된 쪽은 'money'

즉 money.py를 직접 실행할 땐 if __name__ == '__main__': 블록의 테스트 코드가 돌아가지만, 다른 파일에서 import money로 가져다 쓸 땐 이 블록이 실행되지 않는다. 모듈 자체의 테스트 코드와, 남에게 빌려줄 함수 정의를 한 파일에 안전하게 같이 둘 수 있는 방법이라는 걸 이해했다.

from math import *

from 모듈 import *은 편리하지만, 가져온 함수/변수 이름이 내 코드의 기존 이름과 겹치면 조용히 덮어써질 수 있어서 위험하다는 주의사항도 확인했다. 실제로 실습 중에 from member import *로 member.py의 전역변수 nickname을 가져왔는데, 알고 보니 그건 import하는 순간의 값('')과 같은 객체를 가리키는 이름이 내 파일에 따로 하나 생긴 것이었다. 그래서 나중에 member.py 안의 함수가 nickname에 새 값을 재할당해도, 내 쪽 이름은 여전히 예전 값을 가리키고 있어서 반영되지 않는 걸 직접 겪었다.

이런 혼란을 피하려면 from member import set_nickname, show_nickname처럼 필요한 것만 콕 집어 가져오거나, import member 후 member.nickname처럼 모듈명을 붙여서 접근하는 게 안전하다는 결론을 내렸다.

# main.py
from mytools.loader import read_dataset
from mytools.scaler import normalize
from mytools.predictor import predict_one
from mytools.evaluate import mean_abs_error

X, y = read_dataset()                   # 1. 데이터 로딩
norm_X = normalize(X)                   # 2. 전처리
preds = [predict_one(x) for x in norm_X]   # 3. 예측 (정규화된 값을 넣어야 전처리한 의미가 있다)
score = mean_abs_error(y, preds)        # 4. 평가
print('MAE:', score)

데이터 로딩, 전처리, 예측, 평가라는 하나의 파이프라인을 각 단계별 모듈로 쪼개놓으니, main.py만 봐도 전체 흐름이 한눈에 읽힌다는 게 신기했다. 지금까지 배운 함수/클래스들이 결국 이렇게 역할별로 파일을 나누기 위한 재료였다는 걸 체감했다.

모듈 검색 경로

import를 하면 파이썬은 순서대로 sys.modules(이미 로드된 모듈들), 내장 모듈, sys.path(라이브러리 설치 경로들의 리스트)를 뒤져서 모듈을 찾는다는 것도 짚었다. import sys; print(sys.path)로 실제 검색 경로 목록을 직접 확인해볼 수 있었다.

if __name__ == '__main__':은 이 파일이 직접 실행될 때만 동작하게 만드는 관용구라는 것, from 모듈 import *은 편하지만 이름 충돌 위험이 있어서 필요한 것만 콕 집어 import하는 게 안전하다는 것, 패키지의 __init__.py는 3.3 이후로 필수는 아니라는 것까지가 오늘 정리한 내용이다.

  2. 문자열 처리 함수를 모은 text_tools.py 모듈을 만들어보시오. 공백을 뺀 글자 수를 세는 count_chars(s), 단어 수를 세는 count_words(s), 문장을 거꾸로 뒤집는 reverse_text(s)를 넣고, 파일 맨 아래 if __name__ == '__main__': 블록에 세 함수를 확인하는 테스트 코드를 둔다. 그다음 menu.py에서 문장 하나와 메뉴 번호(1~3)를 입력받아 번호에 맞는 함수를 호출해 결과를 출력하게 만들고, menu.py를 실행했을 때 text_tools.py의 테스트 코드는 출력되지 않는지 확인해보시오.

  3. 이번 시리즈에서 다룬 리스트, 딕셔너리 관련 함수들(예: 평균 구하기, 최댓값 찾기)을 모아 my_utils.py라는 나만의 모듈로 만들고, 다른 파일에서 import해서 사용해보시오.

  4. from math import *와 import math의 차이를, 실제로 두 방식으로 각각 pow() 함수를 호출하는 코드를 작성하며 비교해보시오.
