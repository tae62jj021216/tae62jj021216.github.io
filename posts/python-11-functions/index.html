함수를 왜 쓰는가

함수는 특정 작업을 수행하는 코드의 집합이다. 함수는 외부에 별도로 존재하고, 메서드('hello'.upper()처럼 객체가 갖는 함수)는 클래스 안에 정의되어 있다는 차이가 있다. 쓰는 이유는 코드 재사용, 중복 제거, 작업을 기능별로 분해(모듈화)하기 위해서다. 재사용할 수 있어 경제적이고, 가독성이 좋아지고, 로직이 바뀌면 그 함수만 고치면 되니 유지보수도 쉬워진다.

def show_list(my_list):

my_list = [1, 2, 3, 4]

def show_list2(my_list):
    new_list = my_list.copy()   # 얕은 복사로 새 리스트를 만들어 독립시킴
    new_list[-1] = 100
    print(new_list)

show_list2(my_list)
print(my_list)   # 영향 없음

숫자나 문자열을 함수에 넘기면 함수 안에서 값을 바꿔도 원본엔 영향이 없는데, 리스트나 딕셔너리처럼 mutable한 값을 넘기면 함수 안에서의 변경이 원본에도 그대로 반영된다. 원본을 지키고 싶으면 copy()로 복사한 값을 써야 한다. 여기서 copy()는 얕은 복사지만, 요소가 숫자나 문자열처럼 immutable한 값이라 이걸로 충분하다(리스트 안에 리스트가 들어 있다면 copy.deepcopy()가 필요). 예전 리스트 글에서 배운 얕은 복사와 깊은 복사 개념이 함수 인자에도 똑같이 적용된다는 걸로 이해했다.

nonlocal은 중첩 함수(함수 안의 함수)에서 바깥 함수의 변수를 수정하고 싶을 때 쓰는 키워드라는 것도 짚고 넘어갔다. global은 전역을, nonlocal은 한 단계 바깥의 지역을 대상으로 한다는 차이다.

재귀함수(recursive function)

자기 자신을 호출하는 함수다. 반드시 멈추는 조건(base case)이 있어야 무한 호출(스택오버플로우)을 피할 수 있다.

def add_recur(n):
    if n == 1:
        return 1
    return n + add_recur(n - 1)

print(add_recur(10))   # 55

def fibo(n):
    if n <= 1:
        return n
    return fibo(n-2) + fibo(n-1)

반복문으로도 똑같은 결과를 만들 수 있는데, 재귀는 문제를 자기 자신의 더 작은 버전으로 쪼갠다는 관점이 신기했다. 다만 위의 fibo()는 fibo(n-2)와 fibo(n-1)이 같은 값을 계속 다시 계산하느라 호출 횟수가 n이 커질수록 기하급수적으로 늘어나서, fibo(35) 한 번에 함수 호출이 3천만 번 가까이 일어난다. 한 번에 쌓이는 호출 깊이는 n 정도라 메모리보다는 시간이 문제인 셈이다(add_recur(5000)처럼 호출이 기본 한도인 1000단계 안팎을 넘게 깊어지면 RecursionError가 나는 건 또 별개의 문제). 재귀가 항상 최선은 아니라는 것도 함께 알아뒀다.
