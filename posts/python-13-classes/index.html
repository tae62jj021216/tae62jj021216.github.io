오늘은 지금까지 배운 것 중 가장 개념적으로 무거웠던 클래스(객체지향)를 정리했다. 분량이 많지만, 하나씩 따라가다 보니 결국 변수와 함수를 하나로 묶는 것이라는 큰 그림 아래 다 연결되는 느낌이었다.

객체지향이 뭔가

객체(object)는 변수(속성)와 함수(기능)를 함께 묶은 단위, 실제 존재하는 사물이나 개념이다. 변수는 속성/필드(field)로, 객체가 가진 값을 뜻하고, 함수는 메서드(method)로, 객체가 하는 동작을 뜻한다. 클래스(class)는 객체를 만들기 위한 설계도이고, 인스턴스(instance)는 클래스로 실제 생성된 객체를 가리킨다(클래스와의 관계를 강조할 때 이 용어를 씀).

int, list, dict도 결국 파이썬이 미리 만들어둔 클래스라는 걸 이 시점에 깨달았다. [1,2,3]을 만드는 것도 사실 list라는 클래스의 인스턴스를 만드는 것이었다.

class Car:
    def __init__(self, modelN, color='white'):
        self.modelN = modelN
        self.__color = color   # 비공개 필드

    def getColor(self):
        return self.__color     # 클래스 내부에서는 접근 가능

    def setColor(self, color):
        self.__color = color

car = Car('111')
# print(car.__color)  # AttributeError! 외부에서 직접 접근 불가
print(car.getColor())  # getter를 통해서만 접근

앞에서 다룬 getter/setter가 왜 필요한지 여기서 이해가 됐다. 비공개 필드로 막아두고, 공개된 getter/setter로만 값을 주고받게 하면 값이 함부로 바뀌는 걸 막을 수 있다.

class Line:
    def __init__(self, length=0):
        self.length = length

    def __repr__(self):          # print(인스턴스)일 때 보여줄 내용
        return f'선의 길이: {self.length}'

    def __add__(self, other):    # 인스턴스끼리 + 연산
        return self.length + other.length

    def __eq__(self, other):     # 인스턴스끼리 == 비교
        return self.length == other.length

    def __gt__(self, other):     # 인스턴스끼리 > 비교
        return self.length > other.length

line1 = Line(100)
line2 = Line(200)

print(line1)                 # __repr__ 호출 -> "선의 길이: 100"
print(line1 + line2)          # __add__ 호출 -> 300

if line1 < line2:
    print('line2가 더 길어요')

숫자끼리는 원래 +, ==, >가 되는 게 당연했는데, 내가 만든 클래스도 이 매직 메서드들을 정의해주면 똑같이 연산자를 쓸 수 있게 된다는 게 신기했다. __init__도 사실 이 매직 메서드들 중 하나(생성 시 호출되는 것)였다는 것도 다시 확인했다.

클래스 변수 vs 인스턴스 변수

class Car2:
    count = 0   # 클래스 변수, 모든 인스턴스가 공유

    def __init__(self, color, speed):
        self.color = color   # 인스턴스 변수
        self.speed = speed

car2 = Car2('red', 10)

class Car:
    count = 0

    def __init__(self, color='white', speed=0):
        self.color = color
        self.speed = speed
        Car.count += 1

    @classmethod                    # 클래스 자체(cls)가 첫 인자로 넘어옴
    def print_count(cls):
        print(f'현재 {cls.count}대 생산되었습니다.')

    @classmethod
    def create(cls):                 # 팩토리 메서드 : 인스턴스 생성을 대신 해줌
        return cls()

    @staticmethod                    # self/cls 없이, 클래스와 관련은 있지만 독립적인 기능
    def is_valid_speed(speed: int) -> bool:
        return 0 <= speed <= 300

    def drive(self):                 # 일반 인스턴스 메서드 (아래 상속 예제에서 재정의함)
        print(f'{self.speed}km/h로 주행중입니다.')

Car.print_count()          # 인스턴스 없이 클래스에서 바로 호출
car3 = Car.create()        # 팩토리 메서드로 생성
print(Car.is_valid_speed(100))   # True

셋의 차이를 이렇게 정리했다. 인스턴스 메서드는 개별 인스턴스(self)를 다루고, 클래스 메서드(@classmethod)는 클래스 자체(cls)나 클래스 변수를 다루고, 정적 메서드(@staticmethod)는 클래스와 관련은 있지만 인스턴스나 클래스 어느 쪽도 필요 없는 순수 유틸리티 함수에 쓴다.

상속(inheritance)

class Truck(Car):   # 바로 위의 Car(color, speed)를 상속
    def __init__(self, modelNum, color='white', speed=0, load=1):
        super().__init__(color, speed)   # 부모의 생성자 호출 (color, speed 초기화는 Car에게 맡김)
        self.modelNum = modelNum         # 트럭만의 필드
        self.load = load

    def drive(self):    # 부모의 메서드를 재정의 (오버라이딩)
        print(f'{self.load}톤의 짐을 싣고 주행중입니다.')

truck = Truck(modelNum='t211', load=0.5)
truck.drive()

super().__init__(...)으로 부모 클래스의 생성자를 그대로 호출해서 공통 초기화를 재사용하고, 자식 클래스만의 필드(modelNum, load)를 추가하는 패턴이 핵심이었다. 부모에 있던 메서드를 자식에서 다시 정의하는 걸 오버라이딩(overriding)이라고 부른다는 것도 짚었다.

class Animal:
    def __init__(self, name):
        self.name = name

    def talk(self):
        raise NotImplementedError('자식 클래스가 구현해야 함')   # 추상 메서드 흉내

class Dog(Animal):
    def talk(self):
        return '멍멍'

class Cat(Animal):
    def talk(self):
        return '야옹'

for animal in [Dog('바둑이'), Cat('야옹이')]:
    print(f'{animal.name}: {animal.talk()}')   # 같은 talk() 호출인데 다르게 동작

raise NotImplementedError(...)로 이 메서드는 자식 클래스가 반드시 재정의해야 한다는 걸 강제하는 패턴도 새로 봤다. 부모 클래스는 이름과 형태(설계)만 잡아두고, 실제 동작은 자식이 책임지는 구조다. 그리고 사실 10+30과 'Hi'+' Hello'처럼 같은 + 연산자가 자료형에 따라 다르게 동작하는 것도 다형성의 한 예라는 설명을 보고, 지금까지 자연스럽게 써온 것들이 다 이 개념 위에 있었다는 걸 알게 됐다.

클래스 변수는 클래스이름.변수로 접근/수정한다는 것, @classmethod는 cls(클래스 자체)를 받고 @staticmethod는 self/cls 둘 다 없다는 것, super().__init__()을 빼먹으면 부모의 초기화 로직이 실행되지 않는다는 것까지가 오늘 헷갈렸다가 정리한 부분들이다.
