[DB] 06. 정규화 ① 이상 현상과 함수 종속

테이블을 잘못 묶으면 같은 데이터가 여러 번 저장되고, 넣고 고치고 지울 때 문제가 생긴다. 이 글에서는 모든 것을 한 테이블에 몰아넣은 주문표로 이상 현상을 일으켜 보고, 테이블을 나누는 분해와 그 기준인 함수 종속을 정리한다. 다음 편에서 같은 표를 정규형 단계별로 분해한다.

예제는 00편의 cafedb를 쓴다. 실습은 아래 “실습 준비 SQL”로 만드는 연습 DB cafe_practice에서 한다(MySQL 8.4). SQL 문법은 8편부터 다룬다. 여기서는 결과만 보면 된다.

실습 준비 SQL

cafedb의 회원 주문(비회원 주문 제외)을 조인(15편)해 주문표 하나로 만든다.

DROP DATABASE IF EXISTS cafe_practice;
CREATE DATABASE cafe_practice;
USE cafe_practice;

CREATE TABLE order_sheet (PRIMARY KEY (order_id, menu_id)) AS
SELECT o.order_id, o.store, mb.member_id, mb.name AS member_name, mb.grade,
       m.menu_id, m.name AS menu_name, m.price, oi.qty
FROM cafedb.orders o
JOIN cafedb.member mb     ON mb.member_id = o.member_id
JOIN cafedb.order_item oi ON oi.order_id = o.order_id
JOIN cafedb.menu m        ON m.menu_id = oi.menu_id;

한 테이블에 다 넣은 주문표

주문, 회원, 메뉴 정보와 수량을 한 줄에 모두 적은 order_sheet(16행)다. 기본키는 (order_id, menu_id)다.

이상 현상 세 가지

이상 현상(anomaly)은 중복 때문에 삽입·갱신·삭제가 뜻대로 되지 않는 현상이다.

삽입 이상: 넣고 싶은 것만 넣을 수 없다

아직 아무도 주문하지 않은 새 메뉴 ‘흑임자라떼’의 정보만 넣으려 하면, 기본키의 일부인 order_id가 없어서 거부된다.

1
2

INSERT INTO order_sheet (order_id, menu_id, menu_name, price) VALUES (NULL, 12, '흑임자라떼', 5800);
-- ERROR 1048 (23000): Column 'order_id' cannot be null

기본키에는 NULL이 올 수 없으므로(개체 무결성, 3편) 메뉴를 등록하려면 가짜 주문이라도 만들어야 한다. 주문 없는 회원(팥쥐)도 넣을 수 없다. 원하지 않는 데이터까지 함께 넣어야 하는 것이 삽입 이상이다.

갱신 이상: 일부만 고치면 모순이 생긴다

홍길동의 등급이 GOLD로 바뀌었는데, 최근 주문(11번)의 행만 고쳤다고 하자.

1
2

UPDATE order_sheet SET grade = 'GOLD' WHERE order_id = 11;
-- Query OK, 2 rows affected

SELECT DISTINCT member_id, grade FROM order_sheet WHERE member_id = 101;

한 회원의 등급이 두 개가 됐고, 어느 쪽이 맞는지 테이블만 보고는 알 수 없다. 올바르게 고치려면 홍길동이 나오는 5행을 빠짐없이 고쳐야 한다. 다음 예제를 위해 되돌려 둔다.

1

UPDATE order_sheet SET grade = 'VIP' WHERE order_id = 11;

삭제 이상: 지우고 싶지 않은 것까지 사라진다

콩쥐가 주문 10번을 취소해 그 주문을 지운다. 이 주문이 콩쥐의 유일한 주문이고, 딸기 에이드(메뉴 7)가 담긴 유일한 회원 주문이기도 하다.

1
2
3
4

DELETE FROM order_sheet WHERE order_id = 10;
-- Query OK, 2 rows affected

SELECT COUNT(*) FROM order_sheet WHERE member_id = 107 OR menu_id = 7;   -- 0

주문만 지웠는데 콩쥐의 회원 정보와 딸기 에이드의 가격까지 사라졌다.

주의할 점: 이상 현상은 삽입·갱신·삭제 세 가지다. 조회는 데이터를 바꾸지 않으므로 “조회 이상”은 없다.

분해: 테이블을 나눠 중복을 없앤다

이상 현상은 서로 다른 사실(주문, 회원, 메뉴)을 한 테이블에 섞어서 생기므로, 열을 나눠 더 작은 테이블 여러 개로 바꾸는 분해(decomposition)로 해결한다. 단, 나눈 테이블을 다시 조인했을 때 원래 테이블이 정확히 복원돼야 한다. 이런 분해를 무손실 분해(lossless-join decomposition)라고 한다. 삭제했던 주문 10번을 다시 넣어 16행으로 되돌린 뒤, 같은 표를 두 가지 방법으로 나눠 본다.

-- 공통: 주문 정보
CREATE TABLE r_order AS
  SELECT DISTINCT order_id, store, member_id, member_name, grade FROM order_sheet;

-- 분해 A: 주문 번호로 연결되는 주문 줄
CREATE TABLE r_line AS
  SELECT DISTINCT order_id, menu_id, menu_name, price, qty FROM order_sheet;

-- 분해 B: 회원 번호로 연결되는 구매 내역
CREATE TABLE r_buy AS
  SELECT DISTINCT member_id, menu_id, menu_name, price, qty FROM order_sheet;

r_order는 10행, r_line과 r_buy는 16행이다. 두 분해는 연결 고리(order_id, member_id)만 다르다.

무손실 분해: 조인하면 원래대로

SELECT COUNT(*) AS joined_rows FROM r_order JOIN r_line USING (order_id);   -- 16

SELECT order_id, store, member_id, member_name, grade, menu_id, menu_name, price, qty
FROM r_order JOIN r_line USING (order_id)
EXCEPT
SELECT * FROM order_sheet;
-- 결과 없음 (Empty set)

행 수가 같고 조인 결과에만 있는 행도 없으므로 원래 테이블이 그대로 복원됐다(조인은 15편, 차집합 EXCEPT는 14편).

손실 분해: 조인하면 가짜 행이 생긴다

분해 B를 같은 방법으로 조인하면 16행이 29행으로 늘어난다. 주문 1번만 보면 이유가 드러난다.

SELECT o.order_id, o.member_id, b.menu_id, b.menu_name, b.qty

WHERE o.order_id = 1

주문 1번은 원래 두 줄(아메리카노 2잔, 치즈케이크 1개)인데, 홍길동이 다른 주문(5번, 11번)에서 산 메뉴까지 붙어 나왔다. 이렇게 원래 없던 행을 가짜 튜플(spurious tuple)이라고 한다.

주의할 점: 분해한 테이블을 다시 조인한 결과는 항상 원래 행을 모두 포함하고, 손실 분해이면 가짜 행이 더해진다. 행이 사라지는 것이 아니라 어느 행이 진짜인지 구별할 수 없게 되므로 “정보를 잃었다”고 한다.

차이는 공통 열에 있다. 분해 A의 order_id는 r_order의 키라서 각 주문 줄이 정확히 한 주문에만 붙는다. 분해 B의 member_id는 어느 쪽의 키도 아니라서, 회원 한 명의 주문 여러 개와 구매 내역 여러 개가 모든 조합으로 붙는다.

정리하면, 테이블 R을 R1과 R2로 나눌 때 공통 속성이 R1이나 R2 중 적어도 한쪽의 (슈퍼)키이면 무손실 분해다. 공통 속성이 무엇을 결정하는지 따지는 도구가 함수 종속이다. 분해할 때는 무손실 조인과 함께 종속성 보존(원래의 함수 종속을 분해한 테이블 각각에서 검사할 수 있어야 한다)도 따진다. 7편의 BCNF에서 이 성질을 포기해야 하는 경우를 본다.

함수 종속

정의

속성 X의 값이 같으면 속성 Y의 값도 항상 같을 때, Y는 X에 함수적으로 종속된다고 하고 X → Y로 쓴다. X를 결정자(determinant), Y를 종속자(dependent)라고 하며, 둘 다 속성 여러 개의 집합일 수 있다.

메뉴 번호가 같으면 가격도 같으므로 menu_id → price지만, 메뉴 번호만으로는 수량이 정해지지 않는다. X 값 하나에 Y 값이 여러 개인 반례를 찾으면 확인할 수 있다.

1
2

SELECT menu_id, COUNT(DISTINCT qty) AS qtys      -- menu_id → qty 의 반례 찾기
FROM order_sheet GROUP BY menu_id HAVING COUNT(DISTINCT qty) > 1;

메뉴 1, 2, 5, 8이 나온다(GROUP BY·HAVING은 13편). 같은 쿼리를 price로 바꾸면 결과가 없다. 수량은 주문 번호와 메뉴 번호가 둘 다 있어야 정해진다. 즉 (order_id, menu_id) → qty다.

주의할 점: 함수 종속은 지금 들어 있는 데이터가 아니라 업무 규칙으로 정한다. 지금은 동명이인이 없어 member_name → member_id를 어기는 행이 없지만, 동명이인이 가입하면 바로 깨진다. 데이터로는 반례(성립하지 않음)만 확인할 수 있고, 성립한다는 증명은 할 수 없다.

order_sheet의 함수 종속

업무 규칙에서 나오는 종속은 네 가지다.

  • (order_id, menu_id) → qty: 어떤 주문에 담긴 어떤 메뉴의 수량
  • order_id → store, member_id: 주문 하나는 지점 하나, 회원 한 명
  • member_id → member_name, grade
  • menu_id → menu_name, price

키가 아닌 결정자(order_id, menu_id, member_id)가 반복을 만든다. 아메리카노 가격이 3번 저장된 것도 menu_id가 키가 아니기 때문이다.

완전 종속과 부분 종속

기본키가 복합키일 때 구별한다. 기본키가 열 하나뿐이면 “일부”가 없으므로 부분 종속도 생기지 않는다.

  • 완전 함수 종속(full): 기본키 전체에 종속되고, 일부만으로는 결정되지 않는다. 예: qty
  • 부분 함수 종속(partial): 기본키의 일부만으로 결정된다. 이 표에는 menu_id → menu_name, price와 order_id → store, member_id 두 개가 있고, 메뉴·주문 정보가 줄마다 반복되는 원인이다.

이행 종속

X → Y이고 Y → Z일 때(Y는 X를 결정하지 않는다), Z가 Y를 거쳐 X에 종속되는 것을 이행 함수 종속(transitive)이라 하고 X → Y → Z로 쓴다. order_sheet의 order_id → member_id → member_name, grade가 그 예다. 갱신 이상 때 홍길동의 등급이 둘로 갈라진 것도 이 때문이다.

(order_id, menu_id) → order_id처럼 결정자가 종속자를 포함하는 종속은 항상 성립하는 자명한(trivial) 종속이라 정규화에서 따지지 않는다. 다음 편에서는 부분 종속을 없애 2NF, 이행 종속을 없애 3NF로 만들어 cafedb와 같은 모양(4개 테이블)이 되는 것을 확인한다.

복습 문제

  1. 이상 현상 세 가지를 쓰고, order_sheet에서 지점 이름 ‘본점’을 ‘중앙점’으로 바꿀 때 생길 수 있는 이상을 쓰시오.
  2. 테이블 R(회원번호, 쿠폰번호, 회원이름, 등급, 사용일)의 기본키는 (회원번호, 쿠폰번호)이고, 회원번호 → 회원이름, 등급, (회원번호, 쿠폰번호) → 사용일이다. 완전 종속인 속성과 부분 종속인 속성을 나누시오.
  3. R(주문번호, 회원번호, 등급, 할인율)에서 주문번호 → 회원번호, 회원번호 → 등급, 등급 → 할인율이다. 주문번호에 이행 종속인 속성을 모두 쓰시오.
  4. 본문을 모두 실행한 cafe_practice에서 다음 쿼리의 결과를 예측하시오. 이 분해가 무손실인지 쓰고 이유를 설명하시오.

    CREATE TABLE r_menu  AS SELECT DISTINCT menu_id, menu_name, price FROM order_sheet;
CREATE TABLE r_rest  AS SELECT DISTINCT order_id, store, member_id, member_name, grade, menu_id, qty FROM order_sheet;
SELECT COUNT(*) FROM r_rest JOIN r_menu USING (menu_id);
정답과 해설
  1. 삽입 이상, 갱신 이상, 삭제 이상. 지점 이름은 주문마다 반복 저장돼 있어서 일부 행만 고치면 같은 지점이 두 이름으로 남는 갱신 이상이 생긴다.
  2. 완전 종속: 사용일(회원번호와 쿠폰번호가 모두 있어야 정해진다). 부분 종속: 회원이름, 등급(기본키의 일부인 회원번호만으로 정해진다).
  3. 등급, 할인율. 주문번호 → 회원번호 → 등급 → 할인율이다. 회원번호는 주문번호에 직접 종속이다.
  4. 결과는 16(실행 결과도 16)이고 무손실 분해다. 공통 속성 menu_id가 r_menu의 키(menu_id → menu_name, price)라서 r_rest의 각 행이 메뉴 한 줄에만 붙는다.
