오늘은 실무에서 정말 많이 쓴다는 딕셔너리(dictionary)를 정리했다. 리스트가 순서로 데이터를 관리한다면, 딕셔너리는 이름표(키)로 관리한다는 느낌이었다.

딕셔너리란

키(key)와 값(value)의 쌍으로 이루어진 구조다: { 키1:값1, 키2:값2, ... }. 중괄호 {}로 묶고, key:value 한 쌍을 item이라고 부르며 쉼표로 구분한다. 파이썬 3.7부터는 넣은 순서(삽입 순서)가 그대로 유지되지만, 그렇다고 리스트처럼 인덱스로 접근할 수 있는 건 아니고 키로만 접근한다. 다른 언어에서는 해시(hash), 연관배열(associative array)이라고도 부른다는 걸 새로 알았다.

키와 값에 올 수 있는 자료형이 다르다는 게 포인트였다.

  • 키: 중복 불가, 변경 불가능한(immutable) 데이터만 가능. 정수, 실수, 문자열, 튜플
  • 값: 정수, 실수, 논리, 문자열, 리스트, 튜플 등 뭐든 가능

std = {'name': '홍길동', 'age': 20, 'addr': 'Seoul'}

# 접근 : key로만 가능 (인덱스 접근 불가)
print(std['addr'])

키가 왜 튜플은 되고 리스트는 안 되는지 처음엔 헷갈렸는데, 값이 바뀔 수 있는 건 키가 될 자격이 없다는 원칙으로 이해하니 깔끔해졌다. 지난 글의 튜플 활용 예시에서 딕셔너리 키로 쓰인다고 했던 게 바로 이 얘기였다.

같은 키로 값을 또 넣으면 덮어써진다. 딕셔너리 키는 유일(unique)해야 하므로, 동일한 키에 값을 여러 번 할당하면 마지막 값만 남는다. 처음에 이걸 모르고 같은 키로 여러 값을 쌓으려다가 값이 하나만 남아서 당황했었다.

딕셔너리 뷰, keys(), values(), items()

d = {'one': 1, 'two': 2, 'three': 3}

keys = d.keys()      # dict_keys(['one', 'two', 'three'])
values = d.values()  # dict_values([1, 2, 3])
items = d.items()    # dict_items([('one', 1), ('two', 2), ('three', 3)])

for key in keys:
    print(key)

for name, score in items:   # items()는 (키, 값) 튜플이라 바로 언패킹 가능
    print(name, score)

items()로 반복하면서 for key, value in d.items():처럼 바로 튜플 언패킹이 되는 게 편했다. 지난 글에서 배운 언패킹이 여기서 바로 쓰이는구나 싶었다.

d = {'one': 1, 'three': 3, 'two': 2}

# get(키[, 기본값]) : 키가 없어도 에러 대신 기본값(기본은 None) 반환
value = d.get('two')      # 2
value = d.get('four')     # None (키가 없어도 에러 안 남)
value = d.get('four', 4)  # 4

# [] 로 없는 키 접근하면 KeyError!
# d['four']  -> KeyError

# setdefault(키[, 기본값]) : get()과 비슷하지만, 키가 없으면 그 값으로 "추가"까지 해준다
d.setdefault('five', 5)
print(d)   # 'five': 5 가 실제로 추가됨

# copy() : 새로운 딕셔너리로 복사 (리스트의 copy()처럼 얕은 복사라서, 값으로 든 리스트 등은 원본과 공유됨.
#          안쪽까지 완전히 떼어내려면 copy.deepcopy())
d2 = d.copy()

# update(다른딕셔너리) : 다른 딕셔너리의 항목들을 병합/갱신
d.update({'nine': 9, 'ten': 10})

# pop(키) : 값을 반환하면서 제거
value = d.pop('nine')

# popitem() : 마지막 (키, 값) 항목을 튜플로 반환하면서 제거
key, value = d.popitem()

# clear() : 모든 항목 삭제
d.clear()

get()과 []의 차이가 오늘 가장 실무적으로 와닿았던 부분이다. 없는 키를 []로 접근하면 프로그램이 그대로 죽어버리지만(KeyError), get()은 None이나 지정한 기본값을 돌려주고 넘어간다. 사용자 입력처럼 키가 있을지 없을지 확신할 수 없는 상황에서는 무조건 get()을 쓰는 게 안전하다는 걸 배웠다.

study = {'파이썬': 7, 'SQL': 4, '네트워크': 3}

# 총 공부 시간과 과목당 평균
total = 0
for hours in study.values():
    total += hours
print(f'총 {total}시간, 과목당 평균 {total/len(study):.1f}시간')  # 총 14시간, 과목당 평균 4.7시간

# 가장 오래 공부한 과목 — 내장함수 max()에 key=딕셔너리.get 활용
print(max(study, key=study.get))  # 파이썬

# 값 수정
study['SQL'] = 6

# 키로 삭제
del study['네트워크']
print(study)  # {'파이썬': 7, 'SQL': 6}

max(study, key=study.get) 이 한 줄이 가장 인상 깊었다. 딕셔너리를 순회하면서 각 키에 대한 값(get)을 기준으로 최댓값을 찾아주는 건데, 반복문으로 직접 최댓값 로직을 짜는 것보다 훨씬 간결했다.

딕셔너리는 키로만 접근 가능하고 인덱스로는 접근할 수 없다는 것, 값이 바뀔 수 있는 자료형(리스트 등)은 키로 쓸 수 없다는 것(키는 immutable해야 함)을 다시 확인했다. d['키']는 키가 없으면 에러가 나고 d.get('키')는 에러 없이 None을 반환하니, 안전하게 조회하려면 get()을 쓰는 습관을 들여야겠다.
