[DB] 20. 뷰(VIEW)

뷰(View)는 SELECT 문에 이름을 붙여 테이블처럼 쓰게 만든 가상 테이블이다. 이 글에서는 뷰를 만들고 고치고 지우는 방법, 뷰가 실제로 무엇을 저장하는지, 뷰를 통해 데이터를 바꿀 수 있는 조건과 WITH CHECK OPTION을 정리한다.

예제는 00편의 cafedb를 쓴다. 데이터를 바꾸므로 아래 “실습 준비 SQL”로 테이블 4개를 cafe_practice에 복사한 뒤 본문 SQL을 순서대로 실행한다. MySQL 8.4에서 실행한 결과다.

[WITH [CASCADED | LOCAL] CHECK OPTION];

기본 테이블이 바뀌면 뷰에도 바로 보인다

뷰를 조회할 때마다 저장된 쿼리가 기본 테이블(base table)에 대해 다시 실행된다. 그래서 기본 테이블을 고치면 뷰 결과도 바뀐다.

주의할 점: 데이터를 복사해 저장하는 것은 CREATE TABLE ... AS SELECT다. 만든 시점의 사본이라 원본을 따라 바뀌지 않는다.

뷰를 쓰는 이유

  • 보안: 위의 v_member_public처럼 민감한 열을 빼거나 WHERE로 특정 행만 보이게 한다. 사용자에게 기본 테이블 대신 뷰에만 SELECT 권한을 주면(권한 부여는 10편 참고), 뷰에 없는 열을 볼 방법이 없다.
  • 단순화: 복잡한 쿼리를 이름 하나로 줄인다.
  • 논리적 데이터 독립성: 뷰가 외부 스키마 역할을 해서, 기본 테이블 구조가 바뀌어도 뷰 정의만 고치면 사용자에게 보이는 모양을 유지할 수 있다(뒤에서 직접 확인한다).

CREATE VIEW v_member_order_summary AS
SELECT m.member_id, m.name,
       COUNT(DISTINCT o.order_id) AS order_cnt,
       SUM(oi.qty * mn.price)     AS total_amount
FROM member m
JOIN orders o      ON o.member_id = m.member_id
JOIN order_item oi ON oi.order_id = o.order_id
JOIN menu mn       ON mn.menu_id  = oi.menu_id
GROUP BY m.member_id, m.name;

뷰를 통한 데이터 변경: 갱신 가능한 뷰

뷰에 INSERT, UPDATE, DELETE를 하면 실제로는 기본 테이블이 바뀐다. 뷰의 한 행이 기본 테이블의 어느 행인지 하나로 정해질 때만 가능하다.

1
2

UPDATE v_member_public SET city = '부산' WHERE member_id = 109;
SELECT * FROM member WHERE member_id = 109;
member_idnamegradecityphonejoined_onreferrer_id
109심학규BASIC부산010-2468-13572026-09-20NULL

뷰에 없는 phone은 그대로 남고 city만 바뀌었다. 뷰로 INSERT하면 뷰에 없는 열에는 기본값이나 NULL이 들어간다. 그래서 빠진 열이 NOT NULL이고 기본값도 없으면 INSERT할 수 없다.

1
2

CREATE VIEW v_member_short AS SELECT member_id, name FROM member;
INSERT INTO v_member_short VALUES (111, '뺑덕어미');
-- ERROR 1423 (HY000): Field of view 'cafe_practice.v_member_short' underlying table doesn't have a default value

갱신할 수 없는 뷰

행 하나가 여러 행을 합친 결과이거나 계산한 값이면, 기본 테이블의 어느 행을 어떻게 고쳐야 할지 정할 수 없다.

-- DISTINCT가 있는 뷰

UPDATE v_city SET city = '인천' WHERE city = '대전';
-- ERROR 1288 (HY000): The target table v_city of the UPDATE is not updatable

-- 계산식으로 만든 열
CREATE VIEW v_menu_sale AS
SELECT menu_id, name, price, price * 0.9 AS sale_price FROM menu;
UPDATE v_menu_sale SET sale_price = 4000 WHERE menu_id = 1;
-- ERROR 1348 (HY000): Column 'sale_price' is not updatable

주의할 점: 시험에서는 보통 “조인 뷰는 갱신할 수 없다”로 정리한다. MySQL은 조인 뷰라도 한 기본 테이블만 바꾸는 UPDATE와 INSERT(그 테이블의 열만 나열)는 허용한다. 두 테이블을 한 문장으로 바꾸면 ERROR 1393, DELETE는 ERROR 1395가 난다.

조건을 지킨 4,000원짜리 에스프레소만 들어갔다. 뷰 위에 뷰를 만들었을 때, CASCADED(MySQL 기본값)는 아래쪽 뷰들의 조건까지 모두 검사하고, LOCAL은 이 뷰와 아래쪽 중 스스로 WITH CHECK OPTION이 붙은 뷰의 조건만 검사한다.

기본 테이블 구조가 바뀌면: 논리적 데이터 독립성

2편에서 개념으로 본 논리적 데이터 독립성을 뷰로 직접 확인한다. 기본 테이블의 city 열 이름이 region으로 바뀌면, 옛 열 이름을 참조하는 뷰는 조회가 실패한다.

주의할 점: 뷰를 지워도 기본 테이블은 그대로지만, 반대로 기본 테이블을 지워도 뷰는 자동으로 지워지지 않는다. 뷰 정의는 남아 SHOW FULL TABLES에 계속 보이고, 조회하면 위의 ERROR 1356이 난다. 쓰지 않을 뷰는 DROP VIEW IF EXISTS로 지운다.

뷰, 테이블, CTE 비교

17편의 CTE(WITH)도 쿼리에 이름을 붙인다는 점에서 뷰와 비슷하다. 차이는 수명과 저장 여부다.

인덱스만들 수 있다만들 수 없다만들 수 없다

결과를 실제로 저장하는 구체화 뷰(materialized view)는 Oracle 등에 있지만 MySQL에는 없다.

복습 문제

  1. 뷰가 실제로 저장하는 것은 무엇인지, 기본 테이블에 추가한 회원이 뷰를 다시 만들지 않아도 조회되는지와 그 이유를 쓰시오.
  2. 지점(store)별 주문 건수(order_cnt)를 보여 주는 뷰 v_store_sales를 만들고 지점 이름순으로 조회하시오(cafe_practice에서 실행한다. orders는 원본 그대로다). 이어서 UPDATE v_store_sales SET order_cnt = 0 WHERE store = '본점';을 실행하면 어떻게 되는지 쓰시오.
  3. 본문을 모두 실행한 cafe_practice(city가 region으로 바뀐 상태)에서 다음 뷰를 만들고 두 UPDATE를 차례로 실행했다. 각각 성공하는지 예측하고, 마지막 SELECT의 결과를 쓰시오.
