연습 페이지의 상품 검색은 검색 결과를 자바스크립트로 그린다. 2편의 requests로 받아 보면 결과 칸이 비어 있다.

from bs4 import BeautifulSoup

soup = BeautifulSoup(requests.get(url, timeout=5).text, "html.parser")
print(soup.select_one("#results"))

requests는 서버가 보낸 HTML만 받고 자바스크립트를 실행하지 않는다. 검색어를 넣고 버튼을 눌러야 나오는 결과는 Selenium으로 실제 브라우저를 움직여 얻는다.

설치는 pip install selenium. Chrome이 깔려 있으면 Selenium 4.6 이후의 Selenium Manager가 맞는 드라이버를 알아서 내려받으므로, 드라이버 파일을 따로 받지 않아도 된다. 결과는 Python 3.12, Selenium 4.50, Chrome에서 확인했다.

driver가 브라우저 한 개다. get(url)은 주소창에 주소를 넣는 것과 같고, 페이지가 다 열릴 때까지 기다렸다가 돌아온다.

속성·메서드뜻
driver.get(url)페이지 열기
driver.title페이지 제목
driver.current_url지금 주소 (링크를 눌러 바뀐 뒤에도 따라간다)
driver.page_source자바스크립트가 그린 지금 화면의 HTML
driver.back() / forward() / refresh()뒤로 / 앞으로 / 새로고침
driver.close()지금 탭 하나 닫기
driver.quit()브라우저 전체 종료 (드라이버 프로그램까지)

주의할 점: 다 쓴 뒤에는 driver.quit()을 부른다. close()는 탭만 닫아 드라이버 프로그램이 남을 수 있고, 예외로 중간에 멈추면 브라우저가 계속 떠 있다. 긴 작업은 try: ... finally: driver.quit()으로 감싼다.

창을 띄우지 않고 돌리려면(headless) 옵션을 준다. 화면이 없는 서버에서 돌릴 때 쓴다.

find_element는 BeautifulSoup과 달리 못 찾으면 None이 아니라 NoSuchElementException을 낸다. 있는지 확인만 하려면 find_elements의 결과가 빈 리스트인지 본다.

CSS 선택자로 대부분 찾을 수 있으므로 이 시리즈는 By.CSS_SELECTOR, By.ID, By.NAME을 주로 쓴다. XPath는 개발자 도구에서 Copy XPath로 바로 얻을 수 있지만, 4편의 Copy selector처럼 구조가 바뀌면 깨지기 쉽다.

기다리기 ①: implicitly_wait

time.sleep(2)는 결과가 0.8초 만에 나와도 무조건 2초를 쉰다. implicitly_wait를 한 번 정해 두면, 요소를 찾을 때 나타날 때까지 최대 그 시간만큼 기다린다.

검색 결과 3건

이번에는 sleep 없이도 결과를 얻었다. 버튼을 누르면 페이지가 결과 칸을 “검색 중…“으로 바꾸고, find_elements가 h3가 생길 때까지 기다렸다가 돌려준 것이다. 재 보니 0.8초쯤 걸렸다.

주의할 점: implicitly_wait는 “하나라도 나타날 때까지”만 기다린다. 결과가 여러 번에 나눠 그려지거나, 이전 결과가 화면에 남아 있다면 기다리지 않고 바로 돌려줄 수 있다. 특정 조건(클릭할 수 있게 됨, 이전 요소가 사라짐 등)을 기다리려면 8편의 명시적 대기를 쓴다.

복습 문제

  1. requests로 받은 검색 페이지에서 #results가 비어 있는 이유는 무엇인가?
  2. driver.close()와 driver.quit()의 차이를 쓰시오.
  3. 다음 코드가 NoSuchElementException으로 멈추지 않게, 요소가 있는지 먼저 확인하는 코드로 고치시오.
    btn = driver.find_element(By.ID, "more-btn")
  4. 검색 직후 find_elements가 0개를 돌려줬다. time.sleep 말고 쓸 수 있는 방법을 쓰시오.
  5. 상세 링크의 완전한 주소를 얻는 방법을 Selenium과 BeautifulSoup 각각으로 쓰시오.
정답과 해설
  1. requests는 자바스크립트를 실행하지 않는다. 검색 결과는 페이지가 열린 뒤 자바스크립트가 그린다.
  2. close()는 지금 탭(창) 하나만 닫고, quit()은 브라우저와 드라이버 프로그램까지 끝낸다. 작업이 끝나면 quit().
