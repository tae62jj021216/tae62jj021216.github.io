Claude Code 개발 환경 #2 — 자동 커밋 hook이 다른 세션의 폴더를 지운 날
1
2
3

git add -A
git commit -m "auto: <고친 파일>"
git push

자동 커밋 hook이 하던 일이다. 세 줄 모두 흔한 명령인데, 이 조합이 다른 세션이 잠시 옮겨 둔 스킬 폴더를 원격 저장소에서 지웠다.

한 일

Claude 설정 폴더(전역 지침, 설정 파일, 직접 만든 스킬)를 GitHub 비공개 저장소로 관리하기로 했다. 로그인 정보와 대화 기록은 빼고, 허용 목록에 있는 파일만 올린다. 손으로 커밋하는 일을 잊지 않도록 hook 두 개를 붙였다.

시점하는 일
세션 시작설정 저장소를 pull한다
파일 수정 뒤추적하는 파일이 바뀌었으면 커밋하고 push한다

처음 만든 커밋 hook은 위의 세 줄처럼 작업 트리 전체를 담았다.

막힌 점

무슨 일이 있었나

그날은 세션 여러 개가 같은 설정 폴더를 쓰고 있었다.

  1. 한 세션이 스킬 하나(Simulink 모델 정리 스킬)의 설명을 다듬으려고, 그 스킬 폴더를 잠시 다른 곳으로 옮겨 두었다.
  2. 다른 세션에서 설정 파일을 하나 고쳤다. 파일 수정 뒤 hook이 돌았다.
  3. hook의 git add -A는 작업 트리의 모든 변경을 담는다. 옮겨진 스킬 폴더는 “삭제”로 담겼고, 다른 세션이 편집 중이던 스크립트 파일도 함께 담겼다.
  4. hook은 그대로 커밋하고 push했다. 원격 저장소에서 스킬이 지워졌다.

위키의 작업 기록에도 그 흔적이 남았다. 스킬 목록을 자동으로 다시 만드는 hook이 “삭제: 그 스킬”을 기록했고, 30분쯤 뒤 복구하면서 “추가: 그 스킬”이 다시 찍혔다. 스킬은 앞 커밋에서 되살렸다.

원인

git add -A는 “작업 트리에 보이는 변경은 모두 내 것”이라는 가정 위에서만 안전하다. 세션 하나가 저장소 하나를 쓸 때는 이 가정이 맞는다. 여러 세션이 한 저장소를 동시에 쓰면 작업 트리에는 늘 남의 변경이 있고, 가정이 깨진다.

hook은 사람이 보지 않는 곳에서 돈다. 손으로 커밋할 때는 git status를 보고 낯선 변경을 걸러 낼 기회가 있지만, hook은 확인 없이 push까지 했다.

해결

1. 고친 파일 하나만 담는다

커밋 hook을 고쳐, hook 입력에 들어 있는 “방금 고친 파일” 하나만 담게 했다.

1
2
3

git add -- <방금 고친 파일>
git commit -m "auto: <방금 고친 파일>" -- <방금 고친 파일>
git push

git commit -- <파일>을 함께 쓰면, 다른 이유로 이미 스테이징된 파일이 있어도 커밋에는 그 파일만 들어간다.

2. 전부 담는 명령은 확인을 받는다

Claude가 셸에서 실행하려는 명령을 실행 직전에 검사하는 hook을 하나 더 만들었다. 아래 명령이면 바로 실행하지 않고 사용자 확인 창을 띄운다.

확인을 받는 명령이유
git add -A, git add ., git add <폴더>남의 변경까지 담을 수 있다
git commit -a추적 중인 모든 변경을 담는다

파일 이름을 하나하나 지정한 git add -- <파일>은 통과한다. 명령 문자열만 보고 판단하므로 틀릴 수 있어서, 막지(deny) 않고 확인(ask)을 받는다. 파이프 시험 25건으로 판정을 확인했다.

3. hook이 보지 못하는 곳

이 검사 hook은 Claude가 도구로 실행하는 명령만 본다. 스크립트 안에서 실행되는 git은 보이지 않는다. 이번 사고를 낸 것이 바로 hook 스크립트 안의 git add -A였다. 그래서 검사 hook을 만드는 것으로 끝내지 않고, 커밋 hook 스크립트 자체를 1번처럼 고쳤다.

같은 규칙을 다른 저장소에도

같은 원칙을 위키와 이 블로그의 작업 규칙에도 넣었다.

  • 커밋 전에 git status와 git log로 모르는 변경이 없는지 본다. 있으면 먼저 알린다.
  • 바꾼 파일만 이름을 지정해 스테이징한다. git add -A, git add .는 쓰지 않는다.
  • 블로그는 승인 전 초안을 _drafts/에 따로 둔다. 같은 폴더에서 다른 세션이 _posts의 글을 올린 일이 있어, 승인 전 초안이 섞여 올라가지 않게 나눴다.

배운 점: 자동화는 사람이 하던 확인까지 함께 없앤다. “내가 바꾼 것만”을 명령으로 표현하지 않으면, 동시에 일하는 세션이 늘어날수록 자동화가 남의 작업을 건드린다.
