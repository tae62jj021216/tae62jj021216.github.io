r = requests.get("https://tae62jj021216.github.io/assets/crawl/shop/list-1.html")

requests.get 한 줄이 1편의 “요청 → 응답”을 그대로 한다. 돌아온 Response 객체에서 상태 코드, 헤더, 본문을 꺼내 쓴다.

이 글의 예제는 1편에서 소개한 연습 페이지를 쓴다. 설치는 pip install requests. 결과는 Python 3.12, requests 2.34에서 확인했다.

속성뜻

text는 3,737자인데 content는 4,092바이트다. UTF-8에서 한글 한 글자는 3바이트라서 바이트 수가 더 많다.

주의할 점: 헤더에 charset이 없으면 requests는 text/html을 ISO-8859-1로 가정해 한글이 깨질 수 있다. 이때는 r.encoding = r.apparent_encoding(본문을 보고 추측한 인코딩)이나 r.encoding = "utf-8"로 정한 뒤 r.text를 읽는다.

쿼리 붙이기: params

쿼리를 주소 문자열에 직접 이어 붙이지 않고 params에 딕셔너리로 넘긴다.

1
2

r = requests.get(url, params={"sort": "가격순", "page": 2})
print(r.url)

1

https://tae62jj021216.github.io/assets/crawl/shop/list-1.html?sort=%EA%B0%80%EA%B2%A9%EC%88%9C&page=2

r.url이 실제로 요청한 주소다. 한글 가격순은 %EA%B0%80…처럼 퍼센트 인코딩되어 붙었다. 손으로 이어 붙이면 이 인코딩과 & 처리를 직접 해야 하므로 params가 안전하다.

연습 쇼핑몰은 정적 파일이라 쿼리를 읽지 않는다. 위 요청도 200으로 같은 목록을 돌려준다. 쿼리로 결과가 바뀌는 것은 서버가 쿼리를 읽는 사이트(검색, 9편의 API 등)에서다.

요청 헤더: User-Agent

r = requests.get(url)
print(r.request.headers["User-Agent"])

r = requests.get(url, headers={"User-Agent": "Mozilla/5.0 (study crawler)"})
print(r.request.headers["User-Agent"])

1
2

python-requests/2.34.2
Mozilla/5.0 (study crawler)

r.request는 실제로 보낸 요청이다. 따로 정하지 않으면 User-Agent가 python-requests/버전으로 나간다. 이 값을 보고 프로그램 요청을 거절(403)하는 사이트가 있어서, 브라우저 형식의 값을 넣는 경우가 많다.

주의할 점: User-Agent를 바꾸는 것은 거절을 피하는 수단이지 허락을 받는 방법이 아니다. robots.txt와 이용약관에서 막은 곳은 User-Agent를 바꿔도 수집하지 않는다(1편).

requests.get은 404여도 예외를 내지 않고 응답을 돌려준다. 실패를 놓치지 않으려면 status_code를 확인하거나 raise_for_status()로 4xx·5xx일 때 예외를 낸다.

연결 실패와 시간 제한

try:
    r = requests.get("http://127.0.0.1:9/", timeout=5)
except requests.ConnectionError:
    print("연결 실패")
except requests.Timeout:
    print("시간 초과")

1

연결 실패

서버가 없거나(연결 실패) 응답이 늦으면(시간 초과) 예외가 난다. timeout을 주지 않으면 응답이 오지 않을 때 프로그램이 계속 기다리므로, 반복 수집에서는 항상 timeout을 준다.

예외언제
requests.HTTPErrorraise_for_status()에서 4xx·5xx
requests.ConnectionError서버에 연결하지 못함
requests.Timeouttimeout 안에 응답이 없음
requests.RequestException위 모두의 부모. 한꺼번에 잡을 때

주의할 점: SSL 인증서 오류가 날 때 verify=False로 검사를 끄는 예제를 흔히 본다. 이렇게 하면 중간에서 내용을 바꿔치기해도 알 수 없다. 연습 외에는 쓰지 않고, 쓴다면 그 사이트의 인증서 문제를 먼저 확인한다.

간단한 확인에는 urllib도 충분하지만, 헤더·쿼리·예외를 다루기는 requests가 편하다. 이 시리즈는 requests를 쓴다.

정답과 해설
  1. text는 인코딩으로 바꾼 글자(str), content는 원래 바이트(bytes). 이미지는 글자가 아니므로 content를 파일에 "wb"로 쓴다.
  2. https://example.com/search?q=cafe&page=3
  3. requests.get은 404·500이어도 예외를 내지 않는다. r.raise_for_status()를 넣거나 if r.ok:로 확인한다.
  4. r.encoding. 헤더에 charset이 없어 ISO-8859-1로 읽은 경우가 많다. r.encoding = r.apparent_encoding(또는 "utf-8") 뒤에 r.text를 다시 읽는다.
