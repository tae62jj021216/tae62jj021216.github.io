[Pandas] 08. apply와 map으로 함수 적용하기

map()과 apply()는 직접 만든 함수나 딕셔너리를 Series의 원소마다, DataFrame의 행이나 열마다 적용하는 메서드다. 회원 등급을 할인율로 바꾸거나, 주문 상세의 메뉴 번호에 가격을 붙이거나, 가격과 시즌 여부를 함께 보고 할인가를 정하는 일이 여기에 해당한다.

예제 데이터는 00편의 cafe 폴더를 쓴다. Python 3.12, pandas 3.0.6에서 실행한 결과다.

map()에 딕셔너리를 넘기면 원소마다 같은 키를 찾아 그 값으로 바꾼다. 결과는 원래 Series와 길이와 인덱스가 같은 새 Series다.

딕셔너리에 없는 값은 NaN이 된다. BASIC을 빠뜨리면 BASIC 회원 4명의 할인율이 0이 아니라 NaN이 된다.

1
2
3

rate2 = {"VIP": 0.1, "GOLD": 0.05}
print(member["grade"].map(rate2).tolist())
print(member["grade"].replace(rate2).tolist())

1
2

[0.1, nan, 0.05, nan, 0.05, nan, 0.1, nan]
[0.1, 'BASIC', 0.05, 'BASIC', 0.05, 'BASIC', 0.1, 'BASIC']

주의할 점: map()은 딕셔너리에 없는 값을 NaN으로 만들고 오류를 내지 않는다. 할인율처럼 계산에 쓰는 값이면 NaN이 이어지는 계산에 그대로 번진다. 바꾼 뒤 isna().sum()으로 빈 값을 세거나, 키를 모두 넣는다. 일부 값만 바꾸고 나머지는 그대로 두려면 replace()를 쓴다(위 둘째 줄).

SQL로는 CASE에 해당한다. 단, CASE에 ELSE를 빠뜨리면 NULL이 되는 것처럼 map()도 빠진 키는 NaN이다.

1
2
3

SELECT name, grade,
       CASE grade WHEN 'VIP' THEN 0.1 WHEN 'GOLD' THEN 0.05 ELSE 0 END AS rate
FROM member;

Series.map과 Series.apply: 함수 적용

함수를 넘기면 원소 하나씩 함수에 넣고, 돌려준 값을 모은다. 한 번만 쓸 짧은 함수는 lambda로 쓴다.

def price_band(p):
    if p < 4000:
        return "저가"
    elif p < 6000:
        return "중가"
    return "고가"

print(menu["price"].map(price_band).tolist())
print(menu["price"].apply(price_band).equals(menu["price"].map(price_band)))
print(menu["name"].apply(lambda s: s + " L").head(3).tolist())

Series에 함수를 넘기면 map()과 apply()의 결과가 같다(둘째 줄 True). 딕셔너리·Series는 map()만 받는다. 함수에 인자를 더 넘길 때는 apply()의 args=에 튜플로 주거나, 두 메서드 모두 키워드 인자(unit="원")로 준다.

def add_won(p, unit):
    return f"{p:,}{unit}"

print(menu["price"].apply(add_won, args=("원",)).head(3).tolist())

함수가 Series를 돌려주면 열이 여러 개가 된다

함수가 값 하나 대신 Series를 돌려주면, 그 Series의 인덱스가 열 이름이 되어 DataFrame이 나온다. 부가세 10%가 포함된 가격을 공급가와 부가세로 나눈다.

def split_vat(p):
    supply = round(p / 1.1)
    return pd.Series({"supply": supply, "vat": p - supply})

pandas 2.1에서 DataFrame.map()이 생기고 applymap()은 사용 중단 예고(경고)가 붙었다. pandas 3.0에서는 applymap()이 지워져 AttributeError가 난다. 예전 코드의 applymap은 map으로 이름만 바꾸면 된다.

메서드대상함수에 들어가는 것딕셔너리·Series
Series.map()Series원소 하나받음
Series.apply()Series원소 하나받지 않음
DataFrame.apply()DataFrame열 하나(axis=0) 또는 행 하나(axis=1)받지 않음
DataFrame.map()DataFrame원소 하나받지 않음

같은 일을 벡터화 연산으로

앞의 할인가는 apply() 없이 열 전체를 한 번에 계산하는 방법으로도 만들 수 있다.

import numpy as np

p, s = menu["price"], menu["is_seasonal"]

v1 = menu.apply(sale_price, axis=1)
v2 = pd.Series(np.where(s, p, p - 500))
v3 = p.where(s, p - 500)
v4 = p.mask(~s, p - 500)

print(v1.equals(v2), v1.equals(v3), v1.equals(v4))
print(v3.tolist())

1
2

True True True
[4000, 4500, 5000, 4500, 5000, 5000, 6000, 6000, 6000, 2500, 3500]

네 결과가 모두 같다.

방법읽는 법
np.where(조건, A, B)조건이 참이면 A, 거짓이면 B. 결과는 NumPy 배열
s.where(조건, B)조건이 참인 자리는 원래 값을 두고, 거짓인 자리만 B로 바꾼다
s.mask(조건, B)조건이 참인 자리를 B로 바꾼다 (where의 반대)

where()와 mask()는 조건이 반대다. p.where(s, …)는 “시즌 메뉴면 그대로 둔다”, p.mask(~s, …)는 “시즌 메뉴가 아니면 바꾼다”로 읽는다.

apply(axis=1)는 행 수만큼 파이썬 함수를 부르고, 부를 때마다 행 하나를 Series로 만든다. 벡터화 연산은 열 전체를 NumPy가 한 번에 계산한다. 메뉴 표를 1만 번 이어 붙인 11만 행으로 시간을 재 본다.

import time

big = pd.concat([menu] * 10000, ignore_index=True)

t = time.perf_counter()
big.apply(sale_price, axis=1)
t_apply = time.perf_counter() - t

t = time.perf_counter()
big["price"].where(big["is_seasonal"], big["price"] - 500)
t_where = time.perf_counter() - t

print(f"apply {t_apply:.3f}초, where {t_where:.4f}초, {t_apply / t_where:.0f}배")

1

apply 0.429초, where 0.0017초, 253배

결과는 같고 시간은 250배쯤 차이가 났다. 시간은 실행할 때마다, 컴퓨터마다 다르다. 위에서 쓴 pd.concat()은 9편에서 다룬다.

apply가 필요한 경우

벡터화 연산으로 바꿀 수 있으면 바꾸는 편이 빠르고 코드도 짧다. apply()나 map()이 필요한 경우는 다음과 같다.

상황예
값을 다른 값으로 바꾸는 대응표가 있다등급 → 할인율 딕셔너리, 메뉴 번호 → 가격 Series (map)
원소 하나를 받는 함수밖에 없다다른 라이브러리의 함수, if·try가 여러 단계인 함수
함수 하나로 열 여러 개를 만든다공급가와 부가세 (apply가 Series를 돌려줌)
행이 적고 코드를 읽기 쉽게 두고 싶다메뉴 11개처럼 작은 표

조건이 두 갈래면 where()·mask()·np.where(), 숫자를 구간으로 나누면 6편의 pd.cut(), 문자열을 바꾸면 6편의 .str 메서드가 먼저다.
