[DB] 01. 데이터베이스와 DBMS

SQL을 배우기 전에, SQL이 다루는 대상인 데이터베이스와 그것을 관리하는 DBMS가 무엇인지 정리한다.

데이터베이스란

데이터베이스(Database, DB)는 여러 사용자와 응용 프로그램이 함께 쓰려고, 중복을 줄이고 체계적으로 모아 둔 데이터의 집합이다. 정의에 들어가는 네 가지 성질을 묶어 외운다.

성질뜻
통합된 데이터 (Integrated)중복을 최소화해 한곳에 모았다
저장된 데이터 (Stored)컴퓨터가 접근할 수 있는 저장 장치에 있다
운영 데이터 (Operational)조직의 업무에 꼭 필요한 데이터다
공용 데이터 (Shared)여러 사용자와 프로그램이 함께 쓴다

데이터베이스의 특징

특징뜻예 (카페 체인)
실시간 접근성요청하면 바로 응답한다주문하자마자 적립 포인트가 보인다
계속적인 변화삽입·수정·삭제로 항상 최신 상태를 유지한다새 메뉴 추가, 품절 메뉴 삭제
동시 공용여러 사용자가 동시에 같은 데이터를 쓴다여러 지점이 같은 회원 정보를 조회한다
내용에 의한 참조저장 위치가 아니라 값으로 찾는다“등급이 VIP인 회원”처럼 조건으로 찾는다

파일 시스템 대신 DBMS를 쓰는 이유

DBMS(Database Management System)는 데이터베이스를 만들고, 사용자 대신 데이터를 저장·검색·관리해 주는 소프트웨어다. MySQL, Oracle, SQL Server, MariaDB, PostgreSQL 등이 있다.

데이터 관리 방식은 대략 이렇게 발전했다.

종이 장부 → 파일 시스템 → 데이터베이스 시스템 → 웹 데이터베이스 → 분산 데이터베이스

지점마다 회원 정보를 각자 엑셀 파일로 관리한다고 해 보자. 같은 회원이 여러 파일에 중복되고, 한 파일에서 전화번호를 고쳐도 다른 파일은 옛 번호로 남는다. DBMS는 이런 문제를 해결한다.

장점설명
중복 최소화데이터를 한곳에 모아 같은 데이터를 여러 번 저장하지 않는다
무결성제약조건으로 잘못된 값(음수 가격, 없는 회원의 주문 등)이 들어오지 못하게 막는다
일관성한 번 고치면 모든 사용자가 같은 값을 본다
데이터 독립성저장 구조가 바뀌어도 응용 프로그램을 고치지 않아도 된다
보안사용자별로 볼 수 있는 데이터와 할 수 있는 작업을 제한한다
공유여러 사용자가 동시에 접근해도 충돌 없이 처리한다
회복장애가 나도 백업과 로그로 복구한다

단점도 있다. 운영에 전문 인력이 필요하고, 시스템이 복잡하며, 비용이 들고, 백업과 복구 절차가 까다롭다.

DBMS의 세 가지 기능

기능하는 일대응하는 SQL
정의 기능데이터의 구조(테이블, 열, 제약조건)를 정한다DDL
조작 기능데이터를 검색·삽입·수정·삭제한다DML
제어 기능권한, 무결성, 동시 접근, 회복을 관리한다DCL, TCL

DBMS의 종류

DBMS는 데이터를 어떤 구조로 표현하는지, 즉 데이터 모델에 따라 나뉜다. 데이터 모델은 대략 등장한 순서대로 이렇게 바뀌어 왔다.

계층형(1960년대) → 망형(1970년대) → 관계형(1970년 제안, 1980년대 상용화) → 객체지향형·객체관계형(1990년대) → NoSQL(2000년대 이후)

종류데이터 구조특징
계층형트리 (부모 하나에 자식 여럿)초기 모델. 다대다 관계를 표현하기 어렵다
망형(네트워크형)그래프다대다 관계를 표현하지만 구조가 복잡하다
관계형 (RDBMS)표(테이블)가장 널리 쓰인다. SQL로 다룬다. MySQL, Oracle 등
객체지향형객체객체지향 프로그래밍의 개념을 데이터에 적용한다
객체관계형표 + 객체관계형에 사용자 정의 타입, 상속 같은 객체 개념을 더했다. PostgreSQL, Oracle 등
NoSQL키-값, 문서, 그래프 등정해진 스키마 없이 대용량 데이터를 유연하게 저장한다. MongoDB, Redis 등

계층형과 망형은 데이터를 찾을 때 저장된 연결 경로를 프로그램이 직접 따라가야 했다. 관계형은 “어떤 데이터가 필요한지”만 SQL로 말하면 DBMS가 찾아 주므로 쓰기 쉬워서 주류가 됐다. 이 시리즈에서 다루는 MySQL은 관계형 DBMS다.

SQL과 명령어 분류

SQL(Structured Query Language)은 관계형 DBMS에서 데이터를 정의·조작·제어하는 표준 언어다. 국제 표준(ANSI/ISO SQL)이 있고, DBMS마다 이를 확장한 문법이 있다. Oracle은 PL/SQL, SQL Server는 T-SQL을 쓰고, MySQL도 표준에 자체 문법(LIMIT, AUTO_INCREMENT 등)을 더했다.

분류뜻명령어
DDL (Data Definition Language)구조를 정의한다CREATE, ALTER, DROP, TRUNCATE
DML (Data Manipulation Language)데이터를 다룬다SELECT, INSERT, UPDATE, DELETE
DCL (Data Control Language)권한을 관리한다GRANT, REVOKE
TCL (Transaction Control Language)트랜잭션을 확정하거나 취소한다COMMIT, ROLLBACK, SAVEPOINT

주의할 점: SELECT를 따로 DQL(Data Query Language)로 나누기도 하고, TCL을 DCL에 포함하기도 한다. 시험에서는 문제에서 쓰는 분류 기준을 따른다.

관계형 데이터베이스 용어

관계형 DB는 데이터를 표 형태로 저장한다. 같은 대상을 부르는 말이 여러 개라서 한 번에 정리해 둔다.

관계형 모델 용어흔히 쓰는 말파일 시스템 용어뜻
릴레이션 (Relation)테이블파일데이터를 담는 표
튜플 (Tuple)행 (Row)레코드표의 가로 한 줄
속성 (Attribute)열 (Column)필드표의 세로 한 칸
도메인 (Domain)--한 속성이 가질 수 있는 값의 범위
차수 (Degree)--속성(열)의 개수
카디널리티 (Cardinality)--튜플(행)의 개수

이 시리즈의 예제는 가상의 카페 체인 DB cafedb를 쓴다. 받는 방법과 테이블 구성은 00편에 정리했다.

cafedb의 member(회원) 테이블 일부로 보면 이렇다.

member_idnamegradecity
101홍길동VIP서울
102성춘향BASIC서울
103이몽룡GOLD부산
  • 이 표 자체가 릴레이션, 가로 한 줄 (101, 홍길동, VIP, 서울)이 튜플, grade 같은 세로 한 칸이 속성이다.
  • 여기 보이는 부분만 보면 차수는 4(열 4개), 카디널리티는 3(행 3개)이다.
  • grade의 도메인은 업무 규칙상 {'BASIC', 'GOLD', 'VIP'}다. cafedb의 grade 열은 VARCHAR(10)이라 테이블이 이 규칙을 강제하지는 않는다(도메인을 지키는 규칙은 3편에서 다룬다).

주의할 점: 차수와 카디널리티를 자주 바꿔 쓴다. 차수는 열(속성) 수, 카디널리티는 행(튜플) 수다. 행은 데이터를 넣고 빼면 계속 바뀌지만, 열은 구조를 바꾸지 않는 한 그대로다.

데이터베이스 사용자

DB를 쓰는 사람은 하는 일에 따라 세 부류로 나눈다. 카페 체인에 대입하면 이렇다.

사용자하는 일주로 쓰는 것카페 체인 예
일반 사용자 (최종 사용자)DB에서 필요한 데이터를 조회·입력한다응용 프로그램 화면, 간단한 SQL주문을 받는 카운터 직원, 매출을 조회하는 점장
응용 프로그래머일반 사용자가 쓸 프로그램을 만든다프로그래밍 언어에 DML을 넣어서주문·적립 앱과 포스(POS) 프로그램 개발자
데이터베이스 관리자 (DBA)DB 전체를 설계하고 운영·관리한다DDL, DCL, 모니터링 도구본사에서 DB를 책임지는 담당자

일반 사용자는 SQL을 모르고 메뉴 화면만 쓰는 사람과, 직접 질의문을 써서 조회하는 사람으로 다시 나누기도 한다.

DBA(Database Administrator)는 DB 전체를 책임지는 사람(또는 팀)이다. 주요 업무는 다음과 같다.

업무내용
스키마 정의DB의 전체 구조와 저장 구조를 설계하고 정의한다
무결성·보안 관리제약조건을 정하고, 사용자 계정을 만들고 권한을 부여·회수한다
백업과 회복백업 정책을 정하고, 장애가 나면 DB를 복구한다
성능 관리사용 현황을 모니터링하고 인덱스 등을 조정해 성능을 높인다 (튜닝)
변화 대응요구사항이 바뀌면 구조를 바꾸고, DBMS 업그레이드 등을 관리한다

주의할 점: 일반 사용자는 주로 DML(조회·입력)을, 응용 프로그래머는 프로그램 안에서 DML을, DBA는 DDL과 DCL을 쓴다. “DCL로 권한을 관리하는 사용자”를 물으면 DBA다.

복습 문제

  1. 데이터베이스 정의의 네 가지 성질을 쓰시오.
  2. “등급이 VIP인 회원을 찾는다”처럼 저장 위치가 아니라 값의 조건으로 데이터를 찾는 것은 데이터베이스의 어떤 특징인지 쓰시오.
  3. 다음 명령어를 DDL, DML, DCL, TCL로 분류하시오. ALTER, UPDATE, REVOKE, ROLLBACK, TRUNCATE, INSERT
  4. 열 5개, 행 120개인 테이블의 차수와 카디널리티를 쓰시오. 이 테이블에 행 10개를 추가하면 어느 값이 바뀌는지도 쓰시오.
  5. 지점마다 회원 파일을 따로 관리하던 카페가 DBMS로 옮기면 해결되는 문제를 두 가지 쓰시오.
  6. 다음 중 DBA가 하는 일이 아닌 것을 고르시오.
    • ① 신입 바리스타 계정에 주문 조회 권한만 부여한다.
    • ② 매일 밤 DB를 백업하고, 장애가 나면 복구한다.
    • ③ 카운터에서 손님의 주문을 입력한다.
    • ④ 조회가 느린 테이블에 인덱스를 추가한다.
정답과 해설
  1. 통합된 데이터, 저장된 데이터, 운영 데이터, 공용 데이터.
  2. 내용에 의한 참조. 주소나 위치가 아니라 데이터의 값으로 찾는다.
  3. DDL: ALTER, TRUNCATE / DML: UPDATE, INSERT / DCL: REVOKE / TCL: ROLLBACK. TRUNCATE는 행을 지우지만 테이블을 비우고 새로 만드는 구조 작업이라 DDL로 분류한다.
  4. 차수 5, 카디널리티 120. 행을 추가하면 카디널리티만 130으로 바뀌고 차수는 그대로다.
  5. 예: 같은 회원이 여러 파일에 중복 저장되는 문제, 한 파일만 고쳐 지점마다 정보가 달라지는 일관성 문제, 여러 지점이 동시에 고칠 때의 동시 접근 문제, 지점별로 볼 수 있는 정보를 나누는 보안 문제 중 두 가지.
  6. ③. 주문 입력은 응용 프로그램으로 데이터를 다루는 일반 사용자의 일이다. ①은 권한 관리(보안), ②는 백업과 회복, ④는 성능 관리로 모두 DBA의 업무다.
