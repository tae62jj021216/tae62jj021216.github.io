[DB] 12. SELECT 기본과 WHERE 조건 검색

테이블에서 원하는 행과 열만 골라 보는 것이 SELECT다. 이 글에서는 SELECT의 기본 형식과 실행 순서, WHERE에서 쓰는 연산자, 정렬(ORDER BY)과 개수 제한(LIMIT)을 정리한다.

예제는 00편의 가상 카페 DB cafedb를 쓴다. MySQL 8.4에서 실행한 결과다.

SELECT 형식과 실행 순서

1
2
3
4
5
6
7

SELECT [DISTINCT] 열 목록
FROM 테이블
[WHERE 행 조건]
[GROUP BY 그룹 기준 열]
[HAVING 그룹 조건]
[ORDER BY 정렬 기준 [ASC | DESC]]
[LIMIT 개수];

작성 순서와 실제 실행 순서가 다르다.

실행 순서절하는 일
1FROM대상 테이블을 정한다
2WHERE조건에 맞는 행만 남긴다
3GROUP BY행을 그룹으로 묶는다
4HAVING조건에 맞는 그룹만 남긴다
5SELECT보여 줄 열을 고르고 계산한다
6DISTINCT중복 행을 없앤다
7ORDER BY정렬한다
8LIMIT개수를 자른다

이 순서 때문에 SELECT에서 붙인 별칭은 WHERE에서 쓸 수 없고, ORDER BY에서는 쓸 수 있다.

1
2
3
4

SELECT name, price * 0.9 AS sale_price FROM menu WHERE sale_price < 4000;
-- ERROR 1054 (42S22): Unknown column 'sale_price' in 'where clause'

SELECT name, price * 0.9 AS sale_price FROM menu ORDER BY sale_price LIMIT 2;
namesale_price
버터쿠키2700.0
밤 마들렌3150.0

WHERE가 실행될 때는 아직 sale_price라는 열이 만들어지지 않았기 때문이다.

AS로 결과 열에 별칭을 붙이고, 열끼리 계산한 값도 바로 조회할 수 있다.

SELECT name AS 메뉴명, price AS 가격, price * 0.9 AS 할인가

NULL은 =로 비교할 수 없다

NULL은 “값을 모른다”는 뜻이라, NULL과의 비교 결과는 참도 거짓도 아닌 UNKNOWN이 된다. WHERE는 참인 행만 남기므로 = NULL은 아무 행도 돌려주지 않는다.

1
2

SELECT name, phone FROM member WHERE phone = NULL;   -- 결과 없음
SELECT name, phone FROM member WHERE phone IS NULL;
namephone
성춘향NULL
흥부NULL
팥쥐NULL

주의할 점: !=도 마찬가지다. city != '서울'은 도시가 NULL인 회원(팥쥐)을 결과에서 빼 버린다. NULL인 행까지 포함하려면 OR city IS NULL을 따로 붙여야 한다.

LIKE의 %와 _

1

SELECT name FROM menu WHERE name LIKE '%라떼' ORDER BY menu_id;   -- '라떼'로 끝나는 이름
name
카페라떼
바닐라라떼
콜드브루 라떼
말차라떼
1

SELECT name FROM menu WHERE name LIKE '__라떼';   -- 앞에 정확히 두 글자 + '라떼'
name
말차라떼
카페라떼

%나 _ 없이 LIKE '라떼'라고 쓰면 = '라떼'와 같아서, 이름이 정확히 “라떼”인 행만 찾는다.

AND가 OR보다 먼저 계산된다

“서울이나 부산에 사는 GOLD 회원”을 찾으려고 괄호 없이 쓰면 결과가 달라진다.

1
2

SELECT name, grade, city FROM member
WHERE city = '서울' OR city = '부산' AND grade = 'GOLD';
namegradecity
홍길동VIP서울
성춘향BASIC서울
이몽룡GOLD부산
흥부GOLD서울

AND가 먼저 묶여서 city = '서울' OR (city = '부산' AND grade = 'GOLD')로 해석됐다. 의도대로 하려면 괄호가 필요하다.

1
2

SELECT name, grade, city FROM member
WHERE (city = '서울' OR city = '부산') AND grade = 'GOLD';
namegradecity
이몽룡GOLD부산
흥부GOLD서울

ORDER BY: 정렬

ASC(오름차순)가 기본값이고, DESC는 내림차순이다. 기준을 여러 개 쓰면 앞 기준이 같을 때 다음 기준으로 정렬한다.

1
2
3

SELECT name, price, released_on FROM menu
ORDER BY price DESC, released_on ASC
LIMIT 4;
namepricereleased_on
치즈케이크65002024-01-01
초코케이크65002024-09-01
딸기 에이드60002026-03-01
바닐라라떼55002024-01-01

MySQL은 NULL을 가장 작은 값으로 본다. 그래서 오름차순에서는 NULL이 맨 앞에, 내림차순에서는 맨 뒤에 온다.

1

SELECT name, city FROM member ORDER BY city;
namecity
팥쥐NULL
심청대전
콩쥐대전
이몽룡부산
놀부부산
홍길동서울
성춘향서울
흥부서울

주의할 점: NULL의 정렬 위치는 DBMS마다 다르다. Oracle은 반대로 NULL을 가장 큰 값으로 봐서 오름차순일 때 맨 뒤에 둔다.

LIMIT: 개수 제한과 페이지 나누기

LIMIT n은 앞에서 n개, LIMIT n OFFSET m은 m개를 건너뛰고 n개를 가져온다. LIMIT m, n(건너뛸 개수, 가져올 개수)으로도 쓴다.

1
2
3

SELECT menu_id, name, price FROM menu
ORDER BY price DESC, menu_id
LIMIT 3 OFFSET 3;          -- LIMIT 3, 3 과 같다
menu_idnameprice
3바닐라라떼5500
5콜드브루 라떼5500
6말차라떼5500

주의할 점: 정렬 기준 값이 같은 행끼리는 순서가 보장되지 않는다. 가격이 같은 메뉴가 여러 개라서, menu_id처럼 겹치지 않는 열을 마지막 정렬 기준으로 넣어야 페이지를 넘길 때 같은 행이 두 번 나오거나 빠지지 않는다.

LIMIT은 MySQL 문법이다. 표준 SQL과 Oracle 12c 이후는 OFFSET 3 ROWS FETCH NEXT 3 ROWS ONLY를 쓴다.

복습 문제

  1. 가격이 5,000원 미만이거나 시즌 메뉴(is_seasonal)인 메뉴의 이름, 가격, 시즌 여부를 조회하시오.
  2. 다음 쿼리의 결과 행 수를 예측하고, 도시가 NULL인 회원이 포함되는지 설명하시오. 포함되게 하려면 어떻게 고쳐야 하는지도 쓰시오.
    1

    SELECT COUNT(*) FROM member WHERE city != '대전';
  3. 2025년에 가입한 회원의 이름과 가입일을 가입일 순으로 조회하시오.
  4. 아래 쿼리가 “라떼”가 들어간 메뉴를 하나도 찾지 못하는 이유를 쓰고 고치시오.
    1

    SELECT name FROM menu WHERE name LIKE '라떼';
  5. 메뉴를 가격이 높은 순(가격이 같으면 menu_id 순)으로 한 페이지에 4개씩 보여 줄 때, 2페이지를 가져오는 쿼리를 쓰시오.
정답과 해설

1. OR로 두 조건을 묶는다. MySQL에서 BOOLEAN은 TINYINT(1)이라 결과가 1/0으로 보인다.

1
2

SELECT name, price, is_seasonal FROM menu
WHERE price < 5000 OR is_seasonal = TRUE;
namepriceis_seasonal
아메리카노45000
딸기 에이드60001
버터쿠키30000
밤 마들렌35001

2. 결과는 5다. 회원 8명 중 대전 2명을 빼면 6명이어야 할 것 같지만, 도시가 NULL인 팥쥐는 NULL != '대전'이 UNKNOWN이 되어 빠진다. 포함하려면 WHERE city != '대전' OR city IS NULL로 쓴다(결과 6).

3. BETWEEN은 양 끝을 포함한다.

1
2
3

SELECT name, joined_on FROM member
WHERE joined_on BETWEEN '2025-01-01' AND '2025-12-31'
ORDER BY joined_on;
namejoined_on
심청2025-01-08
흥부2025-04-30
놀부2025-09-12

4. 와일드카드가 없는 LIKE '라떼'는 = '라떼'와 같아서 이름이 정확히 “라떼”인 행만 찾는다. “라떼”가 들어간 이름을 찾으려면 LIKE '%라떼%'로 쓴다.

5. 1페이지가 1~4번째이므로 2페이지는 4개를 건너뛰고 4개를 가져온다.

1
2
3

SELECT menu_id, name, price FROM menu
ORDER BY price DESC, menu_id
LIMIT 4 OFFSET 4;
menu_idnameprice
5콜드브루 라떼5500
6말차라떼5500
2카페라떼5000
4콜드브루5000
