[DB] 14. 집합 연산

JOIN(15편)이 두 테이블을 옆으로 붙인다면, 집합 연산은 두 SELECT의 결과를 위아래로 합치거나 비교한다. 이 글에서는 UNION·UNION ALL·INTERSECT·EXCEPT의 차이, 집합 연산을 쓸 수 있는 조건, 결과 열 이름과 정렬 규칙을 정리한다.

예제는 00편의 가상 카페 DB cafedb를 쓴다. MySQL 8.4에서 실행한 결과다.

연도별 이벤트 참가자를 담은 두 테이블은 구조가 같다.

107콩쥐쿠폰

홍길동(101)만 두 해 모두 참가했다.

UNION은 3 + 3 = 6행에서 중복된 (101, 홍길동)을 하나 지워 5행, UNION ALL은 6행을 그대로 돌려준다. UNION은 중복을 찾으려고 결과 전체를 비교해야 하므로, 중복이 없다고 확신하거나 중복도 필요한 경우에는 UNION ALL이 더 빠르다.

홍길동은 2025년에 쿠폰, 2026년에 텀블러를 받아서 두 행의 값이 다르다. 집합 연산은 선택한 모든 열의 값이 같아야 같은 행으로 본다.

주의할 점: 어느 쪽에서 온 행인지 알고 싶다면 상수 열을 하나 붙인다. SELECT 2025 AS 연도, member_id, ... UNION ALL SELECT 2026, member_id, ...처럼 쓰면 된다. 이때 UNION을 쓰면 연도 값 때문에 모든 행이 서로 달라져 중복 제거가 일어나지 않는다.

INTERSECT와 EXCEPT

MySQL은 8.0.31부터 INTERSECT와 EXCEPT를 지원한다. 8.4에서는 그대로 쓸 수 있다.

1
2
3
4

SELECT member_id, name FROM event_2025
INTERSECT
SELECT member_id, name FROM event_2026
ORDER BY member_id;
member_idname
101홍길동
1
2
3
4

SELECT member_id, name FROM event_2025
EXCEPT
SELECT member_id, name FROM event_2026
ORDER BY member_id;
member_idname
103이몽룡
104심청

EXCEPT는 순서를 바꾸면 결과가 달라진다. 위 쿼리는 “2025년에만 참가한 회원”이고, 두 SELECT를 바꾸면 “2026년에만 참가한 회원”이 된다. UNION과 INTERSECT는 순서를 바꿔도 결과 집합이 같다.

Oracle은 차집합에 MINUS를 쓴다(21c부터는 EXCEPT도 쓴다). 시험에서 MINUS가 보이면 EXCEPT와 같은 뜻으로 읽는다.

8.0.31 이전 방식: IN과 NOT EXISTS

옛 버전이나 다른 DBMS와 호환해야 할 때는 서브쿼리(16편)로 같은 결과를 만든다.

1
2
3
4

-- 교집합: 2026년 참가자 명단에 있는 2025년 참가자
SELECT member_id, name FROM event_2025
WHERE member_id IN (SELECT member_id FROM event_2026)
ORDER BY member_id;
member_idname
101홍길동
1

4

-- 차집합: 2026년 참가자 명단에 없는 2025년 참가자
SELECT member_id, name FROM event_2025 e
WHERE NOT EXISTS (SELECT 1 FROM event_2026 x WHERE x.member_id = e.member_id)
ORDER BY member_id;
member_idname
103이몽룡
104심청

두 방식이 늘 같은 결과를 내지는 않는다. 집합 연산은 NULL끼리를 같은 값으로 보고 중복을 제거하지만, =·IN 비교는 NULL을 만나면 UNKNOWN이 된다. 2025년 이후 가입한 회원의 도시 중 2024년 가입자의 도시에 없는 것을 두 방식으로 구해 보자.

1
2
3
4

SELECT city FROM member WHERE joined_on >= '2025-01-01'
EXCEPT
SELECT city FROM member WHERE joined_on < '2025-01-01'
ORDER BY city;
city
NULL
대전
1
2
3
4

SELECT DISTINCT city FROM member
WHERE joined_on >= '2025-01-01'
  AND city NOT IN (SELECT city FROM member WHERE joined_on < '2025-01-01')
ORDER BY city;
city
대전

EXCEPT는 도시가 NULL인 팥쥐의 행을 하나의 값으로 남겼고, NOT IN은 NULL NOT IN (...)이 UNKNOWN이라 뺐다. NOT IN과 NULL의 함정은 16편에서 더 다룬다.

주의할 점: UNION·INTERSECT·EXCEPT는 모두 결과에서 중복을 없앤다(DISTINCT가 기본). EXCEPT로 구한 도시도 대전이 두 명(심청, 콩쥐)인데 한 번만 나왔다. 중복을 살리려면 ALL을 붙인다. MySQL은 INTERSECT ALL, EXCEPT ALL도 지원한다.

집합 연산을 쓸 수 있는 조건

두 SELECT 결과를 합치려면 합병 가능(union-compatible)해야 한다.

  1. 열의 개수가 같다.
  2. 같은 위치에 있는 열끼리 데이터 타입이 호환된다.

열 개수가 다르면 오류가 난다.

1
2
3
4

SELECT member_id, name FROM event_2025
UNION
SELECT member_id FROM event_2026;
-- ERROR 1222 (21000): The used SELECT statements have a different number of columns

열은 이름이 아니라 위치로 짝지어진다. 순서를 바꿔 쓰면 MySQL은 타입을 알아서 바꿔 오류 없이 합쳐 버린다.

1
2
3

SELECT member_id, name FROM event_2025
UNION
SELECT name, member_id FROM event_2026;

103이몽룡

흥부105

member_id 열에 이름이 들어간 엉뚱한 결과다. MySQL은 숫자와 문자를 섞어도 문자열로 바꿔 합치지만, Oracle은 같은 위치의 타입 그룹이 다르면 오류(ORA-01790)를 낸다. 어느 쪽이든 열 순서는 직접 맞춰야 한다.

ORDER BY는 맨 끝에 한 번

ORDER BY는 집합 연산이 끝난 전체 결과를 정렬한다. 중간에 쓰면 문법 오류다.

1
2
3
4

SELECT member_id, name FROM event_2025 ORDER BY member_id
UNION
SELECT member_id, name FROM event_2026;
-- ERROR 1064 (42000): You have an error in your SQL syntax; check the manual ...

각 SELECT에서 따로 정렬하고 잘라야 한다면 괄호로 감싼다. 예를 들어 해마다 회원 번호가 가장 큰 참가자 한 명씩을 뽑으려면 이렇게 쓴다.

1
2
3
4

(SELECT member_id, name FROM event_2025 ORDER BY member_id DESC LIMIT 1)
UNION ALL
(SELECT member_id, name FROM event_2026 ORDER BY member_id DESC LIMIT 1)
ORDER BY member_id;

104심청
107콩쥐

괄호 안의 ORDER BY는 LIMIT과 함께 쓸 때만 의미가 있다. LIMIT 없이 괄호 안에서만 정렬하면 전체 결과의 순서는 보장되지 않는다.

복습 문제

  1. 다음 네 쿼리의 결과 행 수를 각각 예측하시오.
    1
2
3
4

    SELECT member_id FROM event_2025 UNION ALL SELECT member_id FROM event_2026;  -- (가)
SELECT member_id FROM event_2025 UNION     SELECT member_id FROM event_2026;  -- (나)
SELECT name, prize FROM event_2025 UNION   SELECT name, prize FROM event_2026; -- (다)
SELECT prize FROM event_2025 UNION         SELECT prize FROM event_2026;       -- (라)
  2. 2026년 이벤트에만 참가한 회원의 번호와 이름을 EXCEPT로 조회하시오. (선택, 16편을 본 뒤) EXCEPT를 쓸 수 없는 환경을 위해 같은 결과를 NOT EXISTS로도 쓰시오.
  3. 서울에 사는 회원과 본점 직원의 이름을 한 목록으로 조회하시오. 구분 열에 ‘회원’ 또는 ‘직원’을 표시하고, 구분 → 이름 순으로 정렬하시오.
  4. 다음 설명 중 틀린 것을 모두 고르시오.
    • ① UNION하는 두 SELECT는 열 이름이 같아야 한다.
    • ② 결과의 열 이름은 첫 번째 SELECT를 따른다.
    • ③ EXCEPT는 두 SELECT의 순서를 바꿔도 결과가 같다.
    • ④ INTERSECT는 기본적으로 중복 행을 제거한다.
    • ⑤ ORDER BY는 마지막 SELECT 뒤에 한 번만 쓴다.
정답과 해설

1. (가) 6, (나) 5, (다) 6, (라) 2.

  • (가) UNION ALL은 중복을 그대로 두므로 3 + 3 = 6이다.
  • (나) 101이 양쪽에 있어 하나가 지워진다.
  • (다) 홍길동의 상품이 해마다 달라(쿠폰, 텀블러) (홍길동, 쿠폰)과 (홍길동, 텀블러)가 서로 다른 행이다. 중복이 없어 6행이다.
  • (라) 상품 값만 보면 쿠폰과 텀블러 두 종류뿐이다. 선택한 열이 적을수록 중복이 늘어난다.
