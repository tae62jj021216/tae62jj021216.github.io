Claude Code 개발 환경 회고

2026년 9월 19일 첫 hook을 단 뒤 2주 동안 고치고 넓힌 것을 돌아본다. 가장 크게 남은 것은 규칙을 어디에 두느냐에 대한 기준이다.

언제 필요한가어디에 둔다
매 턴지침 파일(CLAUDE.md). 짧게
특정 폴더의 파일을 다룰 때경로 범위가 붙은 규칙 파일. 그 폴더를 건드릴 때만 자동으로 붙는다
사용자가 부를 때스킬
반드시 지켜야 할 때hook

잘한 점

꼭 지킬 규칙을 hook으로 옮겼다

위키 지침에는 처음부터 “원본 자료는 수정하지 않는다”가 있었다. 그런데도 에이전트가 만든 PDF가 원본 폴더 안에서 두 번 수정됐다. 나중에 점검을 돌리고서야 알았다.

지침은 모델이 “따르길 기대하는” 글이다. 지침이 길어지거나 다른 일에 몰두하면 빠진다. 그래서 되돌리기 어려운 규칙 세 가지를 도구 실행 직전에 검사하는 hook으로 옮겼다.

규칙판정
원본 폴더의 기존 파일 수정·이동·삭제 금지파일 도구는 거부, 셸 명령은 확인
작업 기록 파일은 끝에 덧붙이기만파일 도구는 거부, 셸 명령은 확인
보관만 하는 옛 볼트에 쓰기 금지파일 도구는 거부, 셸 명령은 확인

파일 도구는 경로를 정확히 알 수 있어 바로 거부하고, 셸 명령은 문자열로 짐작하므로 틀릴 수 있어 확인을 받는다. 이 hook을 단 뒤에는 작업 기록 첫 줄을 고치려는 시도가 실행 전에 거부됐다. 판단이 모델이 아니라 스크립트에 있으니 매번 같게 동작한다.

지침을 짧게 줄였다

위키 지침 파일은 239줄까지 늘어 있었다. 매 턴 전부 읽히는 파일이라 길수록 규칙 하나하나가 덜 지켜지고 비용도 든다. 위 표의 기준으로 나눠 90줄로 줄였다.

  • 문서 형식, 파일 이름 규칙 → 경로 범위가 붙은 규칙 파일
  • 자료 정리, 초안 작성, 점검 절차 → 스킬
  • 반드시 지킬 것 → hook

나눈 뒤에는 옛 지침의 줄마다 새 파일들과 대조해 빠진 규칙이 없는지 확인했다. 다른 작업 폴더 두 곳의 지침도 같은 방식으로 나눴다.

짐작하지 않고 새 세션으로 확인했다

  • /clear가 데스크톱 앱에서 startup으로 온다는 것은 이벤트를 직접 기록해서 알았다(#1).
  • 경로별 규칙 파일이 실제로 자동으로 붙는지는, 새 세션에서 “파일을 읽지 말고 답하라”며 그 규칙 파일에만 있는 사실을 물어 확인했다.
  • 저장 필터는 새 세션에 “오늘 점심이 맛있었다, 저장해줘”라고 해 보고, 다섯 필터를 모두 ✗로 판정하고 아무것도 쓰지 않는 것을 확인했다.

아쉬운 점

사고가 난 뒤에야 고쳤다

세 가지 모두 일이 생긴 뒤에 고쳤다.

무엇고친 것
지침이 있는데도 원본 PDF가 두 번 수정됨보호 hook
자동 커밋 hook이 다른 세션이 옮긴 스킬을 삭제로 push함 (#2)고친 파일만 커밋, 전부 담기 확인 hook
입력 인코딩 때문에 동기화 hook이 일부 수정을 조용히 놓침 (#1)stdin 인코딩 지정

세 번째는 실패해도 세션을 막지 않게 만든 설계(오류를 삼키고 통과)의 뒷면이다. 막지 않는 대신 조용히 실패했고, 내용에 따라 될 때도 있어 늦게 알았다.

hook은 도구 호출만 본다

명령 검사 hook은 Claude가 도구로 실행하는 명령만 본다. 스크립트 안의 git이나 파일 쓰기는 보지 못한다. #2의 사고가 바로 그 틈에서 났다. hook만으로는 다 막을 수 없어서, 사후에 위키를 점검하는 스킬(깨진 링크, 원본 보호, 근거 없는 결정 확인)을 함께 둔다.

확인하지 못한 것이 남았다

  • 데스크톱 앱에서 대화 창 크기(200K인지 1M인지)를 실측하지 못했다. 상태 표시줄 스크립트가 실행되지 않기 때문이다(#1).
  • 전부 담기 확인 hook은 기록상 파이프 시험으로만 판정을 확인했고, 실제 확인 창이 뜨는 것은 따로 기록하지 않았다.

다음에 할 것

  • 창 크기 확정: 한 대화를 200K 넘게 써서 자동 압축이 일어나는지 본다. 일어나면 200K, 아니면 1M이다. 확정되면 대시보드 기본값만 바꾸면 된다.
  • hook의 실제 동작 확인: 새 hook을 만들면 파이프 시험 뒤에 실제 세션에서 한 번 일부러 걸리게 해 보고 결과를 기록한다.
  • 자동화 스크립트의 git: hook 말고도 스크립트 안에서 커밋하는 곳이 있으면, “고친 파일만 담는다”를 같은 방식으로 적용한다.
  • 강제와 점검을 함께: 새 규칙을 넣을 때마다 위 표의 기준으로 자리를 정하고, hook이 볼 수 없는 부분은 점검 항목에 넣는다.
