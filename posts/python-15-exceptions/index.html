[Python] 15. 예외 처리, try/except로 프로그램이 죽지 않게 만들기 (완결)

드디어 파이썬 기초 시리즈의 마지막 편이다. 지금까지 만든 프로그램들은 사용자가 이상한 값을 입력하면 바로 죽어버렸는데, 오늘 배운 예외 처리로 그걸 막는 방법을 정리한다.

오류(Error)의 종류

문법 오류(Syntax Error)는 : 빼먹기, 들여쓰기 오류 등으로 코드를 실행하기도 전에 걸러진다(VSCode에서 빨간 줄로 표시). 실행 중 오류는 코드는 문법상 맞지만 실행하다가 터지는 오류로, 오늘의 주인공이다. 논리적 오류는 문법도 실행도 문제없지만 결과가 의도와 다른 경우인데, 제일 찾기 어려운 유형이라고 한다.

지금까지 리스트, 딕셔너리, 파일 입출력, 모듈을 배우면서 이미 한 번씩은 다 겪어본 에러들이라, 이렇게 이름 붙여서 정리하니 아 그게 이 에러였구나 싶은 게 많았다. 파이썬의 예외는 클래스 상속으로 계층적으로 구성되어 있는데, 위에 나온 에러들을 포함해 대부분은 Exception 클래스를 상속받고, 맨 꼭대기에는 BaseException이 있다는 것도 알게 됐다. (sys.exit()가 내는 SystemExit나 Ctrl+C를 누를 때 나는 KeyboardInterrupt는 Exception이 아니라 BaseException을 바로 상속한다.) 지난 글에서 배운 클래스 상속 개념이 파이썬 내부 구조에도 그대로 쓰이고 있었다.

a = int(input('숫자1: '))
b = int(input('숫자2: '))

try:
    result = a / b
except:
    print('오류발생')
else:
    print(f'{a}/{b}={result}')

b에 0을 입력하면 except가 실행되어 프로그램이 죽지 않고 “오류발생”만 출력하고 넘어간다는 걸 확인했다. 예외 처리의 핵심은 오류가 나도 프로그램을 계속 살려두는 것이라는 걸 체감했다.

try:

except ValueError as e:      # 에러종류 as 변수명 : 에러 메시지도 받을 수 있음

# Exception으로 받으면 (위에서 본 대부분의) 에러를 한 번에 받을 수 있음
try:
    result = a / b
except Exception as e:
    print('오류발생', e)

여러 종류의 예외를 각각 다르게 처리하고 싶으면 except를 여러 번 나열하면 된다.

try:
    print(10 / 0)
    print([1,2,3][10])
except ZeroDivisionError as e:
    print('0으로 나눌 수 없습니다', e)
except IndexError as e:
    print('인덱스 범위를 벗어났습니다', e)

여기서 중요한 함정 하나를 발견했다. try 블록 안에 예외 발생 가능 문장이 여러 개 있어도, 첫 번째 예외가 발생하는 순간 그 지점에서 바로 처리하고 try 블록을 빠져나간다. 위 코드에서는 10/0에서 바로 ZeroDivisionError가 잡히고, 그 아래 [1,2,3][10]은 아예 실행되지 않는다.

try:
    f = open('data.txt', 'r', encoding='utf-8')
except:
    pass   # 오류 발생시 아무것도 안 하고 넘어가기
else:
    data = f.read(100)
    print(data)
    f.close()
finally:
    print('종료')   # 성공하든 실패하든 무조건 실행됨

else는 예외가 안 났을 때만 실행되고, finally는 예외가 나든 안 나든 무조건 실행된다는 차이가 명확했다. 파일을 닫거나 자원을 정리하는 마무리 코드는 finally에 넣으면 예외 발생 여부와 상관없이 항상 보장된다는 게 실용적이었다. (물론 파일 입출력은 지난 글에서 배운 with문을 쓰면 이런 걱정 자체가 줄어든다.)

반복문 안에서의 예외 처리 흐름, 헷갈렸던 부분

1
2
3
4
5
6

prices = ['1200', '무료', '800']
for p in prices:
    try:
        print(int(p) * 2)
    except ValueError:
        print(f"'{p}'는 숫자가 아니라서 건너뜁니다")

'무료'일 때만 except로 빠지고, 앞뒤의 '1200', '800'은 정상적으로 try 블록이 실행된다(2400, 1600 출력). try-except는 반복문 자체를 멈추는 게 아니라, 그 반복 한 번(iteration)에서 발생한 예외만 처리하고 다음 반복으로 넘어간다는 걸 헷갈리지 않게 정리해뒀다. 처음엔 예외가 나면 반복문 전체가 끝나는 줄 알았다.

정리하자면, try 블록 안에서 예외가 발생한 그 줄 이후의 코드는 실행되지 않고 바로 except로 넘어가고, else는 예외가 없을 때만, finally는 항상 실행된다. 반복문 안의 try-except는 그 반복 한 번만 처리하고 계속 진행하며(전체 반복문이 멈추는 게 아님), 에러 종류를 최대한 구체적으로 명시해서 처리하는 게 except:로 뭉뚱그리는 것보다 디버깅에 훨씬 유리하다.
