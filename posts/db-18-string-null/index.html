이름과 전화번호를 이어 붙이거나 빈 값을 다른 값으로 바꿔 보여 줄 때가 많다. 이 글에서는 MySQL의 주요 문자열 함수와 형 변환, NULL이 연산·비교·논리식에서 어떻게 동작하는지와 NULL을 다루는 함수, 그리고 조건에 따라 값을 고르는 CASE를 정리한다.

예제는 00편의 cafedb를 쓴다. MySQL 8.4(문자 집합 utf8mb4)에서 실행한 결과다.

문자열 합치기: CONCAT과 CONCAT_WS

CONCAT(a, b, ...)은 인자를 순서대로 이어 붙인다. CONCAT_WS(구분자, a, b, ...)는 사이사이에 구분자를 넣는다(WS = With Separator). 둘의 큰 차이는 NULL을 만났을 때다.

SELECT name, phone,
       CONCAT(name, ' (', phone, ')')        AS by_concat,
       CONCAT_WS(' / ', name, city, phone)   AS by_ws
FROM member
WHERE member_id IN (101, 102, 108)
ORDER BY member_id;

  • CONCAT은 인자 중 하나라도 NULL이면 결과 전체가 NULL이다.
  • CONCAT_WS는 NULL 인자를 건너뛴다(구분자도 붙이지 않는다).

숫자를 넘기면 문자열로 바뀌어 붙는다. CONCAT('가격: ', price, '원')은 가격: 4500원이 된다.

Oracle은 'a' || 'b'로 문자열을 잇고 CONCAT은 인자를 두 개만 받는다. MySQL에서 ||는 기본적으로 OR라 'ab' || 'cd'가 0이다. ||를 OR로 쓰는 방식은 폐지 예정이라 경고도 함께 나온다.

길이: LENGTH와 CHAR_LENGTH

LENGTH는 바이트 수, CHAR_LENGTH는 글자 수를 돌려준다. 영문은 1바이트라 둘이 같지만, utf8mb4에서 한글은 한 글자가 3바이트다.

1
2
3
4

SELECT name, LENGTH(name) AS bytes, CHAR_LENGTH(name) AS chars
FROM menu
WHERE menu_id IN (1, 5, 10)
ORDER BY menu_id;
namebyteschars
아메리카노155
콜드브루 라떼197
버터쿠키124

“콜드브루 라떼”는 한글 6글자(18바이트)와 공백 1글자(1바이트)라 19바이트다.

주의할 점: 글자 수 조건에는 CHAR_LENGTH를 쓴다(복습 문제 2). VARCHAR(10)의 10도 바이트가 아니라 글자 수다. Oracle은 LENGTH가 글자 수, LENGTHB가 바이트 수다.

대소문자와 공백: UPPER, LOWER, TRIM

UPPER('Cold Brew')는 COLD BREW, LOWER('Cold Brew')는 cold brew다. TRIM은 양쪽, LTRIM은 왼쪽, RTRIM은 오른쪽 공백을 지운다(CHAR_LENGTH(LTRIM(' 라떼 '))는 오른쪽 공백 2개가 남아 4). TRIM은 BOTH·LEADING·TRAILING과 FROM을 써서 공백이 아닌 문자도 지운다. TRIM(BOTH '*' FROM '**VIP**')는 VIP, TRIM(LEADING '0' FROM '000123')은 123이다.

바꾸기와 찾기: REPLACE, INSTR, LOCATE

REPLACE(s, 찾을 문자열, 바꿀 문자열)은 모든 일치 부분을 바꾼다. REPLACE(name, ' ', '')는 콜드브루 라떼를 콜드브루라떼로 만든다.

INSTR과 LOCATE는 부분 문자열이 처음 나오는 위치를 돌려주고, 없으면 0이다. 인자 순서가 반대인 점에 주의한다.

       LOCATE('라떼', name) AS locate_pos    -- LOCATE(찾을 것, 문자열)

LOCATE는 세 번째 인자로 검색 시작 위치를 받는다. LOCATE('-', '010-5555-6666', 5)는 두 번째 하이픈 위치 9다.

채우기와 뒤집기: LPAD, RPAD, REVERSE

LPAD(s, 길이, 채울 문자)·RPAD는 왼쪽·오른쪽을 채워 길이를 맞춘다. CONCAT('M', LPAD(menu_id, 3, '0'))은 메뉴 1번을 M001로 만든다. 원래 문자열이 더 길면 잘린다(LPAD('12345', 3, '0')은 123). REVERSE('카페라떼')는 떼라페카다.

형 변환: CAST와 CONVERT

CAST(값 AS 타입), CONVERT(값, 타입)으로 타입을 바꾼다. 타입 자리에는 CHAR, SIGNED, UNSIGNED, DECIMAL(p,s), DATE, DATETIME 등을 쓴다.

1
2
3
4

SELECT CAST('2026-08-01' AS DATE)  AS d,
       CAST('0123' AS UNSIGNED)    AS n,
       CAST(10 AS DECIMAL(5,2))    AS dec5,
       CONVERT('77', SIGNED)       AS c;
dndec5c
2026-08-0112310.0077

MySQL은 명시하지 않아도 필요할 때 자동으로 형을 바꾼다(묵시적 형 변환).

SELECT '10' + 5 AS a, '3잔' + 1 AS b, '10' = 10 AS c;

NULL은 어떻게 계산되는가

NULL은 0도 빈 문자열도 아닌 “값이 없음(모름)”이라, 다른 값과 섞이면 결과도 대부분 모름이 된다.

산술과 비교

SELECT 4500 + NULL   AS plus,
       NULL * 0      AS times_zero,
       NULL = NULL   AS eq,
       NULL <> 1     AS ne,
       NULL IS NULL  AS is_null,
       NULL <=> NULL AS null_safe;
plustimes_zeroeqneis_nullnull_safe
NULLNULLNULLNULL11
  • 산술 연산에 NULL이 끼면 결과는 NULL이다. NULL * 0도 0이 아니다.
  • NULL = NULL조차 NULL(UNKNOWN)이다. NULL 확인은 IS NULL / IS NOT NULL로 한다.
  • <=>는 MySQL 전용 “NULL 안전 비교”로, 양쪽이 모두 NULL이면 참(1)을 돌려준다.

3값 논리

NULL이 들어간 비교의 결과는 TRUE, FALSE에 더해 UNKNOWN이 된다. AND·OR는 다음 표대로 계산되고, NOT UNKNOWN은 UNKNOWN이다.

ABA AND BA OR B
TRUEUNKNOWNUNKNOWNTRUE
FALSEUNKNOWNFALSEUNKNOWN
UNKNOWNUNKNOWNUNKNOWNUNKNOWN

FALSE AND ?는 항상 거짓, TRUE OR ?는 항상 참이고, 나머지는 UNKNOWN이다. MySQL은 UNKNOWN을 NULL로 표시한다(SELECT TRUE AND NULL, FALSE AND NULL은 NULL, 0).

WHERE는 조건이 TRUE인 행만 남기고 FALSE와 UNKNOWN은 모두 버린다. NOT으로 조건을 뒤집어도 UNKNOWN은 그대로라 NULL인 행은 여전히 빠진다. 16편의 NOT IN 함정도 같은 원리다.

NULLIF: 0으로 나누기 막기

NULLIF(a, b)는 특정 값을 NULL로 바꾼다(NULLIF(5000, 5000)은 NULL). 가장 흔한 쓰임은 분모가 0이 되는 것을 막는 것이다.

지점별로 “회원 주문 수 ÷ 비회원 주문 수”를 구해 보자. 본점은 비회원 주문이 0건이다.

1
2
3
4
5
6
7

SELECT store,
       SUM(member_id IS NOT NULL) AS member_orders,
       SUM(member_id IS NULL)     AS guest_orders,
       SUM(member_id IS NOT NULL) / NULLIF(SUM(member_id IS NULL), 0) AS ratio
FROM orders
GROUP BY store
ORDER BY store;
storemember_ordersguest_ordersratio
강변점313.0000
공원점212.0000
본점50NULL

MySQL은 조건식을 1/0으로 계산하므로 SUM(조건)이 “조건에 맞는 행 수”가 된다(표준 SQL로는 뒤의 CASE로 쓴다). 분모가 0이면 NULLIF가 NULL로 바꾸고, NULL로 나눈 결과는 NULL이다.

MySQL의 SELECT는 100 / 0도 경고 1365와 함께 NULL로 돌려주지만, Oracle과 SQL Server는 오류를 내므로 NULLIF로 막는 습관이 중요하다.

빈 문자열과 NULL

MySQL에서 빈 문자열 ''은 길이가 0인 문자열이고 NULL이 아니다. '' IS NULL은 0, LENGTH('')는 0, CONCAT('라떼', '')는 라떼다.

Oracle은 ''을 NULL로 취급해 '' IS NULL이 참이다. 같은 식도 DBMS에 따라 결과가 달라진다(복습 문제 4).

CASE: 조건에 따라 값 고르기

CASE는 조건에 따라 다른 값을 돌려주는 표준 SQL 식으로, 값이 들어갈 수 있는 곳이면 어디든 쓴다. 형태는 두 가지다.

단순 CASE

CASE 식 WHEN 값 THEN 결과 ...는 식을 각 값과 =로 비교한다. 회원 등급을 할인율(%)로 바꿔 보자.

SELECT name, grade,
       CASE grade
           WHEN 'VIP'  THEN 10
           WHEN 'GOLD' THEN 5
           ELSE 0

ORDER BY member_id;

검색 CASE

CASE WHEN 조건 THEN 결과 ...는 WHEN마다 조건식을 따로 쓴다. 범위 비교처럼 =로 표현할 수 없는 분류에 쓴다. 메뉴를 가격대로 나눈다.

SELECT name, price,
       CASE
           WHEN price >= 6000 THEN '고가'
           WHEN price >= 5000 THEN '중간'
           ELSE '저가'
       END AS band
FROM menu
WHERE menu_id IN (1, 2, 7, 10)

WHEN은 위에서부터 검사해 처음 참이 된 결과 하나만 돌려준다. 딸기 에이드(6000)는 price >= 5000도 참이지만 첫 WHEN에서 이미 끝났다.

집계 함수 안의 CASE: 조건별로 세기

CASE를 집계 함수 안에 넣으면 한 번의 GROUP BY로 조건별 개수를 나란히 볼 수 있다. 지점별 전체 주문, 비회원 주문, 오전(12시 전) 주문을 센다.

1
2
3
4
5
6
7

SELECT store,
       COUNT(*) AS total,
       SUM(CASE WHEN member_id IS NULL THEN 1 ELSE 0 END) AS guest,
       COUNT(CASE WHEN HOUR(ordered_at) < 12 THEN 1 END)  AS morning
FROM orders
GROUP BY store
ORDER BY store;
storetotalguestmorning
강변점411
공원점312
본점503

SUM 쪽은 맞으면 1, 아니면 0을 더한다. COUNT 쪽은 ELSE가 없어 맞지 않는 행이 NULL이 되고, COUNT(식)은 NULL을 세지 않는다(13편).

MySQL의 IF

IF(조건, 참일 때, 거짓일 때)는 결과가 둘뿐인 검색 CASE를 짧게 쓴 MySQL 전용 함수다. IF(price >= 6000, '고가', '일반')처럼 쓰고, 조건이 UNKNOWN이면 거짓 쪽을 돌려준다.

Oracle의 DECODE(grade, 'VIP', 10, 'GOLD', 5, 0)는 단순 CASE에, NVL2(phone, '있음', '없음')은 CASE WHEN phone IS NOT NULL THEN '있음' ELSE '없음' END(MySQL은 IF(phone IS NOT NULL, '있음', '없음'))에 해당한다. IF는 Oracle에 없다.

정답과 해설

1. 결과는 NULL이다. CONCAT은 인자 하나가 NULL이면 전체가 NULL이 된다. IFNULL로 전화번호를 먼저 바꿔 준다.

SELECT CONCAT('회원: ', name, ', ', IFNULL(phone, '번호 없음')) AS info
FROM member WHERE member_id = 105;
info
회원: 흥부, 번호 없음

2. 글자 수는 CHAR_LENGTH로 센다. 공백도 한 글자다.

1
2
3
4

SELECT name, CHAR_LENGTH(name) AS chars
FROM menu
WHERE CHAR_LENGTH(name) >= 5
ORDER BY menu_id;

아메리카노, 바닐라라떼, 콜드브루 라떼(7), 딸기 에이드(6), 치즈케이크, 초코케이크, 밤 마들렌의 7개가 나온다. LENGTH(name) >= 5로 쓰면 메뉴 11개 전부가 나온다. 한글은 한 글자에 3바이트라 두 글자만 돼도 6바이트로 통과하기 때문이다.

3. 결과는 5다. 성춘향·흥부는 괄호 안이 참이라 NOT으로 거짓이 된다. 팥쥐는 UNKNOWN AND TRUE = UNKNOWN, NOT UNKNOWN = UNKNOWN이라 역시 빠진다. 나머지 5명만 참이다.

4. 결과는 순서대로 아메리, 5, 007, ''(빈 문자열)이다.

  • 공백도 한 글자이므로 5번째 글자는 두 번째 단어의 아다.
  • LOCATE는 2번째 글자부터 찾으므로 첫 글자 아를 건너뛴다.
  • MySQL에서 ''은 NULL이 아니므로 COALESCE가 ''에서 멈춘다. Oracle은 ''을 NULL로 보므로 '기본값'이 나온다.

5. city2는 미입력이 아니라 NULL이다. 단순 CASE는 city = NULL로 비교하는데, 이 비교는 UNKNOWN이라 WHEN이 절대 맞지 않고 ELSE city(NULL)로 간다. IS NULL을 쓰는 검색 CASE로 고친다.

1
2

SELECT name, CASE WHEN city IS NULL THEN '미입력' ELSE city END AS city2
FROM member WHERE member_id = 108;
