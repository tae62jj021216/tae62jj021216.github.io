DataFrame에서 원하는 칸을 고르는 방법은 셋이다. 대괄호 [], 라벨(이름)로 고르는 loc, 위치(순서)로 고르는 iloc이다. 여기에 True/False가 담긴 Series를 넣으면 SQL의 WHERE처럼 조건에 맞는 행만 남는다.

예제 데이터는 00편의 cafe 폴더를 쓴다. Python 3.12, pandas 3.0.6에서 실행한 결과다.

[] 안에 열 이름을 넣으면 열을 고르고, 슬라이스(:)를 넣으면 행을 고른다. 같은 괄호인데 넣는 것에 따라 방향이 바뀐다. 그래서 행 라벨 하나를 []에 넣으면 열 이름으로 찾다가 실패한다.

쓰는 법고르는 것
df["열"]열 하나 (Series)
df[["열1", "열2"]]여러 열 (DataFrame)
df[1:3]위치 1~2인 행
df[불리언 Series]True인 행

행을 고를 때는 아래의 loc·iloc을 쓰면 행과 열을 헷갈리지 않는다.

loc: 라벨로 고르기

df.loc[행, 열] 형식이다. 쉼표 앞이 행, 뒤가 열이고, 열을 생략하면 모든 열이다.

print(m.loc["카페라떼", "price"])              # 칸 하나 → 값
print(m.loc[["아메리카노", "말차라떼"], ["price", "is_seasonal"]])

행 하나만 고르면 그 행이 Series로 나온다. 열 이름이 인덱스가 되고, 정수와 bool이 섞여 자료형은 object다. 행과 열을 모두 하나씩 고르면 값 하나다.

빈칸 조건: isna, notna

1
2

print(member.loc[member["phone"].isna(), "name"].tolist())
print(member.loc[member["city"] != "서울", "name"].tolist())

1
2

['성춘향', '흥부', '팥쥐']
['이몽룡', '심청', '놀부', '콩쥐', '팥쥐']

phone이 빈칸(NaN)인 회원은 isna()로 고른다. 둘째 줄은 SQL과 결과가 다르다. SQL의 city != '서울'은 NULL인 행을 빼지만(DB 시리즈 12편), pandas에서 NaN != "서울"은 True라서 도시가 빈칸인 팥쥐가 들어 있다.

주의할 점: NaN은 어떤 값과도 같지 않다. member["phone"] == float("nan")은 모든 행이 False라서 빈칸을 하나도 찾지 못한다. 빈칸은 항상 isna()·notna()로 찾는다.

체인 할당은 원본을 바꾸지 못한다

[]를 두 번 이어 쓰는 체인 할당은 원본을 바꾸지 못한다.

1
2

menu[menu["name"] == "버터쿠키"]["price"] = 2800
print(menu.loc[menu["name"] == "버터쿠키", "price"].tolist())

1
2

ChainedAssignmentError: A value is being set on a copy of a DataFrame or Series through chained assignment.
[3000]

menu[조건]이 먼저 실행되어 새 DataFrame이 만들어지고, ["price"] = 2800은 그 새 DataFrame에 대입된다. pandas 3.0은 이것을 감지해 ChainedAssignmentError 경고를 내고, 원본 가격은 3000 그대로다. 메시지가 권하는 대로 loc 한 번으로 쓴다.

1
2

menu.loc[menu["name"] == "버터쿠키", "price"] = 2800
print(menu.loc[menu["name"] == "버터쿠키", "price"].tolist())

1

[2800]

필터 결과를 변수에 담아 고쳐도 원본은 그대로다.

1
2
3

cake = menu[menu["category_id"] == 7]
cake["price"] = 7000
print(cake["price"].tolist(), menu.loc[menu["category_id"] == 7, "price"].tolist())

1

[7000, 7000] [6500, 6500]

pandas 3.0은 Copy-on-Write가 기본이라, 다른 DataFrame에서 꺼낸 결과는 항상 복사본처럼 동작한다. 결과를 고치면 결과만 바뀌고 경고도 없다.

pandas 2.x에서는 위 코드에 SettingWithCopyWarning이 났고, 그래서 cake = menu[...].copy()처럼 .copy()를 붙이는 코드가 많다. pandas 3.0에서는 이 경고가 없어졌고 .copy()를 붙여도 결과는 같다. 원본을 고치려면 버전과 상관없이 원본에 loc으로 대입한다.
